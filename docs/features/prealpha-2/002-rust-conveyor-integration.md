## 目标与范围

用独立的 RustConveyor 包承担传送带运输，复用既有 `LogisticsData` 门面、
三维设施建造、区块候选查询、物品表现和会话存档。
Rust 包不得依赖本游戏设施类或场景节点；GDExtension 以批量接口接入。
在两个仓库独立功能分支实施，保留原有未提交改动；不修改两个 vendored 插件。

首轮采用统一速度、固定 tick、单线程运输实例及明确的有限端口能力。
新后端采用连续运输；旧后端保持为对照。后端选择须显式配置并写入存档；
旧存档不因加载而静默采用新规则。未支持的组合返回可诊断错误。

### Rust 矿石三维显示与读取优化

状态：**当前规则，2026-11-23 已实现；针对性验证、独立实现复审、
完整回归和百万图形性能复测通过**。最终实时编辑器复验不可用，
验证方式与限制见当次记录。
读者为接入开发者、测试与审查人员；最终证据见
[本切片验收记录](../../reviews/2026-11-23-rust-ore-display.md)。
本切片同时完成 Rust 三维位置输出和显示数据整理／读取优化，
继承上述表面标记、候选距离、矿石高度、矿石身份与固定 tick 显示规则。

Rust 的 Godot 桥接接收游戏提供的纯几何数据：格子对应的线路编号、区间起点、
长度、表面中心、进出方向、入口方向、平面跨度与升降高度。
该数据是可重建的显示缓存，不进入运输核心或原生快照；不得引用游戏类、
节点、相机或修改运输状态。放置、拆除、旋转、同世界恢复、运输重建、
原生实例替换和等待连边接通后，下一次显示读取采用更新后的几何。
初始矿石的未知入口保留宿主已有来源方向，已知入口采用当前实际端口方向。

新增 `set_display_geometry(data)` 和
`sample_display_cells(indices, limit, offset)` 桥接接口：
前者原子校验并绑定成批几何及未知入口的矿石方向；
后者返回成批矿石编号、三维位置、查询行索引、行边界及完整匹配数量。
位置按现有 `LogisticsOre.surface_position` 的四向平带、转弯与八种坡道计算，
显示偏移由调用方显式传入。非法参数或失效几何返回错误，不悄悄返回旧画面。
显示缓存失效只影响显示读取，不停止正确的运输实例。

Rust 查询只合并同线路且精确相邻的已请求区间，不扩大至未请求区间；
保持各行的原有边界归属、下游到上游顺序、返回上限和调用方行顺序。
重复／重叠请求不得丢失结果；间隙不得被当作可见范围。
每行返回上限不能被错误地当作整段合并查询的总上限。
新接口读取和三维换算不得推进时钟、改变矿石身份或生产／消费账目。
旧 `sample_ranges` 和宿主 `sample_cells` 继续用于规则、编辑与存档等调用。

Godot 的 Rust 显示路径直接读取成批位置，不建立 `LogisticsOreQueue`／
`LogisticsOre` 临时实例，也不重复计算矿石的三维位置。
矿机／箱子库存矿石、稳定身份渲染池、高度筛选和默认 GDScript 后端保留原职责。
正常显示帧不重新上传整个世界的几何；几何绑定耗时计入实际挂载／首次准备，
不得隐藏到测量窗口外而不报告。

验收与复现顺序：

1. Rust 桥接纯几何／批量查询的失败测试与最小实现：
   验证四向、转弯、全部坡道、未知／已知入口、端点、空请求、非法几何、
   相邻／不连续区间、每行上限和只读性；先确认 RED，再 GREEN。
2. Godot 接入失败测试与最小实现：
   比较旧采样后的实际三维位置与新成批输出，核对身份、行顺序、高度筛选、
   编辑／恢复／重绑及等待连边；旧后端和存读档继续回归。
3. 独立审查、Rust 检查、原生 release 安装和 Godot 完整验证：
   命令沿用 [开发说明](../../development.md#本地检查)与
   [原生安装入口](../../development.md#可选-rust-运输后端)。
   Rust 桥接测试用 `cargo test -p rust_conveyor_godot`；
   格式／静态检查用 `cargo fmt --all -- --check`、
   `cargo clippy -p rust_conveyor_godot --all-targets -- -D warnings`。
4. 完整验证通过后只测百万图形场景：
   `bash scripts/run_native_pressure.sh NEW_OUTPUT rust window million`，
   沿用 120 tick 预热、300 tick 测量及原存盘／解码／挂载流程。
   以 [表面标记有效窗口](../../reviews/2026-11-23-logistics-surface-material.md#有效窗口与负载)
   为基线，不用更少的候选、矿石或成交量证明改善。

单独记录实际请求格数、返回矿石数、合并后的 Rust 查询次数、原生三维换算、
宿主读取／绘制提交、场景更新 CPU、帧间隔、挂载与全进程峰值 RSS。
新增三维换算位于 Rust 调用内部时说明阶段迁移，不将不同阶段名直接当作加速。
保留同一固定窗口的原始时间、工作量、来源指纹与真实截图；
最终实时编辑器不可用时按本文性能口径披露独立图形进程的验证范围。

### 候选复用、批量上传与顺序读取

状态：**当前规则，2026-11-23 已实现；完整回归、真实 GPU、百万固定／移动
窗口与直接候选筛选重放通过**。继承上述全部显示与运输规则，
不改变显示距离、高度、固定 tick、矿石身份或区间归属。

候选缓存以相机位置为锚点，保留覆盖小幅平移的扩展球。锚点内侧保守区域
保证在允许位移内仍满足显示距离，边缘区域每次平移重新精确检查；
超过位移预算则重新查询候选。原地转动不改变距离／高度筛选，复用整个候选集。
等于距离的设施保留；非法位置／距离、相机切换、设施编辑、重置、重绑与恢复
不得沿用失效选择。静态设施类型、最低矿石高度和库存表现节点可复用，
矿石位置、设备库存和最终矿石高度仍读取当前帧。缓存只保存局部设施。

矿石池每批每帧只计算一次世界到批次坐标变换，并按 Godot 3D MultiMesh
规定的 12 浮点布局上传完整缓冲区。保留容量增长／缩小／退休／复用、
稳定身份查询、共享资源分批、负坐标区块和变换父节点的正确世界位置。
未使用容量不扩大自定义 AABB；一般带旋转／缩放的实例也须正确上传。

Rust 有限范围采样改为只访问相交队列子树与叶块的顺序读取。
保留补偿距离、懒压缩及原有前缀求和顺序；精确区间边界继续决定归属，
不得用舍入后的三维位置重新分配行。每行完整数量、独立上限、重复、
重叠与间隙行为不变；不导出全段，也不推进运输。
树节点／叶块访问减少，但保持位级前缀结果的祖先补偿合并仍需
`O(K log B)` 算术工作（`K` 为返回矿石数，`B` 为队列叶块数），
不承诺严格线性 CPU。实测结果及限制见
[本轮审查](../../reviews/2026-11-23-logistics-display-reuse.md)。

实施顺序与验收：

1. 候选缓存：先写静止／原地转动／连续小幅平移及边界进入退出的失败测试，
   与直接距离筛选逐帧比较，并验证编辑、高度改变及生命周期；再实现。
   用实际候选检查数和静态元数据准备数证明复用，不能只断言画面相同。
2. 批量上传：先写多批、容量缩小、非单位 Basis、父节点变化和实际
   `MultiMesh.get_instance_transform` 的失败测试；实现后保留身份与 AABB 验收。
   安装原生扩展时，将矩阵打包与 AABB 合并交给无运输状态的显示辅助接口；
   未安装或旧扩展缺少该接口时沿用逐实例提交。原生 AABB 留坐标尺度相关的
   浮点舍入余量，确保与引擎转换后的实际网格边界相容。
3. 顺序读取：先写大队列有限页的访问量及补偿／懒压缩精度失败测试；
   实现后执行核心和桥接测试、格式／静态检查与 release 安装。
4. 独立审查、完整验证通过后，用前一切片相同百万固定窗口复测；
   另测有明确相机轨迹的移动窗口，并与同轨迹的直接筛选结果核对。
   工作量、帧 CPU、帧间隔、首次绑定和 RSS 分列，保留原始样本与截图。

移动百万窗口使用
`bash scripts/run_native_pressure.sh NEW_OUTPUT rust window million small_translation`。
轨迹每 tick 相位增加 0.02，水平圆弧半径 0.2 米，转角幅度 0.05 弧度；
存档、预热和测量流程不变，实际相机位置写入逐 tick 工作量样本。
固定窗口仍采用默认 `fixed`，移动结果单列，不能将不同可见数量的总耗时
当作同负载加速倍率。

命令、文件组织、类型和安全边界沿用本文既有验收入口与
[开发约束](../../../AGENTS.md)。三项实现各自完成 RED／GREEN 后检查，
最终独立审查处理阻断项再执行完整验收。

### 优先级与范围

三项指标共同评估；减少大规模数据复制、对象构建和跨语言调用的方案优先。
上一轮[实测](../../reviews/2026-11-23-logistics-display-reuse.md#百万综合验收)
已证明运输 tick 很小，但内存和挂载未有明确改善。全进程峰值 RSS 包含生成、
存读档和挂载，不能当作常驻游戏内存；保存计时包含写入前后的规则校验，
加载计时包含规则恢复，不能当作纯磁盘 I/O。

| 顺序 | 工作 | 主要收益 | 取舍与进入条件 |
| --- | --- | --- | --- |
| P0 | 分阶段时间、内存和数据量基线 | 为三项指标确定基线 | 必做，先补普通存读档与独立加载进程口径 |
| P1 | 消除恢复内部的重复构建 | 保存／加载耗时与临时内存峰值 | 首个实现切片；保留完整校验，避免全厂默认设施／队列和存档设施重复创建 |
| P2 | 顺序导出原生检查点 | 保存耗时与导出峰值 | 覆盖全量矿石；批量恢复另作条件实验，不能放宽数值语义 |
| P3 | 移动选择增量更新、局部查询计划复用 | 移动帧耗时、每帧分配 | P1／P2 检查点结束后实施；仅保留当前局部计划 |
| P4 | 入向紧凑化、批量显示提交或压缩调整 | 按热点分别改善常驻内存、存读档或帧耗时 | 条件项：记录量／占用／细分耗时确认值得处理，且配对实验有收益才进入 |

本轮不安排全世界设施改为紧凑数组、局部运输编辑、队列树重写、多线程、
异步存读档、GPU 运输或复杂遮挡剔除；这些工作改变范围较大。
若 P0 发现常驻内存主要由逐设施对象或完整世界几何占用，明确报告剩余成本，
不为达成目标自动扩大本轮。既有全量编辑性能边界继续有效。

### 数据与兼容约束

P4 入向方案首选由原生桥接单独持有紧凑的身份→入向数据，用四个方向的枚举代替
每颗矿石的 GDScript `Vector3i` 字典记录，供规则读取与显示共用。
运输核心仍不依赖宿主类；方向由宿主显式传入，不能从矿石当前三维位置猜测。
普通成交批量更新入向及退休身份；不再长期保存同一数据的宿主字典和显示副本。
显式编辑需要物化时，成批读取当前数据；显示几何失效不能清除仍有效的入向。
初始入向仅为逻辑段首格矿石保存；当前百万四段夹具最多八条初始记录，
不能按两百万矿石推算这张表的大小。生产／跨段成交会增加记录，消费会退休记录。
P0 需记录初始／长期运行／复杂工厂的实际条数、占用及复制／恢复成本，
足以达到本轮收益门槛才进入。不能把 PackedArray 引用或写时复制视为
已经发生的物理复制。

入向子块采用版本化紧凑编码：身份保持 int64，方向使用经过校验的枚举；
序列长度一致，重复身份、非法方向、非存活身份和已知端口方向冲突均拒绝。
物流子块的 `rust_host_version` 缺省或为 1 时，`incoming` 保持当前字典格式；
为 2 时，`incoming` 为 `PackedByteArray`：先存小端 uint64 记录数 N，
随后按身份严格递增存 N 行，每行 int64 身份及 uint8 方向，共 `8 + 9*N` 字节。
方向 0／1／2／3 分别为前／右／后／左，与现有方向编码一致。
校验总长度、记录数与身份范围后再分配；未知版本、截断和多余字节均拒绝。
记录保存原有入向表成员，不凭空要求所有存活矿石均有记录。
新载荷显式分流解码，不得由字段类型暗中更换运输规则；
外层世界格式与原生运输快照无需为方向编码一并升级。
旧档在独立实例内转换，失败保持当前游戏；保存后的继续演化保持一致。
成批校验与逐项参考校验接受／拒绝相同输入，不放宽身份或几何绑定检查。

P1 将加载的字段检查、拓扑恢复和规则采用拆开，避免 `bind_world()` 先创建
一套默认设施／旧后端队列，随后又被存档设施替换。已确认选择 Rust 时，
不为其完整恢复创建 GDScript 位置求解器的空队列包装；默认后端仍保留所需队列。
原生布局审计可与实例构建分开，避免先建立随后丢弃的空运输网络；
合法边、缺失边、设备、逻辑段、等待接缝及有序几何仍须全部核对。
这些是一次解码内部的去重，不重复实施已完成的
[T17 加载交接](001-logistics-performance.md#装饰批量绘制与加载去重)。

P2 原生检查点按队列次序顺序写出身份及补偿间距，保持现有快照字节和记录顺序，
包括懒压缩状态的逻辑 `main`／`correction` 位级结果。有限范围显示读取返回
前缀距离，不能直接当作快照间距导出。预估容量并直接填充输出，避免先导出
全部矿石对象或再保留一份完整记录数组。不改 tick 的队列算法。
原生恢复批量建树仅列为 P2 的条件补充：逐项插入确实占加载热点，且能保持
聚合求和、后续边界归属与演化时才采用；不因理论复杂度就重写队列。

保存前验证、保存后的实际磁盘重读验证、SHA-256、压缩、长度上限、
非活动 bank 写入与原子指针／索引切换继续有效。可以复用校验逻辑和减少
临时对象，不能用内存快照替代磁盘校验，不能提前释放失败时须保留的活动世界。
**上述保存前、读回后的完整规则恢复要求已由
[003](003-save-without-reconstruction.md#保存与加载边界) 替代；
磁盘文件校验、原子提交及加载失败保护继续有效。**
命名、覆盖、自动轮换、旧档后端和失败保留现场继续继承
[006](../prealpha-1/006-session-and-save.md)、
[007](../prealpha-1/007-multiple-saves.md)与
[011](../prealpha-1/011-pressure-save.md)。

### 测量、收益门槛与停止条件

以本轮实施前源码／原生库的同条件重测作基线，历史窗口仅作方向参考。
使用三个规模（10k、100k、million）的原压力档，另加含多支路、合流、
空／满环、库存与设备的固定复杂工厂；记录生成参数、种子、拓扑与负载指纹。
Rust 百万四逻辑段蛇形线不能代替复杂工厂。两个后端各自与自身基线对比，
不以不同规则的吞吐或更多缓存命中证明等价加速。默认 GDScript 后端至少完成
同档存读档、固定／移动显示和正确性回归；超时／无法完成的大规模结果明确披露。

每种关键比较使用至少三次独立进程，顺序测量，保留所有运行及来源，
禁止只挑最快的一次；同时保留每次分布与三轮中位数。图形沿用 120 tick 预热、
300 tick 测量、相同相机／高度／距离；固定和小幅移动窗口分列。
帧 CPU、实际帧间隔的 p50／p95／p99、最大值和超预算比例同时记录。
系统内存压力、换页、图形前台状态和文件缓存状态也记录；
相同状态比较，不把热文件缓存计时说成冷盘加载。

内存报告至少分为：独立加载进程中的稳定运行 RSS、保存峰值、加载／切换峰值、
全流程高水位；引擎静态内存及可测原生堆另列。稳定运行不能沿用生成器进程
不下降的 RSS；从已有磁盘档单独启动测量，固定预热／静置窗口。
加载新档时允许旧活动世界与待校验新世界必要地共存，禁止以先清旧世界降低峰值。
再做三次连续保存／加载／换世界，检查退休身份和局部缓存不会随轮次无界增长；
分配器留存与对象仍被引用分别说明。

保存总耗时从游戏快照导出到 bank／命名索引提交成功，包含全部校验和读回；
加载总耗时从选择已存在档案到新世界首次可操作帧，包含磁盘读取、规则恢复、
场景挂载及显示准备。压力生成和额外路线审计另列，不混入普通玩家操作。
既有命令可复现全流程基线：

```bash
RUST_CONVEYOR_SOURCE=/path/to/RustConveyor \
  bash scripts/run_native_pressure.sh /tmp/new-final-fixed rust window million
RUST_CONVEYOR_SOURCE=/path/to/RustConveyor \
  bash scripts/run_native_pressure.sh /tmp/new-final-moving rust window million small_translation
bash scripts/verify.sh
```

输出目录须不存在。生成入口同时保存小型 `route.bin` 工厂证书；
独立加载进程在计时前读取证书，不导出全量物流或重复拓扑审计。
生成进程退出后，编排器流式计算证书、bank 文件与当前指针摘要，
保存 `fixture_manifest.json`；独立加载前核对全部摘要，拒绝错配档案或证书。
摘要计算在 Godot 进程之外，不计入玩家存读档操作或加载进程 RSS。
采用本轮新生成的对应档，顺序测量独立加载和连续三次切换：

```bash
LOAD_SAVE=/path/to/new-final-fixed/million/save SWITCH_COUNT=3 \
ALTERNATE_SAVE=/path/to/new-complex-fixed/complex/save \
RUST_CONVEYOR_SOURCE=/path/to/RustConveyor \
  bash scripts/run_native_pressure.sh /tmp/new-final-load-fixed rust window million
LOAD_SAVE=/path/to/new-final-fixed/million/save \
RUST_CONVEYOR_SOURCE=/path/to/RustConveyor \
  bash scripts/run_native_pressure.sh /tmp/new-final-load-moving rust window million small_translation
```

`complex` 选择固定综合工厂 v1：三台矿机、两处合流、空／稀疏／满环和四个箱子，
其中三个箱子组成库存链；生成种子为 0，证书校验实际合流、环路与设施数量。
它不采用蛇形线的单一路径证书。默认后端可使用相同入口。
`BENCHMARK_PROJECT` 可指向已导入的隔离副本；编排器核对实际执行资源与原源码指纹，
并记录实际使用的原生库与输入档文件哈希。

`phases.json` 保存嵌套阶段的包含／独占耗时、Godot 静态内存与对象数边界、
200 ms 外部 RSS 及边界采样、操作峰值、稳定窗口分布与磁盘文件大小。
macOS 用 `proc_pidinfo` 的 resident size；非正数或不可读值不当作零内存。
短于采样间隔的内部峰值仍可能遗漏；未采到的阶段明确列为不可用。
对象数与静态内存不是 Rust 分配次数或分配总量。
首次可操作时间量到加载、挂载后的第一个成功 tick／显示提交，
图形另量首帧绘制时间；压测的拓扑与人口审计不计入玩家加载时间。
`save_operation` 包含导出到提交，`load_operation` 包含读盘到首个成功 tick／显示，
各内部阶段仍单列；RSS 峰值按完整操作归属。首个 tick 计入 120 tick 预热，
零预热时另列 bootstrap，不混入稳定测量。图形截图在稳定窗口结束后、切换前保存。
连续切换需用 `ALTERNATE_SAVE` 指定同后端不同世界的预生成档；
每轮先保存当前挂载世界，再交替加载两个世界，保留旧世界直至新档成功解码，
挂载及首次成功 tick／显示后以相同 12 帧静置窗口记录 RSS、对象数和局部工作计数。
保存、加载和静置各自独立计量；检查器要求阶段、正数 RSS、完整证书和全部请求轮次。
原生格式、包契约、桥接测试／Clippy／release 安装命令沿用本文上方验收入口。

每个图形测量 tick 在 `work_samples.json` 记录引擎窗口的焦点状态；
前台请求不等于焦点已获得，焦点混合或缺失的帧间隔不进入正式配对比较。
`scripts/summarize_native_pressure.py RUN_DIRECTORY` 汇总 `runs.json` 所列全部运行，
显式标注不足三次独立成功、缺失所需生命周期或来源／负载／焦点不一致的组。
普通游戏保存使用独立加载进程的第一次生命周期保存，每轮各取一次；
后续切换保存涉及不同世界与时钟，单列原始记录，不与首次保存平均。
生成器保存与普通游戏保存的耗时及峰值分别汇总。
比较还按模式要求取得完整指标：两种模式均记录加载、解码、挂载、稳定／加载
RSS 和 CPU／帧间隔；生成模式另需生成保存与检查点，固定独立加载另需首次
普通保存及其峰值。移动独立加载的普通保存标为不适用，不能用缺失数据代替
不适用。各轮显示目标阶段缺失或必需指标缺任一独立样本时拒绝比较。
Rust 来源未知、库或描述符与构建清单不符的组也不得准入；
准入只证明比较条件完整，仍须逐项检查下文收益和回退门槛。

本轮规划目标如下，均不是已取得结果或实施承诺：

- 百万 Rust 保存／加载峰值分别争取降低至少 25%，保存总耗时与加载到可操作
  总耗时分别降低至少 30%。实际基线由 R01 确认，不能从约 14 GiB 全流程峰值
  直接换算稳定内存目标。
- 稳定 RSS 不出现明确回退，按 R01 确认的不必要常驻副本占比制定下降目标；
  有足够空间时争取下降 10% 以上。若常驻成本主要来自本轮排除的设施／几何，
  报告剩余占用，不能把临时峰值减少说成常驻数据减少。
- 同负载百万固定窗口帧间隔 p95 争取不超过 20 ms，移动不超过 25 ms；
  同时报告 CPU 和帧间隔，稳定 60 FPS 不作为自动扩展本轮的理由。
- 默认后端和复杂工厂的三项指标不出现超过重复测量波动的明确回退；
  工作量与行为保持，未支持／未测完范围不藏入平均数。

保留单个优化切片的最低门槛为：目标阶段耗时中位数降低至少 15%，且对应
玩家端到端时间／帧间隔至少降低 5%；或对应稳定／操作峰值内存降低至少 10%。
在三轮中方向一致、超过环境波动，且另外两项没有明确回退时才采纳。
缓存若净增内存而没有达到时间门槛，不采纳；只把工作移出计时窗也不算收益。
这些门槛决定保留与否，不能替代运输、兼容、原子保存及失败恢复验收。

最多完成上述五类工作；每个条件项最多一次细分测量和一次配对原型实验，
失败即保留当前实现。本轮目标未达时报告差距与剩余成本，结束普遍性能优化，
转回玩法开发；只在代表性玩家负载出现明确卡顿、内存不足或存读档等待问题时
另开专项任务。预计约 6～9 个集中开发／验证时段，最终取决于 P0 及条件项，
不保证以帧率、内存和存档三个目标全部达标来无限追加重构。

## 新后端运输规则

- 路径为有向三维中心线网络，连接来自设施端口，不按空间接近自动连通。
  不同高度交叉或相邻但端口不合法的线路不连接。
- 平带中心线长度 0.5 米，45° 坡道长度 `sqrt(0.5² + 0.5²)` 米。
  物品沿实际带面以 1 米/秒运动，坡道完整运输时间约 0.7071 秒，
  不使用水平投影速度。上坡、下坡与转弯保持方向和位置映射一致。
  本条已通过原生宿主契约验证，替代 009 中 Rust 后端范围内的“相同单段运输时间”。
- 采用 Rust 连续交接：跨段保留剩余 tick 时间，仍受实际空间、间距、
  端口调度和预约约束。旧后端出口截断和接收资格规则不作为逐 tick 等价要求。
- 环路按已验证的 Rust 调度能力运行。空/稀疏/满环及带外部输入环均必测；
  保守满环停止与原后端满环循环的差异必须显式记录。
- 最小间距采用沿中心线的距离；坡道上的容量由长度与间距决定。
  不通过水平投影或固定“两件每格”限制伪装新速度。
  入口、出口边界归属以及跨片段计数需在包契约中明确并测试。
- 物品运输状态只有 Rust 一份权威数据；Godot 显示结果为只读采样。
  矿机生产相位和箱子库存仍由宿主管理，以实际成交事件结算。

## 编辑、存档与错误边界

建造、端口预检、坡道高度、旋转及拆除继续使用既有世界规则。
批量线路先统一预检，再按固定边界提交运输变更。
存活物品保持身份，载矿旋转的进度按明确的路径替换策略映射；
删除仅移除对应运输区间内物品，并返回身份清理结果。
两个原先断开的载矿端点可能在接通时具有不足的接缝间距；
此时保留独立逻辑段，出口等待，下游继续运动。
接缝满足原生间距和预约条件后才建立运输连边，不合并重叠队列、
丢弃物品或以容差放宽间距。等待连边属于存档逻辑状态。

组合存档含世界、设备库存/生产相位、后端身份和版本化运输快照。
新快照先创建并校验独立实例，再整体采用；非法加载不修改当前活动游戏。
核心修改后内部失败停止物流，宿主不得继续扣库存；
恢复同一组合检查点，不能只恢复旧运输状态而保留较新库存。
旧格式保留其后端，显式迁移必须验证身份、数量和继续演化。
设备先预留本 tick 的生产和库存资格，原生成功后再提交相位、库存、时钟和身份。
纯库存到库存的边沿用原规则：每个接收设备每 tick 仲裁一个来源，
转移该来源本 tick 的全部合格库存；本 tick 新接收的库存不能再次转出。
带到设备、设备到带仍按原生成交身份结算，带间交接保留实际入口方向。

### 当前接入与待补边界

`GameConfig.transport_backend` 为新会话的显式入口，默认 `gdscript`；
选择 `rust` 后由 `LogisticsData` 注入原生运输实例。加载保留存档的后端。
当前实现压缩普通连线，按可见格子批量采样；显示固定 tick 的已提交位置，
尚未提供子 tick 预测。矿机、箱子以及旧后端调用方继续通过原门面工作。
编辑目前采用显式全量物品导出后重建，尚未达到局部编辑的性能目标；
加载时核对原生快照的配置、时钟、逻辑段长度、连边和端口/设备，
以及有序逐格几何绑定和等待接缝。无分支环路压缩为两个逻辑段；
核心不支持单段自连，不能为长环逐格建段。紧密满环首个 tick
可重新归属恰处出口的物品；完成边界归属后允许保守停止。

随后生产端堵塞；该入口臂的物品不能当作已通过合流或持续环路吞吐。

## 性能口径

百万压力档必须记录真实传送带、坡道、物品、逻辑段与候选采样数量，
确认整条线路拓扑及出口可达性，记录加载/挂载耗时。
先预热，再采集固定窗口的 p50/p95/p99/最大值与超预算帧。
分列模拟、宿主准备、绑定调用/转换、成交结算、范围采样、
三维映射及表现提交；记录工作量、吞吐、内存和适用限制。

同规则且行为/实际工作量对齐的共同负载才判断性能优劣。
采用不同坡道速度或满环规则的场景分别报告耗时、吞吐和行为，
不能以更少运动或未完成测量证明加速。
原始日志与样本使用工具输出到临时目录，长期保留必要汇总与复现入口。
测量前通过游戏既有校验和 bank 写入器保存，再从磁盘解码独立会话并挂载；
分别计量检查点导出、保存/校验、读档/解码、拓扑审计和场景挂载。
进程峰值 RSS 另用系统计时工具记录，Godot 静态内存不包含 Rust 全部堆分配。
无实时连接时不得宣称编辑器视觉验收完成；无头运行只报告无头性能。
独立图形进程须另行记录渲染器、测量期绘制证据及截图，并披露缺少编辑器复验。
