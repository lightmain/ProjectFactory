# 001：物流性能优化与开发计划

所属版本：prealpha-2。状态：首项更新，方案已确认，开始实施；规则变化仍待实施。
面向开发者、测试与审查人员；实施进展见[开发任务与依赖](#开发任务与依赖)，
不表示优化或数组越界修复已经完成。
版本阶段与 prealpha-1 封版范围统一见 [README](../../../README.md#版本规格入口)。

## 目标与范围

让大规模工厂避免每个逻辑 tick 和显示帧逐设施、逐矿石创建对象与复制全图数据，
并降低设施装饰和重复读档解码的成本。先建立可信的正确性基线，
再分批替换运行数据表示，保持玩家看到的运输、生产、建造和存档行为。

本次假设：继续使用现有 Godot／typed GDScript；以现有百万带压力档作为主基准；
优先采用连续运输线路与间距表示，而不是立即引入原生扩展或多线程。
性能数字是开发目标，必须通过同条件测量确认，不能预先承诺所有硬件达到百万规模实时运行。

本次包含数组越界排查、差分回归与性能基线、最小接口解耦、运行数据复用、
连续运输线路求解、可见范围采样、矿石高度裁剪、设施装饰批量绘制和消除重复解码。
不增加玩法、无限世界、物流降频、离线生产、异步存读档、ECS、原生扩展或多线程。
按需地形网格／碰撞与平面合并仅在最终测量仍显示其阻碍目标时另立后续任务，
不纳入本首项更新的必交范围。

## 证据与数组越界

### 已有性能证据

依据 [2026-11-08 压力场景分析](../../reviews/011-pressure-save.md#2026-11-08压力场景性能原因分析)：
逻辑每 tick 创建全图队列包装并求解、交接；显示先准备全图矿石再做距离筛选；
箭头／端口大量使用独立节点；读档重复解码完整快照。
存档紧凑编码减少文件表达成本，但恢复后仍是逐机器、逐矿石对象。
原始测量与分项旁证的采样条件不同，不能将分项表冒充同一长帧的精确分解。
详细数字、硬件、数量、限制和原始产物位置只在该审查记录维护。

### 数组越界排查

已观察到手工运行停在 `LogisticsTopology.rebuild` 的数组越界：

```text
Out of bounds get index '1016187' (on base: 'Array[LogisticsMachine]')
```

当次位置为 `scripts/core/logistics_topology.gd:107`。已停止该运行；
相同原始 ZIP 的独立分项运行未触发，当前没有稳定复现或已确认根因。
不能直接判定为拆除后索引未更新，也不能把断点暂停解释为干净压力测量的慢帧。

排查先保留触发存档和操作序列，再记录首次非法访问之前的机器／格子／邻接数组长度、
查询坐标、返回索引、世界边界、dirty 状态、tick、增删／旋转／恢复顺序。
按需要检查索引映射和数组压紧、重建、恢复之间的一致性；这些是候选方向，
必须用运行证据排除或确认，不在每个正常 tick 增加全图诊断扫描。
不输出整份百万对象数组；故障日志记录首个违规项、前后有限操作和复现标识。

退出条件：找到可复现的最小或缩小案例，先补正确失败的回归测试，再修复根因；
原触发链路、大档恢复／推进及同类增删序列均通过。只增加边界判断跳过设施，
或换算法后暂时不再报错，均不能作为结案依据。
若无法复现，继续登记未解决条件；可继续 T01 的独立测量和后续显示方案设计，
不提前实施依赖尚未满足的任务，不得将问题关闭，
也不得将新运行数据替换作为绕过该问题的办法。

## 技术方案与基础建设

### 最小接口解耦

复用 `LogisticsData` 的外部入口和信号，不先做全仓库抽象改造。
在已有模块中明确以下边界；新增类型须由实际测试或消费者需求证明必要：

1. **模拟入口**：固定 tick、编辑结算和权威状态，仅接受纯数据。
   线路索引、活动集合与求解暂存区归模拟内部，视图不得访问可变机器数组。
2. **显示读取**：调用方传入纯坐标范围／候选格和采样余量，返回独立只读意义的结果；
   不传 Camera3D 到 core，不触发生产或交接。
   保留旧全量查询的行为，主场景热路径改用范围读取。
3. **存档边界**：旧格式输入经校验转换为已验证 `SessionSnapshot`；
   恢复只消费该结果一次，保存从权威状态导出规范内容。缓存不是可信度证明，
   不能跳过数据完整性检查。

既有独立松弛参考、固定种子随机位置求解、交接／公平／存档／显示生命周期测试均复用，
而不是重新创建同名框架。新基础建设只补整工厂差分、操作回放、故障上下文与性能计数。

### 连续运输线路与间距表示

将适合聚合的单出口连续带段用路径长度、队列顺序、矿石身份序列及相邻间距表示。
无阻挡段用共同位移或头尾偏移推进，堵塞时维护受影响的间距／边界；
合流口、库存设施、编辑断点作为显式边界。转弯和坡道通过路径映射还原带面位置。
矿石身份仍逐颗可追踪，但不要求每 tick 为每颗矿石创建对象或更新所属格字段；
查询、保存和交接需要时从线路位置确定所属设施。

同速连续段的表示参考 [Factorio FFF-176](https://factorio.com/blog/post/fff-176)；
堵塞间距压缩的优势是特定条件下的摊销成本，插入、移除或编辑可能使缓存失效。
不声称所有线路、合流、满载环或每个 tick 都能严格 O(1)。

先支持直线，再覆盖堵塞与同步恢复、合流／闭环、坡道与动态编辑。
每步用旧实现和独立小规模参考验证结果。内部格边界的容量、下一批次交接、
公平轮询和最大可行位置必须有等价证明及反例测试，不能用“整体位移看起来正确”代替。
满载环可使用环形身份顺序与偏移，不能按每颗矿石重建整个环。
不支持的局部结构可暂时走旧求解路径，但必须明确依赖范围和重复结算边界，
统计回退工作量；不得把整厂隐式回退后仍宣称百万规模优化完成。
混合路径阶段必须测试新线路与旧求解区之间的双向边界交接、堵塞恢复和边界编辑，
确认同一矿石只结算一次、不可见依赖不遗漏；双向指分别覆盖新→旧和旧→新连接。

拓扑或方向变动才重建受影响线路／索引；普通 tick 复用结构与有界暂存区。
矿机按到期事件或活动集合处理，库存／端口仅在可能变化时参与；
这些跳过条件必须证明不会漏生产、释放空位或改变轮询。
保存可在非热路径展开为既有格式 4 的规范机器行，重建运行缓存；
优先不升级文件格式，若无法表达全部既有状态，先单独修订格式及兼容验收再实施。

### 可见范围采样与高度裁剪

先通过空间索引筛选附近设施，再分配结果和采样矿石。
候选范围是保守筛选，最终仍以活动相机到设施格子中心的三维距离判定，
保留 [005](../prealpha-1/005-game-config.md#配置来源与生效) 的距离和边界规则。
距离关闭时不准备全图显示数据，后台照常运行。

仅采样可见格不能切断不可见下游对堵塞位置的约束。
可见矿石的边界内预测必须读取已结算线路约束／缓存，必要的不可见依赖单独计数；
不能每帧为一小片可见区域重建整个工厂约束图。
相同后台版本、余量与范围可以复用结果；范围变动、编辑及相机切换正确失效，
调用方修改返回数据不污染权威状态或缓存。

新增 `GameConfig.ore_render_max_height_above_camera`，以米为单位，默认 **2.0 米**
（四格），同时在 `config/game_config.tres` 明确保存默认值。
只控制传送带上的矿石；箭头、端口、设施实体和库存显示沿用原规则。
高度采用当前活动相机的世界 Y，不用玩家脚底或固定地层：
矿石最终渲染中心的世界 Y 大于 `camera_y + limit` 时隐藏，恰好等于时保留。
合法值为有限非负数；0 表示只显示中心不高于相机的矿石，非法值按默认值处理。
参数运行时修改在下一次显示刷新生效；不写入物流状态或改变存档运输数据。

按整段路径包围范围提前排除完全高于阈值的矿石候选；
斜坡或转弯跨越阈值时逐颗按最终位置判定，不能用设施基准格高度误删阈值下的矿石。
隐藏后再次进入范围按当前 ID／位置恢复，不重播运动。

### 装饰批量绘制与加载去重

复用现有 `ItemRenderPool`／批次能力，将箭头和端口按共享网格、材质和空间分区批量提交，
保留设施朝向、坡度、高低端、颜色与可见性。不得每设施重复创建共享 Mesh。
矿石池已批量化，不把重新实现矿石池列作收益。批次容量与空缓存有界复用，
删除、旋转、重绑和世界重置及时失效；是否调整阴影根据对照测量决定。

`SaveGameStore` 将一次完整校验所得快照交给会话加载入口和 `pressure_test.gd` 的运行入口，
消除所有正常加载消费者对同一内容的第二次 `SessionSnapshot.decode()`；
百万档加载对照必须使用这条一次重建的路径，不能只优化菜单而保留压力工具双解码。
保留损坏拒绝、旧格式转换、当前场景失败保护与保存后的实际文件重读验证；
“一次解码”指一次成功加载的重建次数，不禁止保存写入前后各自必要的校验。

## 测试与性能验收

### 正确性基线

在数据改造前保存可重放的旧实现基线；修复数组越界后建立用于正常行为差分的稳定参考。
旧参考留在测试／隔离基准中，不永久维护两个生产模拟器。
小规模独立松弛参考验证位置最大解；整厂差分同时比较所有可观察状态，
防止旧、新实现共享同一错误。

固定种子生成合法小世界与操作序列，逐 tick 比较数量、矿石 ID／顺序／入向／进度、
输入轮询、生产相位、最近输出及待生效编辑；整数状态精确一致，
归一化进度容差沿用现有测试的 `1e-6`，不能靠扩大容差掩盖批次变化。
失败输出种子、首次差异 tick、缩小后的存档和操作序列。
插入／拆除有预期增减时用带账目的守恒检查，不错误要求总矿量永远不变。

纯规则测试在 `tests/unit/`，真实保存、主场景与显示协作在 `tests/integration/`；
性能产物使用独立 `build/` 目录，详细报告由工具生成，必要结论留在 `docs/reviews/`。
验证框架和环境继承 [开发说明](../../development.md#环境要求)，
代码类型／命名／core 边界与安全约束继承 [AGENTS](../../../AGENTS.md#命名类型与架构)。
例如边界输入采用显式类型 `func sample_cells(cells: Array[Vector3i], extra_time: float) -> Array[LogisticsOreQueue]`；
这是接口形态示例，具体签名在任务 T03 确定。

### 基准矩阵与目标

同时测量空带、稀疏运行、满载运行、完全堵塞／解除、多路合流、满载环、
连续坡道、批量建造／拆除与载矿旋转；不能只测静止空世界。
规模覆盖 1 千、1 万、10 万和现有百万带压力档，小档检查全状态，大档使用线性证书、
身份／数量校验和及工作量统计；全状态扫描在验证阶段而不是每个正常 tick。
大档除原蛇形链外还需堵塞及恢复对照，孤立小合流／环不足以证明百万规模收益。

T01 固定存档指纹、Godot／渲染器、硬件、分辨率、视角、距离、预热与时间窗口，
同时记录 shader 缓存状态、物理追赶上限和自动保存是否进入采样窗口。
逻辑测试用同一状态分别记录单 tick、显示、加载和挂载；
图形测试用实际完成 tick／绘制帧除以墙钟秒。
基线和新版均运行至少三轮，报告中位数、p95、最慢 tick／帧、峰值内存、
节点与绘制调用、临时对象／复制项和线路／边界访问计数；
每轮稳态窗口至少 30 秒且至少 120 个已完成样本，异常长运行须记录超时和缺样本，
不能把未完成样本当作高帧率。关闭高度裁剪的对照可使用足够高的合法阈值；
测算法和批量绘制收益时保持可见集合相同，再单独报告默认高度裁剪的收益。

首项目标为参考硬件上的百万带稳态 **60 逻辑 tick／秒、至少 30 绘制帧／秒**，
单 tick p95 不超过 16.7 毫秒、显示采样 p95 不超过 4 毫秒。
这是待验证目标；T01 按同条件实测确认预算，若不可达，保留目标差距和瓶颈，
先提交新的范围／方案供审阅，不以降频、丢补算或只隐藏物品视为达标。
1 千／1 万规模的正确性全部通过，tick、采样和加载时间中位数不得劣化超过 10%；
低于计时精度的差异报告测量限制，不作失败依据。
加载验收要求一次成功加载仅重建一次快照，
同档解码与验证耗时中位数相较双解码基线至少降低 40%，记录峰值内存不高于基线。
复杂度用计数及规模序列验证，不仅用耗时比值；
固定可见集合扩大远处工厂时，显示结果复制量必须保持有界，依赖访问量另报。

- **A：T01～T04**。数组越界有根因与回归；旧参考、接口和差分可用。
  若复现仍受阻，明确登记，不开始权威运行表示替换。
- **B：T05～T09、T17**。显示读取、装饰与加载各自有对照收益；
  全回归通过，原模拟语义未变。T04 后显示、装饰和加载可并行，
  但涉及同一文件时串行集成，每批独立验证。
- **C：T10～T13**。直线→堵塞→合流／环→坡道依次通过；
  每两项检查差分、工作量和存档展开可行性，失败则缩小切片后继续。
- **D：T14～T18**。动态编辑、存档和活动处理通过，完整压力目标有实际结果；
  每个可见范围和回退结构都有计数，未达目标先修订计划，不提前标“当前规则”。

## 风险与应对

| 风险 | 应对与停止条件 |
| --- | --- |
| 数组越界无法稳定复现 | 保留存档／操作与首错上下文；未解决阻断运行表示替换和最终验收 |
| 聚合破坏批次、公平或满载环 | 先用反例和逐 tick 差分证明；不接受跳格交接、固定端口优先级或满环停转 |
| 隐藏下游影响可见预测 | 读取已结算约束与必要边界，统计依赖闭包；不能只求可见子图 |
| 编辑频繁使线路缓存失效 | 记录受影响段长度和重建成本；保留正确局部回退，最终统计覆盖率与最慢编辑 |
| 线路省了对象却仍全图扫描 | 显式统计线路／边界／矿石访问和复制量，百万堵塞及运行都测 |
| 兼容层抬高保存或峰值内存 | 分开测运行、保存、加载峰值；保持旧格式和原子失败保护，不长期双份全图权威状态 |
| 目标需要进一步引擎能力 | 先交付数据／显示／加载实测及差距，再评审原生或并行方案；不直接扩大本轮范围 |
