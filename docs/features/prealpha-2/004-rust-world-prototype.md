# 004：纯 Rust 百万方块最小原型

所属版本：prealpha-2。状态：**A 已实现，正式三尺度九轮测量满足预算；B 未实施**。
日期：2026-11-25。面向原型实现者与性能验收人员。
本实验不替代现有游戏规则、存档格式或后端；当前接入与保存边界仍见
[002](002-rust-conveyor-integration.md) 和 [003](003-save-without-reconstruction.md)。
方案的独立审查见 [设计审查](../../reviews/2026-11-25-rust-world-prototype-plan.md)；
实现、正式测量与独立审查见 [实现验收](../../reviews/2026-11-25-rust-world-prototype.md)。

## 目标与判断边界

先回答一个问题：**不用 Godot、只构建一份最终世界数据时，Rust 存储、恢复和局部访问百万静态方块需要多少时间和内存？**

最小交付是一个单线程命令行程序，完成“生成世界 → 保存 → 退出 → 新进程加载 →
局部编辑 → 返回观察范围数据”。不创建窗口，不接 GDExtension，不模拟生产或运输。
第一阶段记为 A；只有 A 正确且满足预算后，才考虑本文末尾的 B 运输实验。

本实验可以证明所选 Rust 数据模型的静态世界成本，以及查询是否只依赖局部范围。
它不能单独证明 Rust 比 GDScript 快多少、完整游戏可以几秒加载、
百万传送带可以实时运行，也不能证明 Godot 网格与碰撞构建成本已消失。
要比较语言效率，需要同数据、同算法、同检查与同测量边界的独立对照；
本轮不新增这套对照。

背景证据：既有百万带加载约 62.77 秒，其中读取与解码约 38.64 秒、
场景挂载约 22.96 秒；这些阶段属于旧游戏实现。
直接恢复候选曾在相同引擎和原生库下改善加载，但因另一规模内存回退撤下。
详见 [历史测量与候选处置](../../reviews/2026-11-24-final-optimization.md)。
这些结果提供实验动机，不是本原型的性能基线。

## 默认与范围

- “百万级”采用 x=128、y=64、z=128，共 **1,048,576 个非空格子**，全部实际写入数组；
  不使用隐式平地、统一填充值、压缩或按公式即时生成查询结果。
- 原型支持空格和四种静态方块类型。四种类型只代表数据值，没有配方、库存、方向或设备状态。
- 每格为 `u16` 方块类型，0 表示空。纯格数据为 2,097,152 字节，即 2 MiB；
  这是模型的容量计算，不是进程内存实测。
- 世界维度为 16 的正整数倍，各轴不超过 128；有效坐标为 `[0, size)`。
  操作使用整数格坐标，固定区块边长为 16。
- 不增加 ECS、异步任务、多线程、网络、数据库、压缩格式、对象池或通用插件体系。
  不导入旧游戏存档，不修改现有游戏或 RustConveyor。

## 结构与数据归属

```mermaid
flowchart LR
    Driver["CLI 与测量驱动"] --> World["Rust 世界：唯一完整状态"]
    World --> Disk["原型二进制存档"]
    Disk --> World
    World --> View["范围内区块数据与统计"]
```

`World` 持有按坐标直接索引的区块数组；每区块为 `Box<[u16; 4096]>`。
区块索引使用 x 最快、其次 z、最后 y；区块内部也使用这个顺序。
同一坐标只能对应一个格子，查询不使用逐格哈希表或逐格堆对象。

世界持有当前修订号、五类格子数量，以及每区块最后修改的修订号。
`set_block` 在成功修改时更新对应计数和修订号；相同值写入为无变化操作。
越界或非法类型在修改前拒绝，统计不变。读取世界总体统计为固定数量字段，
不得为一次统计查询重新扫描世界。

显示接口只生成数据，不生成网格、碰撞或逐方块三维位置：

| 原型接口 | 行为与复杂度 |
| --- | --- |
| `get_block(cell)` | 直接索引一个区块和一个格子 |
| `set_block(cell, kind)` | 修改一格并更新计数、区块修订号；不扫描其他区块 |
| `stats()` | 返回非空数、各类型数量、世界修订号 |
| `update_view(bounds, cursor, output)` | 只访问范围相交的区块，返回进入、更新、离开记录 |
| `save(writer)` / `load(reader)` | 显式全量操作，计费依赖世界格数 N |

观察范围为半开整数 AABB，先校验 `minimum <= maximum`，再与世界范围求交。
以整个区块为返回单位：进入范围时返回完整区块；已经在范围内且修订号变化时
重发该区块；离开时返回区块编号。未变化且未移动的第二次查询不得重发格数据。
`ViewCursor` 只保存上次可见区块及其修订号，不保存世界副本，不消费其他观察者的变化。
游标绑定一个世界实例；更换世界时创建新游标，不跨世界比较修订号。
按区块返回会多包含边缘格子，必须记录实际访问区块数、返回格数和字节数。

输出使用可复用 `Vec<u8>`，区块编号和类型数组按固定顺序以小端编码；
进入与更新区块包含每格类型，离开区块只包含编号，同时附总体统计和世界修订号。
不使用逐格 JSON 或为每格创建对象。单个观察者缓冲区是必要的局部数据副本，
不是“零复制”；接口编码和复制必须计入范围查询耗时。

已实现的 Rust 接口示例：

```rust
use factory_world_probe::{Bounds, Cell, ViewCursor, World};

let mut world = World::generate(Cell { x: 32, y: 16, z: 32 }, 20_261_125)?;
let mut cursor = ViewCursor::new(&world);
let mut output = Vec::new();
world.set_block(Cell { x: 1, y: 0, z: 1 }, 0)?;
let report = world.update_view(
    Bounds { minimum: [0, 0, 0], maximum: [32, 16, 32] },
    &mut cursor,
    &mut output,
)?;
```

游标使用独立的 `Rc<()>` 身份绑定世界，移动 Rust 对象不使游标失效；
保留上次可见区块与可复用的下次范围临时数组。访问计数指此次可见的不同区块数，
不包括游标内上一范围的元数据比较；读取格数仅计算确实被编码的类型值。

显示包头为 `FVIEW001`（8 字节）、修订号 `u64`、五类计数 `[u64;5]`、
非空数 `u64`、进入／更新／离开数量各 `u32`，共 76 字节。
其后依次是进入区块、更新区块和离开编号；前两者各为 `u32` 编号与
4,096 个 `u16` 类型值，离开只有 `u32` 编号。所有整数为小端；
不变查询返回 76 字节统计头，区块格数据为零。

## 存档与恢复

只有一种原型格式：magic、版本、维度、世界修订号、区块数，以及固定顺序的
区块类型数组。不序列化 Rust 内存布局、指针、区块索引或显示游标。
每次按小端写入固定长度字段；各区块内容用可复用小缓冲区处理。
具体头部为 `FWRLD001`（8 字节）、版本 `u32=1`、x/y/z 各 `u32`、
修订号 `u64`、区块数 `u32`，共 36 字节；区块内容每块 8,192 字节。
区块修订号不入档，恢复时统一设为世界修订号，新观察者首次获取完整区块。

保存从活动世界流式写出，`flush` 和 `sync_all` 成功后结束保存计时。
失败文件不能作为后续成功样本。原型只写实验目录，没有自动存档、覆盖玩家档、
双 bank 或保存后重建验证。生成命令拒绝覆盖已有同名文件。

加载检查 magic、版本、合法维度、对应区块数、准确文件长度与类型值；
使用检查过的长度进行分配。直接解码到新世界的最终区块数组，
在同次遍历中建立类型计数，不先生成默认世界再覆盖，也不调用生成器。
新世界只在成功后返回；失败不得产生可用世界。

文件身份由测量驱动在计时外用 SHA-256 记录和核对；原型格式不提供内部校验和，
因此不能声称能发现所有内容损坏或具备游戏存档的容错能力。
保存和加载时必要的格式检查仍计入其耗时。

## 夹具与测量路径

仅保留三种规模，类型由固定 seed 的明确整数混合函数生成，类型值为 1～4。
生成器须固定算法并提供小样本期望值，不依赖 Rust 默认哈希器的随机种子。
每个规模生成一次独立文件，正式加载的三次进程都使用该文件。
实际混合算法为 `fixture_kind` 的显式 32 位 wrapping 运算；
seed=20,261,125 时 `(0,0,0)`、`(1,0,0)`、`(16,0,31)`、`(31,15,31)`
分别为 3、2、3、4，并以固定期望测试约束。

| 规模 | x×y×z | 非空格数 | 区块数 |
| --- | --- | ---: | ---: |
| 小样本 | 32×16×32 | 16,384 | 4 |
| 中样本 | 64×32×64 | 131,072 | 32 |
| 百万样本 | 128×64×128 | 1,048,576 | 256 |

生成与保存是单次诊断，分别计时，不冒充三次正式分布。
每个规模正式执行三次独立 `probe` 进程；每进程完成以下路径：

1. 从已有文件加载，只量打开文件到最终世界和统计可用的 `load_total`。
   分配、读盘、解码和输入检查都包含在内。打印加载完成和 PID，等待测量驱动取 RSS；
   等待时间不计入加载或后续操作。
2. 对齐的固定 `32×16×32` 范围首次返回四个完整区块；首次数据计时单列。
   预热 100 次后做 1,000 次不变范围查询，记录耗时和确实为零的区块数据返回量。
3. 对同一范围内 1,000 个唯一格子做确定性编辑：部分置空，其余改成另一种合法类型。
   每次编辑后更新范围数据，计时包含修改、增量统计和输出编码；
   同值写入另由正确性测试覆盖。统计实际修改数和重发区块数量。
4. 只在百万样本做移动观察：x 方向按一格移动，在 `[0, 96]` 内往返；
   y、z 固定为 0，范围大小不变。预热 100 次后查询 1,000 次。
   相交区块通过坐标求得，不遍历全部区块；分别统计进入、更新、离开和字节数。
5. 在修改前及编辑阶段结束时，分别在计时外全量核对世界与独立参考，不能只比较非空数量。
   保存各阶段的显示消息用于计时外审计；按相同命令顺序推进参考世界并逐条应用消息，
   每次编辑刷新、进入、离开后的缓存都必须与参考世界的可见区块一致。
   编辑阶段单独审计后才开始移动，不能用重新进入后的补发掩盖早先漏发。
   验证用的参考世界和消息记录不是后端状态，仍计入整个 probe 的峰值 RSS；
   记录或复制消息在操作计时结束后进行，阶段审计完成即释放记录。

保留每次操作的整数纳秒样本，计时期间不逐条打印、写日志或执行审计。
使用 `std::time::Instant` 单调时钟，百分位采用 nearest-rank：
升序样本的 `ceil(p × n)` 项，排名从 1 开始，p50/p95 分别使用 0.50/0.95。
计时数组可预分配；重复调用不得因编译器消除而变成空操作。
查询工作量通过访问区块数、读取格数和输出字节数记录，而非凭耗时推断复杂度。
不变范围通过只能证明缓存有效；首次查询、编辑刷新、移动进入数据必须分别报告。

## 测量协议与目标预算

以下数值是**本实验的验收上限，不是 Rust 的速度承诺**。
本机正式测量满足这些预算，逐轮值、失败采样处置与结论限制见
[实现验收](../../reviews/2026-11-25-rust-world-prototype.md#正式性能验收)。
使用同一台机器、同一 release 二进制，单线程、串行执行；不同时跑 Godot、
其他压力任务或编译。记录 OS、CPU、Rust 版本、源码/二进制/输入档摘要、
构建参数、实际人口、修订号、每轮状态及完整 stdout/stderr。

| 百万静态样本指标 | A 阶段预算 |
| --- | ---: |
| 加载 `load_total` | 三轮均 ≤ 1 秒 |
| 生成后的完整保存，包含 `sync_all` | 单次诊断 ≤ 1 秒 |
| 对齐范围的首次区块数据 | 三轮均 ≤ 2 ms |
| 一次编辑及观察刷新 | 每轮 p95 ≤ 2 ms |
| 移动范围更新 | 每轮 p95 ≤ 2 ms |
| 整个 probe 进程峰值 RSS | 三轮均 ≤ 256 MiB |

加载报告逐轮值及中位数、最小、最大；重复操作每轮报告 p50、p95、最大值和样本数。
不变查询也报告分布，但不以它代替有数据输出的预算。
`load_total` 不等于“首个游戏可玩画面”，保存不等于游戏普通玩家保存。

macOS 驱动用 `/usr/bin/time -l` 捕获各 probe 的进程峰值 RSS，并在加载完成握手时
对其实际 PID 执行 `ps -o rss= -p <pid>`，将 KiB 转换成字节作为加载后 RSS。
若 `ps` 成功但返回零或无法解析的值，驱动通过 Python 标准库 `ctypes` 调用
Darwin `proc_pidinfo(PROC_PIDTASKINFO)`，读取 `pti_resident_size` 字节值；
必须返回完整结构和正数，报告记录实际采集方法与原始 `ps` 输出。
本机 macOS 26.5.1 的 `ps` 返回零，已确认该系统接口能返回实际驻留内存。
macOS `time -l` 的最大驻留集值按字节记录，不套用 Linux 的 KiB 单位。
加载后 RSS 是阶段快照，不是峰值；RSS 采集失败为“测量不完整”，
不能将缺失值当零或判为 A 通过。
若换平台，先明确峰值 RSS 的单位和可用采集方式，再执行正式样本。

生成后的首次读档也可能命中 OS 文件缓存。本轮不清空系统缓存，
所有加载称为“文件缓存未控制的独立进程加载”，不声称冷盘性能。
SHA-256 与全量审计在计时外，输入格式校验在计时内。

一次进程超时 30 秒、整批测量最长 5 分钟；失败保留日志和实际完成阶段。
非零退出、超时、缺成功标记、人口错误或审计失败立即停止后续正式运行。
三轮结束后才判定预算；预算不达标则报告具体阶段，不自动扩展成优化矩阵。
规模曲线用于判断全量存读档是否随 N 增长；局部查询以相同观察范围的访问计数为准，
不得因为大样本计时较快就宣称 O(1)，也不得隐藏边缘区块多返回的数据。

## 项目位置、命令与任务

本仓库的隔离 crate 为 `prototypes/rust_world/`，不改现有游戏入口：

```text
prototypes/rust_world/
  Cargo.toml             独立 crate factory_world_probe，仅标准库，Rust 1.94+
  src/lib.rs             导出原型世界、文件和观察接口
  src/main.rs            generate / probe 命令与 NDJSON 测量边界
  src/world.rs           区块、直接索引、修改和增量计数
  src/snapshot.rs        流式二进制保存、直接恢复
  src/view.rs            范围游标和批量数据编码
  src/probe.rs           操作计时、消息记录和分阶段审计
  src/audit.rs           独立平铺参考与显示消息解码
  tests/contract.rs      正确性与显示消息应用的独立参考
  tests/cli.rs           跨进程与命令错误契约
  tools/run_bench.py     生成三尺度档、三轮子进程与报告；仅 Python 标准库
  tools/test_run_bench.py 驱动单位、失败、超时与结果校验
```

从仓库根目录执行，构建、存档和日志留在本机临时目录：

```bash
prototype_output="$(mktemp -d /tmp/factory-world-probe.XXXXXX)"
export CARGO_TARGET_DIR="$prototype_output/target"

cargo fmt --manifest-path prototypes/rust_world/Cargo.toml -- --check
cargo test --manifest-path prototypes/rust_world/Cargo.toml
cargo clippy --manifest-path prototypes/rust_world/Cargo.toml --all-targets -- -D warnings
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s prototypes/rust_world/tools -p 'test_*.py'
cargo build --release --manifest-path prototypes/rust_world/Cargo.toml

"$CARGO_TARGET_DIR/release/factory_world_probe" generate \
  --size 128,64,128 --seed 20261125 --output "$prototype_output/manual.world"
"$CARGO_TARGET_DIR/release/factory_world_probe" probe \
  --input "$prototype_output/manual.world" --warmup 100 --samples 1000
python3 prototypes/rust_world/tools/run_bench.py \
  --binary "$CARGO_TARGET_DIR/release/factory_world_probe" \
  --output "$prototype_output/formal" --runs 3 \
  --timeout-seconds 30 --total-timeout-seconds 300
```

`probe` 在加载后打印 PID 并等待 stdin 的继续信号；手动使用时输入 `continue` 再回车，
自动驱动完成 RSS 采集后发送该信号。驱动最终输出 `runs.jsonl`、
`summary.json`、逐进程日志和三个源档，明确区分单次生成诊断与三次正式 probe。
报告状态分为正确性失败、测量不完整、预算未达、A 通过；不填写伪造示例成绩。
Rust 的 `generate`／`probe` 命令拒绝未知或重复选项；
`--samples` 为 1～1,000，`--warmup` 为 0～1,000。
`probe` 可指定 `--seed`，默认与正式夹具一致；该参数仅供计时外参考审计，
存档不保存 seed，加载从实际文件类型数组恢复世界。
NDJSON 顺序为 `loaded`、`audit(stage=loaded)`、`audit(stage=edited)`、
`complete(audit=true)`；最后一项保留每次整数纳秒样本与实际工作量。

以下 A1～A4 均已完成；保留切片顺序与验收供复现和后续修改使用。

| 顺序与依赖 | 切片与主要文件 | 验收和验证 |
| --- | --- | --- |
| A1，无前置 | 可修改的小世界；Cargo、lib、world、contract | 先运行失败测试；边界、同值写入、置空/换类型、统计与独立逐格参考一致；`cargo test` |
| A2，依赖 A1 | 保存后独立加载；snapshot、main、audit、lib、contract | 往返后逐格与统计一致；未知版本、非法类型/维度、截断/多余字节拒绝；跨进程加载不调用生成器；小档 generate/probe，此阶段只做加载和审计，明确标记阶段性结果 |
| A3，依赖 A2 | 观察范围与编辑刷新；view、probe、audit、lib、main、contract、cli | 初始、无变化、跨区块移动、进入/离开、两个观察者独立；消息应用结果与世界一致；`cargo test` 和小档 probe |
| A4，依赖 A3 | 可复现百万测量；run_bench、test_run_bench | fmt/test/clippy/build 通过；三尺度各三轮独立加载、全量审计、正确 RSS 与失败退出；执行正式驱动 |

A2 完成即检查一次小档端到端正确性；A3 完成后独立审查接口和测量边界，
再执行 A4；A3 才补齐完整 probe 观察工作负载，A2 结果不作为正式成功样本。
A1～A3 顺序实施，不并行修改共享世界模型；
驱动可在 CLI 协议固定后单独编写，但不可先跑正式大样本。
报告单位、超时和缺失轮次处理也须有小输入测试，不需要大压力运行才能发现驱动错误。

边界：始终先测试规则再实现，采用 checked 长度与明确错误，保留用户变更和完整失败日志；
新增实验依赖、扩大到 B 或接入游戏需要重新确定范围。不得修改 vendored 插件、
游戏存档或 RustConveyor 核心，不得为达预算关闭必要格式检查、删除失败样本或擅自提交推送。
本次独立 Rust 实验检查 Rust 构建、契约测试、驱动测试、正式测量、
文档引用、内容一致性、diff 与独立审查；没有游戏或场景变更，不运行 Godot 验证矩阵。

## A 通过后可选的 B：运输后端验证

**B 不属于本次最小实现范围，A 通过不自动授权执行 B 或迁移游戏。**
其价值是补上 A 没有证明的“设备、拓扑、物品队列”的成本：

- Rust 世界保留百万带格的显式几何映射，RustConveyor 作为独立依赖。
  只通过 `rust_conveyor::api` 使用 `add_segment_gaps`、`tick`、
  `sample`/`sample_adjacent_ranges`、`snapshot`/`restore` 和 `stats`；
  对应契约见 [RustConveyor 宿主 API](../../../../../RustConveyor/docs/specs/host-api.md)。
  此跨仓库链接依赖当前两个工作区的本地布局，不是仓库内自包含文档。
  `Network` 在创建线程使用，不把它假定成 `Send` 或 `Sync`。
- 第一个夹具限定为 128 条独立、每条 8,192 格的可压缩路径，
  总计 1,048,576 带格、2,097,152 个不同 ID 的物品。
  宿主在 Rust 里维护每格路径键、区间与几何，不在 Godot 建一份宿主机器图。
  这是合成运输夹具；真实路径长度、初始间距、消费口和运动观察的规则另行明确。
- 分开量宿主几何恢复、原生网络恢复、固定 tick、局部物品采样与显示数据编码，
  加载计入整个后端恢复；保存必须调用原生快照，不能凭公式生成同等人口。
  API 当前快照有自身复杂度，不能把 A 的线性方块写入速度外推到物品快照。
- 至少有真实位置变化和消费事件，保持物品守恒，加载后与未重启参考继续演化一致。
  不以空 tick 或一个完全堵塞网络当作运动性能。
- 长路径通过只说明该压缩场景可行；若要决定完整后端迁移，
  还需一个规模固定、分段多且存在汇流/设备活动的补充夹具及后续 Godot 显示接入验证。

A 不达预算：先定位静态存储、解码或局部访问的失败阶段，暂不引入运输。
A 通过：说明可以继续做 B，仍不承诺游戏加载或帧率。
B 通过并补齐复杂拓扑验证后：再评估 Godot 只持有范围内表现数据的接入；
网格、碰撞、FFI 和首个可玩画面仍需各自测量。
