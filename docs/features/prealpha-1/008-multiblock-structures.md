# 008：多方块测试结构

所属版本：prealpha-1。状态：当前规则。面向开发与验收；继承
[体素规则](001-voxel-foundation.md)、[建造方向](004-free-camera.md)及
[区块存档](006-session-and-save.md)，不改变现有物流设施。

## 行为与验收

- 数字键 7 选择 3×3×3 格测试结构（每边 1.5 米），无限建造，不生产物品。
- 放置前显示无碰撞的整座虚影；R 绕世界竖直轴转 90°，保持底面中心，
  顶面方向标记随旋转改变。切换工具保留朝向，暂停／物品栏隐藏预览。
- 以实际射线命中点锚定底面正中心：水平吸附到最近格子的中心，
  垂直吸附到最近格层边界。即水平索引 `round(point / 0.5 - 0.5)`、
  高度索引 `round(point.y / 0.5)`；恰好一半采用 Godot 四舍五入。
  奇数宽度结构的底面中心在中心格正中，保证所有边缘都落在格线。
  不采用命中格最小角，也不随相机朝向偏移。侧面命中仍按同一规则计算，
  与已有方块重叠时拒绝放置，不自动挪开。
- 全部 27 格必须为空、在边界内，且不与玩家／自由镜头碰撞。
  任一格无效就拒绝整座，显示失败提示；虚影与提交共享判断。
  暂不要求完整地基，沿用现有沙盒自由建造规则。
- 挖掘任意占用格都删除同一结构的全部 27 格；相邻结构独立，
  底下地形保持不变。选中时整座描边；碰撞与射线覆盖全部占用格。
- 跨数据／显示区块仍作为同一实例。存读档恢复实例身份、锚点与朝向；
  旧版本无结构存档仍可加载。拒绝孤立占位格、重复实例和不完整结构。
- 结构预览使用灰白透明体和深色箭头，无效时变暗，提交失败闪白并显示原因。
  现有物流预览保留原配色。

## 数据与参考

保留字节型区块数组，在占用格写入同一结构类型编号；额外维护
`格坐标 → 实例 ID` 稀疏索引和 `实例 ID → 锚点、类型、旋转` 表。
实例只有一份状态，格子用于占位／碰撞／查询，不是 27 台独立设施。
存档保存实例表与现有区块差量，读档验证二者一致，再重建格子索引；
索引不重复存盘。测试结构用既有区块外露面和一个整座方向标记渲染。
会话格式升级为 2，仍读格式 1 的无结构旧档，区块编码不变；
扩展 [006 快照范围](006-session-and-save.md#行为与验收)。
**当前会话格式已由 [009](009-sloped-belts.md#数据与实现约束)
升级为 3；此处实例表及无结构旧档兼容继续有效。**
实例 ID 在单个世界内从 1 递增分配，拆除不主动回收；加载后从现存最大
ID 的后一个开始，达到合法上限后回绕寻找未占用编号。ID 不表示方块类型，
不同测试结构共用类型编号，但拥有不同实例 ID；不同世界可使用相同 ID。
当前仅测试结构使用这套索引，地形不分配实例 ID，矿机、平传送带与箱子
仍以单格坐标维护物流状态。斜坡传送带应作为独立的单格物流功能，
不因外形倾斜而成为多方块结构；当前尚未实现，见
[物流未实现边界](003-basic-logistics.md#行为与边界)。
**“尚未实现”边界已由 [009 的独立单格斜坡](009-sloped-belts.md) 替代；
斜坡仍不使用结构实例索引。**

### 渲染与跨区块

测试结构主体复用 [VoxelWorldView](../../../scripts/world/voxel_world_view.gd)
的体素渲染。Godot 原生 `SurfaceTool` 将外露面生成 `ArrayMesh`，
每个显示区块使用一个 `MeshInstance3D` 和网格 `ShaderMaterial`；
同一网格生成三角碰撞形状，挂在 `StaticBody3D` 的 `CollisionShape3D` 上。
整座顶面方向标记另由 `MultiMeshInstance3D` 批量绘制，每实例一个标记。
预览也使用 `MultiMesh`，不创建碰撞。没有引入第三方体素渲染库，
也不为结构的 27 格分别创建场景节点。

数据区块每边 32 格，显示区块每边 8 格，二者职责独立。结构跨显示区块时，
各区块只生成自己的外露面，判断相邻面是否被遮挡时查询全局世界数据，
因此区块边界不额外生成内部面。顶点统一由世界格坐标计算，
网格线也使用世界坐标，不在区块边缘重新起算。
格子变化会标记所在显示区块与六个相邻格所属区块，
在玩家物理更新前重建待更新网格与碰撞；整座增删先更新全部占用和身份，
再发出变化信号。跨区块不会拆分实例，仍由
[VoxelWorldData](../../../scripts/core/voxel_world_data.gd) 的同一 ID 关联，
任意占用格都能查询和拆除整座。

参考原始开源实现（采用模式，不引入依赖或复制代码）：

- [Mindustry Tile.java](https://github.com/Anuken/Mindustry/blob/master/core/src/mindustry/world/Tile.java)：
  `setBlock` 让多格共用同一 `Building`，`preChanged` 清除全部关联格。
- [Luanti Minetest Game beds/api.lua](https://github.com/minetest/minetest_game/blob/master/mods/beds/api.lua)：
  多部分放置先检查目标，任一部分的 `on_destruct` 联动删除另一部分，
  用无递归的内部删除避免反复触发。
