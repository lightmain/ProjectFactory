# 003：基础物流

所属版本：prealpha-1。状态：当前规则，部分条款已按文中标识被后继规格替代。
维护类型：当前工厂规则、边界与验收。面向游戏开发与验证；
世界尺度见 [体素规格](001-voxel-foundation.md)，开发流程见 [AGENTS](../../../AGENTS.md)。

## 行为与边界

- 矿机、传送带、箱子均独占一个格子，沿用世界放置、破坏和边界限制。
  矿机与箱子是完整体素；传送带贴格子底部，高 0.08 米，宽深各一个格子。
  渲染、碰撞、格子射线、玩家占用检测、选中框与重生高度统一采用实体范围，
  射线可穿过传送带上方空隙；该空隙不能另放一个方块。
  射线从实体表面向内发射时保留命中面的法线，包括零距离命中；
  严格位于实体内部的起点没有入射面，不能据此相邻放置。
  快捷栏 4/5/6 为无限矿机/传送带/箱子建造工具，与 I 打开的玩家库存分开。
- 放置朝向取相机水平朝向的最近四向；R 顺时针旋转待放置方向，每次选择工具重置旋转。
  **本句已由 [004 的世界建造朝向](004-free-camera.md#行为与边界) 替代**；
  下列端口、连接与载矿转向规则继续有效。
  顶面箭头指向出口。矿机只有前方出口；箱子只有后方入口与前方出口。
  传送带后方和左右两侧均为入口，前方为唯一出口，支持侧面合流和转向连接。
  连接仅限同高度相邻格，上游出口必须朝向合法入口；不提供垂直运输或分流。
  传送带允许载矿转向；生效时物品随带面转向，保留身份、数量、进度和队列顺序。
  编辑瞬间不保证物品原世界坐标连续，正常运输仍不得倒退。
- 主场景导出 `mining_interval`（秒，默认 1）和 `mining_amount`（默认 1），
  放置矿机时复制配置，独立计时，每完成一个周期凭空生成一批铁矿。
  支持的最小周期为 0.001 秒；更小/非有限周期或非正数量停产。
  截止时间必须在浮点时钟上严格增长，否则停产，避免极端配置卡死补算。
  运行中修改导出配置只影响后续放置，已有矿机继续使用其独立配置。
  **本条主场景导出参数入口已由
  [005：游戏配置](005-game-config.md#配置来源与生效) 的共享 Resource 替代**；
  生产与快照规则保持不变。
- 矿机无入口；矿石先进入其输出缓存。无下游或堵塞时保留缓存，不丢矿。
  与箱子直接相连时，每批可输出已到期周期的全部库存；连接传送带时受运力限制。
- 传送带内部最多缓存两个矿石。移动与静止使用同一最小路径间距 0.25 米，
  速度为 1 米/秒，满载运力为每秒 4 个。到达出口后在下一逻辑批次交接；
  收到的矿石不能在同一批次再次交接。
  矿石沿带面以 1 米/秒前进，完整单格路径长 0.5 米；到达出口后才可转移。
  后方输入沿中线前进，侧面输入先到中心再转向出口，两段路径位置连续。
  堵塞时前矿停在出口，后矿保留至少半条路径的队列间距；
  入口仍被占用时不接受新矿，批量输入不会在同一入口叠放。
  同一入口路径跨格也约束队列间距，另一入口到来的矿石不会将等待矿石推回上游；
  下游释放时，紧贴的整队同时恢复恒速，
  不需要空位逐格向后传播。出口等待可能延长驻留时间，矿机周期保持不变。
  多路输入按后/左/右的端口顺序轮流分配空位，成功接受一个后移至下一端口；
  单个上游传送带每批最多输出一个。分配先预留接收空间，
  不因上游数量或遍历顺序超出容量，持续有效的各路输入不会被固定优先级饿死。
  轮到已有矿石的上游传送带时，为其保留到达入口的机会，
  错峰矿机生产不能抢占该机会；空的或方向不匹配的端口不会阻塞其他输入。
- 箱子储存铁矿，初版不设容量上限；出口连接合法下游时自动输出，
  向箱子可整批转移，向传送带每批最多输入一颗。没有下游时持续储存。
- 物流逻辑批次固定为 `h = 1/60` 秒，独立于设施数、矿机相位与 delta 分片。
  非边界上的生产、到达和入口腾空延至下一批次，单次量化延迟小于 `h`；
  此上限不包含堵塞、端口竞争或轮询保留造成的等待。
  箱子库存每批检查一次，矿机按整数周期号批量生产，不丢周期。
  批次先推进原矿石位置，再应用待生效连接、生产与轮询；
  根据交接开始时的矿石和库存计算转移，
  接收容量可使用本轮已确认输出腾出的空间，最后统一应用，
  避免遍历顺序决定结果或单批瞬移整条流水线。
  完全占满的闭合环保持原有矿石循环；外部输入等待实际空位，
  不因轮询选择了无法插入的外部矿石而卡死整环。
- 拆除设施删除该设施缓存与计时；其他设施不受影响。重新生成世界清空全部工厂状态。
  无存档、离线退出生产、矿石拾取或箱子交互面板；瞄准设施时 HUD 显示铁矿数量。
  **无存档的限制已由 [006](006-session-and-save.md#行为与验收) 替代；
  其余未实现范围继续有效。**

## 架构与执行顺序

### 建造预览与路径操作

- 选择矿机、传送带或箱子时，瞄准位置显示与实体尺寸及出口朝向一致的半透明模型。
  预览没有碰撞，不占用世界、不参与生产；无目标时隐藏未锁定部分。
  无效位置显示红色，按键失败额外短暂闪红并在屏幕下方提示原因。
- 矿机和箱子仍用右键单格放置；传送带第一次右键记录起点，第二次右键提交整条线路。
  第一次之后持续显示起点/锁定前缀到当前瞄准目标的路径；未提交前不修改世界或起点朝向。
  左键仅取消此次线路，不拆除目标。换工具、Esc 释放鼠标、失焦或重生取消线路；
  打开库存隐藏预览并暂停输入，关闭后恢复线路。
  **本条 Esc 释放鼠标已由 [006 的暂停规则](006-session-and-save.md#行为与验收) 替代；
  Esc 仍取消未提交线路。**
- C 将当前有效预览的所有路径锁定为前缀，可多次追加；后续寻路不能重写或穿过此前路径。
  每次成功锁定，在当时瞄准格的带面上方悬浮显示黄色圆圈；同一格不重复标记。
  移动目标或按键失败保留圆圈，库存关闭后恢复；提交、取消或换工具后清除。
  C 瞄准机器或已有传送带不能将它锁成中途点，因为这些实体只允许作为整条线路的端点。
- 寻路仅在起点所在高度沿四向格子进行，寻找最短路径，同长度优先少拐弯，
  拐弯计入终点已有带的固定出口转向；同等路径用待放置朝向确定稳定优先级。
  自动绕过地形、机器和已有带，忽略玩家实体；起点、终点及锁定前缀也允许与玩家重叠。
  不支持斜坡或垂直带；目标高度不同、无目标、越界、占用、无路或端口不合法均失败。
  所有失败按键都当作未发生，保留起点与锁定前缀；这取代此前高度不同取消操作的约定。
- 第一次点击矿机或箱子，使用其同格高度出口外相邻格，并限定首段从该出口离开；
  点击已有带使用该格作为起点，成功提交时才将其朝向改为线路第一段。
  第二次点击箱子，线路经入口外相邻格接入其固定后方入口；
  点击已有带可接入后/左/右入口，保留终点带朝向，不从其出口侧逆接。
  点击其他实体仍沿命中面取相邻空格。
- 中途已有带不复用、不旋转、不覆盖。无可绕行路径而诊断路径穿过已有带时，
  以红色显示诊断路径；右键或 C 提示“与现有传送带交叉”，起点和前缀不变。
  已锁定路径被新设施占用时也重新校验整段，不允许部分建造。
  所有格子及端口在提交前统一校验，成功一次创建整条线路，失败不创建任何格。
- 建造成功时，若新传送带实体与玩家重叠，立即将玩家向上抬至重叠带的最高带面，
  留出碰撞安全间距，保持水平位置并消除下落速度；没有重叠时不移动玩家。
  上方没有足够站立空间时拒绝此次提交并保留线路，不让玩家穿过天花板；
  抬升扫掠空间同时校验世界数据与物理空间，刚修改而尚未重建的碰撞也不能漏检。
  玩家站稳后不受传送带驱动；矿机与箱子继续禁止放入玩家实体。
- 转向在既有固定批次边界生效，入口方向随出口一起旋转；新连接若暂不满足已有矿石间距，
  暂不加入跨格位置约束，等待下游腾出入口，不通过回退矿石强制满足新约束。
  交接继续遵守入口半条路径的空位要求。编辑后恢复正常间距，物品不丢失、不重复。
- 预览使用共享网格/材质与 MultiMesh 批量绘制，Alpha Hash 抖动透明、无光照、无阴影；
  锁定圆圈使用共享不透明网格和独立 MultiMesh，不随无效预览变红，也没有碰撞。
  仅目标、方向、玩家占用或世界版本变化时重算路径和实例布局，避免每帧重新建网格或节点。
  Alpha Hash 的颗粒感是透明混合性能与排序问题的取舍，
  依据 [Godot 材质文档](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html#transparency)
  和 [MultiMesh 文档](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)。

## 最坏线性推进

本节面向实现者与审查者，说明固定批次、候选失效传播与函数图位置求解的界限。

### 目标与计算边界

- `N` 为当前存活设施数，带上矿石数不超过 `2N`，每个设施最多三个入口和一个出口。
  一个固定逻辑批次的物流求解和一次完整位置采样最坏 `O(N)`，
  辅助空间 `O(N)`。只有传送带增长、其他设施数保持同阶时，也可将 `N` 理解为带数。
- 同批多个生产/到达合并后只仲裁一次入口，与逐事件版本相比，
  合流选中顺序可能不同，但容量、守恒与持续输入公平性保持。
- 一个批次小于相邻矿石交接的最小间隔，每条带最多输出一个原有头矿、接收一个新矿。
  新接收矿石不能在同批再次输出。矿机按截止周期号批量计算增量，
  禁止按每个生产周期创建循环或事件对象。
- 对一次传入时长 `delta`，批次数 `K` 仅由时长与固定时钟余量决定，
  时间为 `O((K + 1)N)`；固定时长内相对于设施数仍为最坏线性。
  不将长时间补算伪称为与时长无关的 `O(N)`，不丢弃积压时间来掩盖开销。
- 热路径通过稠密整数索引和预计算邻接数组寻址，不将哈希表的均摊查找当作
  严格最坏常数。世界现有有限边界可使用格子直址表建立设施索引；
  直址表初始化属于世界初始化，其空间依赖世界格子数，单批不扫描整张表。
  设施活跃数组紧凑维护，不扫描历史删除设施留下的槽位。
  Godot 引擎自身的渲染、分配器与物理处理不属于物流算法的复杂度声明。

### 索引拓扑与交接依赖

拓扑保存出口目标索引、三个入口来源索引和当前轮询游标。
方块增删与方向修改维护局部设施状态，将图重建合并到下一逻辑批次；
同一格的连续编辑保留最终设施状态以及必要的缓存删除结果。
处理外部 `U` 次编辑请求本身需要 `O(U)`，一次合并求解为 `O(N + U)`，
禁止每个编辑请求各触发一次全网扫描。复杂度目标中的单批 `O(N)` 指物流求解，
不把外部输入读取成本隐含到设施数中。

1. 每个目标按现有端口规则产生至多一个候选，候选放在固定索引槽位中。
   保存每个设施的候选出边与入边，使用有效标记，不从数组中删除元素。
   满载合法闭环先沿唯一出口识别并预留环内前驱；外部供料等待实际空位。
2. 满载目标的入边依赖该目标的候选出边。没有出边的满载目标入边先标为失效，
   加入带读游标的队列；已存在的出边暂为有效。
3. 出边失效时，只访问其来源设施的那条依赖入边；若该来源满载，则将入边标为失效并入队。
   每个候选最多失效一次、入队一次，不重新扫描其他候选。
4. 剩余候选统一执行：先移出全部原有头矿，再追加接收矿石并更新成功端口游标。
   无失效源的闭环保持全部有效，不需要反复尝试循环交接。

候选数与依赖边数均为 `O(N)`，生成、闭环识别、失效传播和统一执行总计 `O(N)`。
队列仅推进读游标，不使用 `pop_front` 或 `remove_at` 移动未处理元素。

### 位置求解

矿石仍保存稳定身份、输入方向与归一化路径进度。
每个原有矿石只有一个需要跟随的前方矿石：
同格后矿跟随头矿；格内头矿按合法同入口路径跟随下游尾矿。
因此位置约束图的每个节点出度至多一，节点与边总数为 `O(N)`。

先计算每颗矿石本批期望进度 `d_i`：头矿取
`min(old_progress + delta / BELT_TRAVEL_TIME, 1)`，
后矿再取与前矿期望进度减去 `0.5` 的较小值。然后解：

```text
x_i ≤ d_i
x_i ≤ x_leader(i) + w_i

同格 w_i = -0.5；跨格 w_i = +0.5
```

采用显式栈和未访问/访问中/已完成三种状态沿唯一 leader 前进：

- 无 leader 或遇到已解节点时，从栈尾向前计算
  `x_i = min(d_i, x_leader + w_i)`，每个非环节点只求解一次。
- 遇到访问中节点时，截出闭环，先求解环，再沿栈返回解其他节点。
  环上总权重非负：每个跨格边贡献 `+0.5`，每格最多一条格内边贡献 `-0.5`。
  负总权重属于无可行间距的非法图，必须作为约束错误处理。
- 对含 `k` 个节点的环，按 leader 顺序复制为长度 `2k` 的索引序列，
  令 `P_j` 为边权前缀和。每个环节点的解为：

```text
x_i = min(d_(j mod k) + P_j, j ∈ [i, i+k-1]) - P_i
```

  环总权重非负，最优上限不必绕环超过一圈。
  用单调双端队列求长度为 `k` 的滑动窗口最小值，每项最多入队一次、出队一次，
  零权重的紧密满载环和含空隙的正权重环均在 `O(k)` 内解出。

选择上述约束的逐分量最大可行解，即不违约前提下每颗矿石尽可能前进，
不是任意一个满足间距但可能让整队少移动的解。
原状态可行时解必须满足 `x_i >= old_progress_i`，不允许为修复间距让矿石倒退。
载矿转向属于主动编辑，在批次边界整体旋转该格路径，保留队列数据。
新连接不通过回退已有矿石修复不可行间距；暂不满足间距的跨格连接等待入口腾空。
放置空带与拆除只新增空路径或删除约束。

该方法直接得到整批约束的稳定解，取消 `while changed` 全网收敛循环。
求解以同一批期望位置为输入；堵塞解除后，各矿石同批前进，保持原路径间距。
不同入口路径的等待矿石仍不受另一入口新矿石的回推。

### 时钟、采样与接口

- 使用整数批次号计算边界时间，避免逐次浮点相加；`advance(delta)` 的拆分不能重置时钟网格。
  边界内未满一批的时间保留为余量，数量按已结算批次读取，位置可在副本上采样该余量。
- 拓扑修改也不重置固定时钟网格。拆除设施的缓存立即删除，新矿机保存实际放置时刻；
  连接与方向变化在下一批次统一参与交接，新增连接的生效延迟小于一个批次。
  恰在已结算边界上的一组编辑，在下一次正时间推进起点额外统一结算一次，
  每个边界最多一次；此后同边界再发生的编辑延至下一边界。
  补充结算不重新生产，已在该边界输出的设施不得再次输出，
  本边界新接收的库存也不得在补充结算中再次输出。
  查询与零时间推进不能触发结算，也不能消耗这次编辑结算机会。
  保持该时刻接通后的同步恢复；不得按每格编辑分别结算全网。
  待应用的连接与方向同时在正式或上述补充结算中进入运动约束图；
  副本采样继续使用已经生效的图，不提前启用尚未结算的连接。
  生产周期继续由原放置时间与整数周期号决定，编辑不能将原有截止时间不断推迟。
- 一次采样最多执行一次线性位置求解。结果按后台版本和采样时刻缓存；
  公开接口返回独立副本，不能把缓存对象交给调用方修改。
  内部缓存行随设施索引局部增删并同步压紧；删除时即释放该行最多两个矿石副本，
  下次采样不集中清理历史设施行，更新时仅清理当前行的有界副本。
  `sample_belts()` 返回每个存活设施一行的有序 `Array[LogisticsOreQueue]`，
  其中包含格子、已生效朝向与矿石副本，不使用哈希表建立快照。
  单格读取只复制该格最多两个矿石，不因遍历各格重复求解全网。
- 视图读取同一份采样结果或已求解的位置插值数据，按稳定身份复用节点。
  插值沿实际路径处理跨格和拐角；不重算物流交接、生产或依赖，
  不调用全网收敛算法，不预测尚未结算的输入轮询。
  隐藏、剔除与重建行为保持既有边界。

### 复杂度验收

`work_stats()` 与两个求解器的 `work` 统计设施、矿石、候选边与队列访问；
测试断言固定线性上限，不以耗时比值证明复杂度。固定数量的数组初始化和副本复制
同样只扫描 `O(N)` 项；每条带的队列操作最多移动两个元素。
固定 delta 内批次数不得随矿机相位或设施数增长。
小规模独立松弛参考验证最大可行解，长链与环检查访问上限；
游戏测试继续验证容量、守恒、公平、同步恢复、时钟分片与视图生命周期。
