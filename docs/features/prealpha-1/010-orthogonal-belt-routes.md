# 010：直角贴地传送带线路

所属版本：prealpha-1。状态：当前规则。本规格替代
[003 的自动寻路与交叉诊断](003-basic-logistics.md#建造预览与路径操作)及
[平面寻路模块](003-basic-logistics.md#平面寻路的模块边界)，并替代
[004 的激活线路 R 及寻路优先级](004-free-camera.md#行为与边界)、
[009 的自动线路仅平带限制](009-sloped-belts.md#行为与验收)。
继承 [009 的单格斜坡几何与物流端口](009-sloped-belts.md#行为与验收)；
不恢复原先撤回的三维搜索方案。面向线路建造开发、玩家操作与验收。

## 目标与操作

- 取消 BFS 和地图绕障搜索。每段未锁定线路的俯视投影只沿两个水平轴，
  每轴单调移动：先南北（Z）后东西（X），或先东西后南北。
  两轴均有位移时只有一个转角；单轴位移时是一条直线。
  起终点投影相同时只保留一个格，不用垂直堆叠连接高度差。
- 默认先南北后东西。线路激活期间 R 切换顺序并立即刷新预览，
  不改变设施建造朝向；线路未激活和其他建造工具的 R 仍旋转待放置设施。
  HUD 显示当前顺序。新线路恢复默认顺序；取消、换工具和会话重置清除线路。
- 首次右键选择起点，第二次提交整条线路，C 锁定此前全部线路；
  后续每个新段分别遵循上述投影规则。R 不改写已锁定前缀。
  复用原有取消、库存、暂停、失焦、失败闪红、黄色锁定圈与预览缓存。

## 高度、转角与地面

- 线路包含平带和 45° 上下坡。各格沿确定的投影排列，
  以入口和出口的整数格高度表示带面；每段坡道的出口比入口高或低一格，
  相邻两格的出口与入口必须等高。
  斜坡只能直行，转角必须是平带；不在坡道内部转向。
- 新线路的起点入口高度固定为选中空格的底部高度，已有起点设施保留原类型、
  高度及端口约束。新空起点可在需要时成为直行上坡；
  下坡可将基准格放到选中入口下方一格，但该格及坡道带缘必须实际空闲。
  末端为空格时，底部及出口高度固定为选中终点空格的高度，
  可以是平带或直行下坡；下坡入口比该高度高一格，末格计入下降容量。
  本次不增加末格上坡。已有箱子/平带终点保留原设施及真实端口，
  不限制其前一格只能是平带。未延伸的单格线路仍只能是平带。
- 起点矿机/箱子必须沿固定出口离开，终点箱子必须沿固定后方入口接入；
  已有平带端点继续沿用 003 的旋转与侧入规则。
  轴顺序与端口冲突时标红，由玩家按 R 切换或另选端点，
  不自动增加额外横向折线。
  已有斜坡不作为可重定向的线路端点，仍可使用 8/9 单段建造。
- 中间格读取所在 X/Z 列中最高非空气实体，把地形、机器、多方块结构、
  已有平带及斜坡都视为需要从上方通过的地面；不覆盖、旋转或拆除它们。
  普通方块和平带上方的第一个空格作为最低基准格；
  斜坡高端带缘越过上方格界，再留一个整数格，确保新平带不与带缘相交。
  空列采用世界下界。选中端点保持选中的高度，并校验实际实体净空。
  已锁定而未提交的前缀也计入沿途障碍高度，不能被新段改写或实体穿过。
- 在地面最低高度之上选择逐点最低的可连接带面。
  为跨越较高地面，允许前面地面较低处提前上坡；
  为下降至较低地面，允许保持高度直到有足够直行坡道。
  不要求每格都有实体支撑，坡道和必要的桥段可在空中延续。
- 转角处若需要升降，将所需高度变化传播到较低的直线格：
  上坡向前面的直线格提前，下坡在可用直线格完成（包括直行空末格），
  转角本身保持水平。
  若直线格已全部用于坡道，仍无法满足地面、转角和固定端点高度，
  则整条预览标红，C 和提交均失败。
  端点高度差大于可用坡道格数量时同样失败，不扩大路线、不搜索其他路径。
- 越界、端口不合法、实际斜坡相交、新占用或无法接通高度均复用
  已有不合法预览与闪红处理；提示具体原因。
  失败保留起点、前缀和目标预览，不创建任何设施。
- C 锁定下坡末格后，整个坡道及其方向保持不变。
  下一段从坡道出口前方的相邻水平格、以出口高度开始，不从坡道本身重算。
  新段第一格若继续同方向可升降，若改变方向必须是平带，
  不在已锁定坡道内部转向。R 只切换这个新段的轴顺序。
  同一终点上的刷新、再次 C 或提交保留原前缀，不凭空增加格子。
  出口前方被占用、越界或新段无法连接时标红并保留前缀。

## 计算与模块边界

纯 `OrthogonalRoute` 只处理格子数组、最低高度和每格是否可升降，
不依赖 `VoxelWorldData`、方块枚举、物流端口、节点、Input 或物理空间。
`BeltPlacement` 适配地面、端口、锁定前缀与单格类型，
继续负责预览和提交；视图只接收逐格类型、坐标和方向。

高度采用有限路线上的贪心传播：

1. 创建两个轴的投影格序列，长度为 `|Δx| + |Δz| + 1`。
2. 读取每格最低基准高度 `floor[i]`。斜坡最低端也必须不低于该高度，
   因此内部共享端口最低高度为相邻两格地面高度的较大者。
3. 在格 `i` 到下一格的连接上，允许坡道则高度变化上限为 1，
   转角、固定起点设施及锁定接点则上限为 0。
   空末格允许下降时，增加一个只表达末格出口的虚拟端口：
   其最低高度与选中终点基准相同，末格容量为 1；
   末格入口最低高度不低于该基准，所以不会生成末格上坡。
   虚拟端口不创建额外格子。已有设施终点容量为零。
   已有平带前缀最后一格继续作为平直接点，包括仅 C 锁定起点一格的情况；
   已锁定下坡前缀则全部保留，从出口前方另起投影及高度数组。
4. 将固定起终高度加入最低高度约束，正向与反向各传播一次：
   下一端口至少是当前高度减去该格的变化上限，反向同理。
   结果是满足所有地面和坡度约束的逐点最低高度。
5. 若结果抬高固定起终高度，说明直线格不足，判为不合法。
   合法时由相邻端口高差编码平带/上坡/下坡，
   以两个端口较低的高度保存斜坡基准格，再进行实际实体及世界边界校验。

起点下方的局部净空决定首格最低基准：允许下坡时为选中入口高度减一，
否则为选中入口高度；固定入口高度仍保持不变。
已有设施和 C 锁定接点都不使用该下降余量。

不枚举路线之外的水平格，不保留搜索队列、入向状态图或诊断第二遍搜索。
投影和高度传播为 O(L)，地面查询只扫描这 L 列的有限世界高度 H，
为 O(L×H)；附加内存为 O(L)，不随整个世界平面面积增长。
仍使用目标、模式、方向、世界修改及相关占用变化驱动预览刷新。

提交前统一校验逐格实际类型、端口、原有端点和前缀；
通过后创建全部新格。预览中的坡道类型必须与提交结果一致。
玩家重叠仍按原规则抬升并校验头顶空间；自由镜头按实际斜坡实体拒绝相交，
不能继续用平带薄盒代替坡道。
抬升净空同时计入同批待建的上层带段；初始与玩家重叠的带面用于确定抬升高度，
不相交而位于抬升头顶扫掠范围的新段则使提交失败。
运输、存档格式和斜坡几何不变。
