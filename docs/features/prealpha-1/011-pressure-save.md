# 011：大世界存档与压力测试

所属版本：prealpha-1。状态：当前规则。面向开发、存档编辑与性能验收。
继承 [006](006-session-and-save.md)、[009](009-sloped-belts.md) 的规则。
本规格变更 006 的固定世界尺寸、会话文件／区块上限和 009 的当前格式版本；
默认新世界、区块差量记录、斜坡几何与端口规则继续继承。

- 格式 4 保存每个世界的边界与地下层数，继续读取格式 1／2／3；默认新游戏不变。
  尺寸各轴最多 128 格，坐标绝对值不超过 256；地下 1～4 层，
  最底层为不可破坏基岩。数据区块仍为 32³，最多 64 个。
- 物流机器与矿石采用固定长度二进制行，保持整数身份、浮点进度、生产相位、
  已结算／待结算拓扑。未压缩会话上限 384 MiB；校验和、压缩、原子写入不变。
  非法尺寸、编码、矿石间距或身份不得修改活动世界。
- 提供可复现的命令行生成／运行工具；编辑矿石通过真实队列数据并经快照验证。
  产物使用独立存档目录，不覆盖玩家存档。
  手工试玩的独立目录限制已由
  [prealpha-2 普通列表入口](../prealpha-2/001-logistics-performance.md#压力存档的普通列表入口)
  替代；性能采集的独立目录规则继续有效。
- 压力存档总尺寸 128×128×64 格，一层地板；地板以上尽量填满一条三维蛇形
  传送带，4 个矿机汇入起点，终点为箱子；保留玩家站位及斜坡上方净空。
  每条带预填两颗矿石。验收唯一访问、邻接、方向、终点及实际文件重读。
- 运行实际场景，按墙钟时间统计完成的逻辑 tick 和渲染帧；
  报告加载时间、测量窗口、数量、视角与运行限制，结束停止游戏。

## 编码与范围

`minimum`／`maximum` 使用半开格坐标，`floor_depth` 为地下层数且
`minimum.y == -floor_depth`，地表仍为 y=0。边界参与世界生成、差量索引、
物流稠密索引、镜头碰撞与线路规划；每个数据区块的合法坐标按该世界尺寸计算。
格式 1／2／3 必须使用原始边界和原始机器字典数组，不能夹带大世界或二进制机器行。
格式 4 仍接受经过同样校验的机器字典数组，实际菜单保存使用紧凑编码。

物流字典的 `packed == 1` 表示 `machines: PackedByteArray`、
`outgoing: PackedInt32Array` 和 `inputs: PackedInt32Array`；
时钟、next ID、生产参数与 dirty 字段保持独立。机器每行 136 字节，小端：

| 字节偏移 | 内容 |
| --- | --- |
| 0～11 | 格坐标，三个 int32 |
| 12～15 | 方块、请求方向、已结算方向、输入轮询，四个 uint8 |
| 16、24、32 | 数量、可交接数量、最近输出 tick，int64 |
| 40、48、56 | 生产间隔 float64、产量 int64、下次生产时刻 float64 |
| 64、72 | 放置时刻 float64、已生产周期 int64 |
| 80～87 | 矿石数量 uint8（0～2），其余为保留字节 |
| 88～111、112～135 | 每颗矿石的 ID int64、入向 uint8、七个保留字节、进度 float64 |

方向按 `FORWARD、RIGHT、BACK、LEFT` 编码为 0～3。
写端将保留字节归零，读端忽略保留字节；合法性由机器、队列、拓扑和快照共同校验。
这是有界大世界支持，仍同步构建全世界网格与碰撞、全工厂模拟；
没有后台读档、异步保存或远处逻辑降频。压力场景是否可交互以实际测量为准。

## 工具

在仓库目录运行，输出路径须为独立目录：
手工试玩的目录限制已由
[prealpha-2 普通列表入口](../prealpha-2/001-logistics-performance.md#压力存档的普通列表入口)
替代；以下命令保留为独立基准用法。

```bash
godot --headless --path . --log-file /tmp/pressure_generate.log \
  -s res://scripts/pressure_test.gd -- generate "$PWD/build/pressure_128" 128 64
godot --path . --log-file /tmp/pressure_run.log \
  -s res://scripts/pressure_test.gd -- run "$PWD/build/pressure_128" 15
```

生成目录使用正常多存档索引及原子快照，生成同名档时拒绝覆盖；
`generation.json` 记录数量，运行后产生 `performance.json` 与 `run.png`。
运行必须使用图形进程；测量排除读档、网格构建和前两个预热帧，
随后覆盖至少指定墙钟秒数，实际窗口可能因长帧超过该值。
逻辑 FPS 为完成 tick 数／墙钟秒，渲染 FPS 为引擎完成绘制帧数／墙钟秒，
在绘制完成信号中采样，另记录该信号回调数。
保持默认第一人称镜头、渲染距离与物理频率，停止窗口会停止测量。
输出存档目录可作为 `SaveGameStore.directory` 使用；工具不改玩家默认存档目录。

`PressureSaveBuilder.build(size, height)` 创建纯数据快照；
`LogisticsData.prefill_belts()` 仅接受时钟为零且无矿石的工厂，
按已结算输入方向赋予唯一 ID 和进度 1／0.5，更新真实数量与 next ID。
进一步编辑可读取 `save_state()` 的机器／矿石行，再用 `restore_state()` 原子验证；
大档使用 `LogisticsPacked` 的固定行读写，写盘前仍经完整快照验证。
禁止修改 `belt_ores()` 的返回副本来冒充内容物更新。

`PressureSaveBuilder.route_certificate(snapshot)` 在线性时间内检查已结算出口的
相邻坐标与高低端口、四个矿机均接入带、唯一箱子、带链唯一头部、每条带至多一个
带前驱，并从头遍历到箱子且恰好访问全部带。生成及文件重读后均执行，
因此完整百万设施档也经过连续性验收；未结算、断链、合并的多条带或孤立环会失败。
仅矿机输入允许汇合，四个矿机进入起点的短带链。
