# 003：基础物流

维护类型：当前工厂规则、边界与验收。面向游戏开发与验证；
世界尺度见 [体素规格](001-voxel-foundation.md)，开发流程见 [AGENTS](../../AGENTS.md)。

## 行为与边界

- 矿机、传送带、箱子均独占一个格子，沿用世界放置、破坏和边界限制。
  矿机与箱子是完整体素；传送带贴格子底部，高 0.08 米，宽深各一个格子。
  渲染、碰撞、格子射线、玩家占用检测、选中框与重生高度统一采用实体范围，
  射线可穿过传送带上方空隙；该空隙不能另放一个方块。
  射线从实体表面向内发射时保留命中面的法线，包括零距离命中；
  严格位于实体内部的起点没有入射面，不能据此相邻放置。
  快捷栏 4/5/6 为无限矿机/传送带/箱子建造工具，与 I 打开的玩家库存分开。
- 放置朝向取相机水平朝向的最近四向；R 顺时针旋转待放置方向，每次选择工具重置旋转。
  顶面箭头指向出口。矿机只有前方出口；箱子只有后方入口与前方出口。
  传送带后方和左右两侧均为入口，前方为唯一出口，支持侧面合流和转向连接。
  连接仅限同高度相邻格，上游出口必须朝向合法入口；不提供垂直运输或分流。
- 主场景导出 `mining_interval`（秒，默认 1）和 `mining_amount`（默认 1），
  放置矿机时复制配置，独立计时，每完成一个周期凭空生成一批铁矿。
  支持的最小周期为 0.001 秒；更小/非有限周期或非正数量停产。
  截止时间必须在浮点时钟上严格增长，否则停产，避免极端配置卡死补算。
  运行中修改导出配置只影响后续放置，已有矿机继续使用其独立配置。
- 矿机无入口；矿石先进入其输出缓存。无下游或堵塞时保留缓存，不丢矿。
  与箱子直接相连时，每个生产周期可输出整批；连接传送带时受运力限制。
- 传送带运力为每秒 2 个：全局每 0.5 秒最多向下游移动一个矿石，
  内部最多缓存两个矿石。收到的矿石不能在同一物流事件继续移动。
  两格缓存让稳定连续流水线可以每个运输周期同时出入一个。
  多路输入按后/左/右的端口顺序轮流分配空位，成功接受一个后移至下一端口；
  单个上游传送带仍每个运输事件最多输出一个。分配先预留接收空间，
  不因上游数量或遍历顺序超出容量，持续有效的各路输入不会被固定优先级饿死。
- 箱子储存铁矿，初版不设容量上限；出口连接合法下游时自动输出，
  向箱子可整批转移，向传送带最多填充其空余缓存。没有下游时持续储存。
- 物流事件包括矿机生产到期与传送带运输到期。事件按时间顺序处理；
  同时到期先生产，再按事件开始时的数量与接收空间计算转移，最后统一应用，
  避免遍历顺序决定结果或单次事件瞬移整条流水线。
- 拆除设施删除该设施缓存与计时；其他设施不受影响。重新生成世界清空全部工厂状态。
  无存档、离线退出生产、矿石拾取或箱子交互面板；瞄准设施时 HUD 显示铁矿数量。

## 架构与执行顺序

- `scripts/core/logistics_data.gd` 与 `logistics_machine.gd` 保存权威工厂状态，
  只依赖纯世界数据和传入的时间，不依赖节点、相机、Input、可见性或物理空间。
- `FactoryGame` 明确注入世界与矿机配置，在 `_physics_process` 推进全部工厂。
  视图隐藏、销毁或区块不可见均不停止生产；大 delta 按事件补算，不丢周期。
- 世界修改信号同步工厂增删；设施方向由纯规则接口设置。
  地形网格依实体范围提供网格与碰撞，只剔除被邻块完全覆盖的面；
  独立 `LogisticsView` 根据工厂快照展示方向、入口和矿石。
  矿石是无碰撞的表现对象，不参与物流结算。
- 时间累计使用补偿求和，生产截止时间由放置时间与整数周期号计算，
  避免长时间反复加生产间隔造成丢批次。当前有限世界按事件线性补算，
  不限制补算次数；不支持超出浮点时钟表示能力的运行时长。
- 使用现有 Godot/GdUnit4 与显式类型，第三方插件与 Autoload 边界见 AGENTS。

实施顺序：先验证生产/端口/吞吐/堵塞/时间分片/删除规则，再接入快捷栏与主场景，
最后加入方向、矿石表现和 HUD，运行完整验证、编辑器截图与独立审查。
