# 001：完整 Rust 数据后端重构

所属版本：**alpha-2.0**。状态：**待实施方案；尚未接入游戏，不替代当前规则**。
日期：2026-11-25。读者：接手重构的开发者、测试人员与审查者。
本版本将世界数据、工厂模拟、数据查询、网格数据生成及完整存读档迁移到 Rust；
Godot 保留引擎对象、玩家物理、输入、界面与渲染提交。
通信与存档的权威条款在 [002](002-backend-protocol-and-persistence.md)，
实施顺序与交接入口在 [003](003-migration-plan.md)。
本次独立审查、修订和文档验证范围见 [计划审查记录](../../reviews/2026-11-25-alpha-2-plan.md)。

## 需求、判断与边界

用户需求是减少 Godot 承担的大量纯数据工作，尤其加载和保存，并形成可由新对话实施的完整计划。
选用 Rust 是本版本的明确技术方向；具体模块边界、线程数量和优化算法仍须由实际成本验证。
本计划不将“所有 GDScript 都慢”“Godot C# 不成熟”或“人类指令越多 AI 越差”
作为已证实前提。语言之间的性能取决于数据布局、算法、分配、调用次数与引擎工作量；
既有运输优化也说明快速 Rust tick 并不能自动解决宿主对象、加载与 GPU 提交成本。

因此迁移的核心是**单份权威世界状态、批量局部通信和独立持久化**，
而不只是把原脚本逐行翻译成 Rust。
玩家运动仍依赖 Godot 物理世界，渲染仍依赖 Godot 的资源和 GPU；
Rust 提供这些系统所需的数据，不另造物理引擎或渲染器。

本版本继承有限世界、工具、设备、碰撞、视角和菜单的用户行为。
不扩展无限世界、联网、远处逻辑降频、新设备或配方，不引入外部常驻服务，
不重写 RustConveyor 的运输队列算法，不以改变玩法或减小测量负载换取性能。
按可运行切片实施，每步先明确验收并完成 RED／GREEN，再进入下一步。

未来只有一个游戏进程。Godot 通过 GDExtension 调用同进程 Rust 动态库；
库内的 RustConveyor 是运输模块，并不是 Godot 各部分之间的中转服务器。
Godot 的玩家、相机和 UI 可以直接交互；修改世界和工厂时才经后端命令边界。

```text
玩家输入、相机、菜单 ──直接交互── Godot 场景与表现
          │                          ↑
          │ 小命令／视角／玩家姿态    │ 局部网格、碰撞、实例批次、查询结果
          ↓                          │
             factory_godot：薄 GDExtension 适配
                              │
             factory_core：唯一权威世界与完整工厂
               ├─ 世界、占用、查询、网格数据
               ├─ 拓扑、生产、库存、运输规则
               │                   └─ RustConveyor（连续运输）
               └─ 快照、格式、旧档迁移、磁盘目录
```

这个图表示目标状态。当前 Godot 规则仍运行，静态实验也仍独立；
只有 [003 的切换验收](003-migration-plan.md#最终切换与交付)通过后才能声明上述职责已迁移。

## 职责清单

### Rust 的权威数据与计算

| 工作 | Rust 负责内容 | Godot 接收内容 |
| --- | --- | --- |
| 世界 | 尺寸、地形基线、区块差量、方块、结构定义与实例、占用索引 | 感兴趣区块的表面／碰撞数组、局部目标元数据 |
| 建造与拆除 | 范围、基岩、重叠、朝向、整座拆除、线路／坡道规划、事务提交 | 预览结果、拒绝原因、提交确认、受影响显示 |
| 物流 | 设备、端口、拓扑、逻辑段、接缝、轮询、生产相位、库存、物品身份与运输 | 有界统计、被查看设备详情、可见物品批次 |
| 库存 | 玩家与设备库存数据、合法转移；继承当前空玩家库存与无限工具规则 | 当前打开页面与数量；工具选择仍在 Godot |
| 空间查询 | 格子射线、建造路径、逻辑占用、相机范围候选、距离与高度筛选 | 有界命中、预览路径、渲染订阅数据 |
| 表现数据 | 面剔除、方向标记属性、矿石三维位置、实例矩阵与 AABB、碰撞三角形 | PackedArray 形式的批次，不是逐设施脚本对象 |
| 存读档 | 世界身份、命名／自动档目录、版本兼容、所有载荷、校验、压缩、原子提交、恢复 | 条目页、进度、成功／失败与新世界交接描述 |
| 数据工具 | 压力生成、完整工厂无头重放、存档检查、导入和性能报告 | Godot 无头／图形宿主可调用同一协议 |

Rust 不根据 GPU 可见性停止模拟。镜头看不到的矿机、传送带、箱子仍按当前规则运行；
可见范围只限制表现和查询数据量。
建造事务必须同时提交方块、结构实例、机器与拓扑，失败不留下半条线路或孤立占用。
拓扑重建与存档校验也不得依赖是否已经生成画面。

### Godot 的引擎职责

Godot 保留输入事件、焦点、工具选择、相机、玩家 `CharacterBody3D` 运动与碰撞、
重生表现、UI 排版和交互、材质／shader、灯光、音效及 GPU 绘制。
世界／设备的节点只是局部表现，不再持有完整规则。
主场景显式注入后端适配对象；不增加承载游戏规则的 Autoload。

玩家位置由 Godot 物理运动决定。Rust 接收带帧序号的少量姿态数据，
用于建造距离、当前玩家状态和一致保存；不能声称 Rust 已接管玩家物理。
Rust 计算合法出生／重生候选及需要的碰撞范围，Godot 在附近碰撞就绪后完成实体移动。
第一人称与自由镜头的物理阻挡依然通过 Godot 物理查询。
建造命中的逻辑格子和最终合法性由 Rust 判定，避免场景未挂载导致漏判占用。
放带抬升玩家时 Rust 检查权威净空／拟建几何，Godot 确认物理可移动并执行抬升；
异步期间绑定姿态和短运动屏障，具体事务见 [002](002-backend-protocol-and-persistence.md#建造与玩家物理协作)。

允许 Godot 保留当前视图、当前预览、最近的设备详情及渲染批次映射。
禁止常态持有完整机器数组、全世界矿石列表、完整拓扑或另一份存档世界。
UI 的临时未确认状态须有标识；收到提交确认后才能把设施当成已建成。

| --- | --- | --- |

若离散规则移植无法满足预算，先记录差异与测量，形成显式范围调整；
不得省略兼容测试、在 UI 隐藏规则变化或自动改用连续规则。
本计划不承诺两套规则可在同一游戏中途无损互换。

## 模块、依赖与数据布局

拟在 ProjectFactory 新建 `rust/` Cargo workspace：

| crate | 责任 | 依赖方向 |
| --- | --- | --- |
| `factory_core` | `world`、`entities`、`topology`、`production`、`inventory`、`transport`、`queries`、`meshing`、`snapshot`、`legacy`、`storage`、`runtime` | Rust 标准库、最少格式依赖、RustConveyor 公共 API；不依赖 Godot |
| `factory_godot` | 类型转换、生命周期、请求提交、结果领取、PackedArray 构造 | `factory_core`、godot-rust；不重复规则 |
| `factory_cli` | 生成、检查、重放、导入、完整后端测量 | `factory_core`；没有 Godot |

RustConveyor 继续是独立仓库，游戏只依赖 `rust_conveyor::api`，不引用队列内部。
连续运输的设备适配、世界到路径几何和工厂成交账目属于 `factory_core`。
固定时间步、米制长度和最多三个入／出端口按其当前公共契约验证；
游戏不凭假设把不受支持的组合传给包。
局部拆带优先复用已有路径拆分、连接、删除能力；整条受影响连通分量的工作量也须计量，
不能把“局部入口”宣传成恒定成本。离散规则与连续规则共用工厂接口，内部存储可以不同。

初版依赖候选为 godot-rust（参考已有桥接所锁版本）、SHA-256 和 DEFLATE 实现；
具体版本、许可证、Godot 4.7.2 支持与平台构建在 M01 锁定。
RustConveyor 未发布注册表时，用显式源码位置构建，并记录源码指纹和生成库哈希；
不提交本机绝对路径，不从当前源码猜测旧二进制的来源。
不为初版引入通用 ECS、跨进程 RPC、复杂任务框架或新的渲染引擎。

数据采用紧凑、显式类型：

- 有界世界继续以世界 `minimum` 为数据区块索引原点，数据区块为 32³，
  局部索引为 `(y & 31) << 10 | (z & 31) << 5 | (x & 31)`。
  基线地形可推导，已编辑区块按需分配；格式与缓存分别管理。
- 表现区块初始继续为 8³；它与数据区块不是同一概念。
  调整粒度须核对 draw call、提交延迟、邻面更新与内存，不同步改变存档索引。
- 机器采用紧凑表和稳定逻辑身份，坐标到机器／结构使用明确索引；
  结构定义与可变实例分离。移除后不得让旧句柄指向新设备。
- 物品保持整数身份、种类、规则集所需的进度／间距及来源方向。
  计数、下一身份、生产相位、轮询与待结算边都属于权威状态。
- 方向、方块种类与规则集用校验后的枚举。跨格式 ID 使用明确整数宽度，
  保存精度继承现有规则；渲染矩阵可以转 `float32`，不反向覆盖模拟的精度。

## 线程与生命周期

选同进程 GDExtension，是为了复用当前原生接入和批量数组，避免额外服务、
进程管理与序列化完整世界。不是因为跨进程实现绝对不可行。
先用同步小世界证明规则和协议，再增加以下有界后台执行模型：

1. Godot 主线程拥有场景和引擎资源，薄桥接只在此线程接收／返回 Godot 类型。
2. 一个 Rust 世界工作线程拥有可变世界、工厂和运输实例；所有命令与 tick 串行排序。
   RustConveyor 的 `Network` 当前不是 `Send`／`Sync`，必须在此线程内创建和使用，
   不能先在主线程创建再搬移，不以 `unsafe impl Send` 规避。
3. 一个 I/O 工作线程只接收不可变 Rust 快照或字节，进行压缩、磁盘写入和文件读取。
   它不访问 `Network`、Godot `Object` 或场景；文件解码后的纯数据交给世界线程验证／建实例。
4. 初版网格 CPU 生成由世界线程按预算分块处理；确有阻塞再增加基于不可变区块的网格任务。
   工作者数、积压及内存上限须先验收，不能直接启用任意多线程。

同步验证阶段尚无后台世界线程，实例始终在当前执行线程内创建和使用。
M06 切换到后台时停止同步测试会话，在新工作线程按同一夹具重新创建实例并验证等价，
不搬移同步阶段的活 `Network`。本切片不迁移运行现场；
后续需要跨会话恢复时使用 M08 已验证的不可变检查点，在拥有者线程内重新恢复。

独占世界线程消除跨线程修改同一设施的锁争用，但长时间快照或恢复仍会占用它；
必须报告最长阻塞，后台不等于零暂停。时钟、积压和队列规则见 [002](002-backend-protocol-and-persistence.md#时钟与暂停)。
退出时停止接受新请求、完成或取消当前作业、通知停止并回收线程；
原生库不可在仍有工作线程时卸载。线程异常向宿主报告故障并暂停操作，
不返回伪造的空世界。完整退出与超时诊断列入集成测试。

## 表现流送与引擎成本

Rust 根据相机订阅生成局部静态网格和动态实例批次，
同时按玩家周围独立兴趣范围准备碰撞；自由镜头不能移走玩家脚下所需的碰撞。
网格、碰撞和方向数据的修订包括邻区边界，边界编辑要使两侧相关表现失效。
Godot 主线程创建 `ArrayMesh`／`Shape3D`、节点及 MultiMesh 并提交 GPU；
引擎碰撞构造和 GPU 上传的剩余成本单独计量，不能计为“Rust 已全部消除”。

普通帧不得全世界扫描或给每个设施建脚本对象。
移动物品的输出按可见数量 K 打包，Godot 每批调用 `MultiMesh.set_buffer`。
所有可见物品都运动时仍需 O(K) 数据更新；所谓增量是局部范围与静态修订增量，
不是宣称运动位置可以只发送少数变化。缓冲、身份映射、容量与 AABB 有明确上限。

碰撞流送未就绪时不得允许玩家进入空洞：保留现有站脚与邻近碰撞，
必要时限制移动／暂不完成重生或载入交接。首个可操作帧须满足玩家附近碰撞及视图就绪；
自由镜头的平移、缩放和绕点旋转同样按扫掠范围／修订验证，
延迟安装期间由 Rust 权威数据扫掠限制运动，不能只依赖旧碰撞。
远处画面可继续流送，但必须分别报告“首次可操作”和“全部请求场景挂载”。

## 验收与候选性能预算

正确性先于速度。完整无头工厂必须独立运行矿机→带→箱子，
验证生产、转移、消费、总量守恒、身份唯一、堵塞、合流、坡道、环路、编辑、
暂停、保存／重启后继续演化以及旧档拒绝／接受。
Godot 集成必须核对真实引擎网格、碰撞、世界变换、实例缓冲、UI 和生命周期。
不是只运行静态体素实验或只测 RustConveyor tick。

下列是**待 M00 校准的工程预算，尚无 alpha-2.0 实测达标证据**。
M00 用当前版本重新建立完整基线，可据同负载样本调整候选预算并记录理由；
不得在失败后无证据降线或把未测数据补零。

| 指标 | 初始预算 | 口径 |
| --- | --- | --- |
| 完整百万工厂后端加载 | ≤ 5 s | 实际文件读取、解压、全量校验、规则实例恢复与可开始模拟；不含 Godot 挂载 |
| 完整百万工厂保存 | ≤ 3 s | 一致快照开始到文件验证及持久提交完成；含 flush／同步，不只压缩 |
| 百万工厂首次可操作 | ≤ 8 s | 独立进程发起载入到附近视图／碰撞就绪且输入可操作；全场景挂载另报 |
| 后端常规 tick | p95 ≤ 4 ms | 60 Hz，实际生产／消费及指定规模；最慢 tick、积压另报 |
| Godot 桥接与资源提交 CPU | p95 ≤ 2 ms／帧 | 主线程转换、缓存更新及引擎提交，注明是否含引擎内部同步 |
| 真实图形帧间隔 | p95 ≤ 33.3 ms | 固定／移动窗口同可见负载；不冒充 GPU profiler 时间 |
| 全游戏 RSS | 稳定 ≤ 2 GiB，峰值 ≤ 3 GiB | 完整加载、保存与编辑全过程；Rust CLI 与游戏分别报告 |

至少覆盖万级、十万级、百万级及复杂工厂，长蛇形以外加碎片、合流、循环与持续生产／消费。
同条件三轮有效测量，保留原始逐 tick 时间与工作量。
小规模与复杂工厂相对 M00 不得出现可重复的 >10% 时间或内存回退，
否则修正或显式报告未达验收，不仅展示百万长带收益。
M00 冻结比较统计量：分轮加载／保存总时长的中位数、常规 tick／桥接／帧间隔的 p95、
稳定 RSS 与全流程峰值 RSS；同规则集、同显示模式和同负载配对。
“可重复”要求至少两轮同方向超线且配对中位数超线，单次异常单列诊断，
不能混合规则集、headless／图形或不同缓存状态得到回退百分比。
边界条件和统计方法见 [003](003-migration-plan.md#测量与停止条件)。

当前静态实验的约 2 MiB 文件与毫秒级存读档不代表完整工厂。
历史百万连续运输快照约 48.8 MB、一次原生恢复约 3.27 s 等数据只作风险提示；
旧综合存读档记录在保存校验去重前，不能当成当前版本的精确基线。
相关范围见 [静态实验](../prealpha-2/004-rust-world-prototype.md)、
[保存边界](../prealpha-2/003-save-without-reconstruction.md)及
[历史综合记录](../../reviews/2026-11-24-final-optimization.md)。

## 设计依据与可调整项

必须保持：Rust 唯一权威数据、完整 Rust 存读档、规则与语言分离、失败不破坏活动档／世界、
有界局部通信、显式线程归属、可复现测量以及独立审查。
可根据证据调整：内存布局细节、表现区块粒度、压缩策略、网格任务并行、
缓冲容量、候选预算及小任务切分。调整写回所属条款，避免另一份计划成为竞争事实来源。
