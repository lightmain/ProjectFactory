### 执行与结果所有权

- 单个适配实例分配正 `request_id`；它用于匹配一次请求，不是去重／重放序号。
  Rust 不保存历史载荷、命令退休水位、控制水位或结果消费水位。
- 同时最多一个世界操作，含已完成但尚未领取的结果。提交前校验全部输入并原子接收；
  `Busy` 表示未接收，只允许重试这种请求。已接收请求不得再次提交。
  操作结果通过一次领取交给本地所有者；进度可重复读取，终态不能被覆盖。
- 单条请求继续限制字节数和建造格数；结果固定有界。
  不再按多命令、控制、未退休窗口联合预留；无独立 `control_seq` 和 `result_seq`。
- 磁盘服务最多一个作业。保存捕获完成产生 `SaveStarted`，世界操作槽在领取后释放，
  不可变快照交给 I/O。磁盘完成结果占一个独立有界槽，直到一次领取；
  保存期间允许普通世界操作，第二次磁盘请求明确返回忙。
- 取消直接操作对应作业的取消标志，不另建可靠控制记录或取消结果确认。
  作业终态报告实际取消结果；磁盘提交与取消的原子裁决、`CommitUncertain` 保留。
  已准备候选取消也在世界边界释放，不能遗留候选几何或误取消新世界。
  加载决定与安装仍通过同一世界操作槽串行执行；关闭使用独立关闭标志。
- 领取调用先校验预算，不足时不消费结果；桥接的纯 Rust 结果移入本地所有者，
  转换失败冻结会话，不重放已经执行的命令。

实际接口如下，身份只需为合法正数并与当前待处理请求区分；Rust 不要求连续或递增。
适配器按实例分配递增身份以方便匹配，不能再次提交已经接受的请求。

| 接口 | 当前契约 |
| --- | --- |
| `submit(epoch, Input { request_id, command })`／`submit_runtime(epoch, input)` | 一次提交一个不可变操作；Godot 字典使用 `request_id`／`kind` |
| `poll_updates(PollLimits { result_bytes })`／`poll_runtime(bytes)` | 每条完整结果计 96 字节，一次最多领取两条；不足 96 字节只读状态，已领取结果不再返回 |
| `cancel(epoch, job_id)`／`cancel_runtime(epoch, job_id)` | 返回取消标志是否胜出；作业的原结果报告终态，没有额外取消回执 |
| `PresentationReady`／`SwitchApplied` | 通过同一提交入口；桥接 `kind` 为 `ready`／`switch`，带候选作业身份及切换所需的新 epoch |

普通输入默认上限 64 KiB；单个建造事务仍最多 64 格，按 32 + 每格 16 字节计费。
时间事件计 48 字节；保存计 288 字节加世界名和槽位名的 UTF-8 字节数。
这些是传输预算，不是完整世界或快照的内存预算。目录、候选及表现页各自的载荷预算继续有效。
查询载荷在结果领取后仍可重复读取，下个查询被接收时替换；拒绝的新查询不替换旧载荷。
目录载荷仍需独立确认，确认按当前身份匹配，不把请求 ID 当递增退休水位。

### 时钟、暂停与保存采样

- 普通推进只有 `frame_seq` 与原始 delta，不传完整玩家检查点。
  `frame_seq` 仅识别推进及诊断，不参与玩家姿态配对。
  世界操作未完成时禁止下一次物理推进，不产生待补偿游戏时间；
  UI、进度与结果领取继续运行。保持已接受 delta、固定 tick 和部分 tick 余量。
- 不缓存多帧时间事件，不合并时间段、不追补等待期间的墙钟时间，
  不保留 `pending_simulation_time` 上限与积压恢复状态。
  宿主最多暂存一个已经采样但未接收的原始帧；它优先于后来菜单事件重试，
  期间不再次采样，暂停后拒绝新采样的正 delta。
  普通等待保留跳跃释放状态及已按住的中键手势，丢弃等待期间的运动增量；
  中键释放仍可结束拖动，暂停／失焦／物品栏继续取消交互；
  关闭与解绑明确结束手势并释放鼠标捕获。
- 暂停等待正在进行的世界操作完成；恢复不能越过暂停／保存采样／交接／故障。
  暂停、恢复一次只有一个在途请求，不维护旧回执与新意图的多序号竞争。
- 保存先完成已接受操作并暂停世界、冻结相关玩家运动，然后采集完整 `Player`，
  直接随保存请求交给世界拥有者捕获快照；删除 `SaveBarrier` 和过去帧
  `FrameMismatch` 重新协商。捕获完成后按采样前的暂停意图恢复，
  写盘不持有玩家采样屏障。手动／自动／退出保存仍有明确结果；
  宿主从保存请求到磁盘终态最多一项，第二项返回忙，由用户在完成后重试；
  保存并退出必须等待持久成功，失败保留会话。

### 本轮验收

1. 单个世界槽位在执行及结果未领取时均拒绝第二次操作；领取后不重复交付。
   非法请求／预算不足不改变已有操作，合法非连续请求 ID 可执行。
2. 一个推进未完成时，宿主不再次采样物理或积攒 delta；菜单与取消／关闭仍响应。
   两规则集的原始 delta、固定时钟和暂停行为正确，故障不继续推进。
   持续逐帧等待后仍能跳跃，中键拖动跨等待继续，等待期间释放中键不遗留捕获。
3. 保存先暂停后采集完整玩家／镜头／工具状态；捕获后可继续工厂，
   I/O 终态与同时完成的世界结果各交付一次，无 ACK 顺序依赖。
   两规则集的连续事件、保存完整字节及加载后继续运行结果与串行工厂对照一致；
   捕获与磁盘完成同次领取时也能恢复原暂停意图并释放保存槽位。
4. 保存、目录、删除、加载的坏档／失败／取消与关闭回收能力保留，
   候选交接、静态页面和新 epoch 能通过适配后的真实 GDExtension 与宿主链路。
   真实磁盘失败不触发退出，恢复写盘后可重试；取消已准备加载不改变旧玩家，
   释放候选后可再次准备同一存档。
5. 独立审查后运行完整 Rust／原生／Godot 验证，记录本轮边界；
   不把尚未接续的完整后台试玩声明为已完成。

本节为已接入的小工厂规则，不表示全部 M07 已完成。

### 行为与边界

- 玩家与自由镜头先检查当前 epoch／世界修订下的碰撞扫掠覆盖，再执行 Godot 运动。
  缺覆盖、操作等待或新编辑尚未安装时冻结相关运动；释放事件仍送达。
  扫掠按拟执行运动计算；世界边界外为空，只要求扫掠与有限世界相交的部分有碰撞覆盖。
  自由镜头进入时从玩家眼睛扫掠到初始高度，重置北向上、东向右；滚轮／中键增量
  排队到物理帧执行，锚点使用独立视野中心射线，轨道运动分段检查碰撞。
  镜头瞄准使用后台有界射线，不保留 Godot 权威方块或完整工厂副本。
- 单格建拆、朝向、直角线路、轴顺序、重复锁定与取消继承同步试玩操作。
  后台查询携带请求／视图身份；移动、切工具或取消后的旧结果只领取不显示。
  当前绿色预览不能代替提交校验。建造保存短期玩家／镜头姿态并冻结相关运动，
  Rust 检查玩家防重叠、同批几何与抬升净空，Godot 执行必要物理检查；
  提交时重验权威修订及安全条件，碰撞安装与抬升完成后解除等待。
  当前只有线路新增的传送带允许抬升，普通单格建造重叠玩家时拒绝。
  取消线路草稿不撤销已接受的准备操作；准备操作继续领取并确认，或随会话关闭释放。
  确认必须匹配准备 token、完整姿态及世界修订，并通过引擎安全检查；
  引擎否决或身份失配也消耗准备 token，不能重新确认旧准备。
  多方块结构与库存编辑仍属于 M12 后续范围。
- 已执行的玩家帧先保存或提交其原始 delta，再安排到期自动保存的暂停，
  等待不重复采样。场景／静态分页失败停止主动操作，但生命周期领取继续；
  错误面板提供关闭并返回主菜单的路径，不静默永久冻结。
- 动态物流由世界线程按有界区块兴趣采样，两规则输出同一采样 tick 的矿石身份、
  位置、局部设备数量与端口；不得先 `observe()` 全厂再在 Godot 筛选。
  单轮最大 1 MiB、单页最大 64 KiB，最多一轮请求或未释放的完整快照。
  宿主主动请求下一轮；已开始领取的一轮不可被新 tick 或兴趣覆盖。
  Godot 收齐并校验清单、身份与数组后，以 PackedArray 更新 MultiMesh，
  同时替换设备数量／端口，并退休离开兴趣的成员；失败保留旧完整画面。
  快照取消、关闭和 epoch 退休释放缓冲，不添加命令重放或结果水位。
  此处字节限额是桥接载荷计费，不能当成整个快照及引擎资源的内存上限。
  本片用显式释放及生命周期回收替代旧动态领取期限；未释放时拒绝新轮，
  不自动超时覆盖现有轮。动态期限若后续引入，须另写规则及验收。
- 暂停菜单切换规则时重新创建示例世界，保留工具、朝向和暂停意图；
  新宿主、玩家与菜单使用同一暂停状态，继续后恢复玩家控制及物流。

## 接口边界

本节旧批次提交、消费确认和帧配对部分已由[受控等待](#受控等待第-17-项)替代；
下文线程归属、纯数据转换和路径安全边界继续有效。

GDExtension 对外提供一个由主场景持有的 `FactoryBackend` 对象。
Godot 传小型命令和订阅，Rust 返回查询结果、作业结果和局部表现数组。
桥接层把 Godot 值转换为经过校验的 Rust 结构；工作线程不持有 Godot 类型。
高频数据使用成批 PackedArray，低频结果可用小 Dictionary；
不把整个世界包装成嵌套 Dictionary 过桥，不借用会被另一线程修改的裸指针。

| 拟定入口 | 输入／输出 | 行为边界 |
| --- | --- | --- |
| `open_backend(options)` | 显式运行参数、应用提供的存档根目录；能力／错误 | 握手协议和构建来源；Rust 创建目录服务与世界线程 |
| `submit_batch(frame_input)` | 帧序号、时钟、少量玩家姿态、命令批次；接收状态 | 非阻塞；接受只代表入队，不代表世界已修改 |
| `poll_updates(limits)` | 领取预算、上次消费确认；状态／可靠结果／表现页 | 非阻塞；暂停和载入画面也持续调用 |
| `set_interest(interest)` | 相机参数、玩家碰撞范围、查看设备、视图代号 | 覆盖旧订阅；输出按局部范围限制 |
| `request_query(query)` | 射线、预览、设备、库存、目录页等 | 排队并返回匹配请求 ID 的有界结果 |
| `request_save(save_request)` | 世界身份、名称／槽位语义、玩家姿态帧 | 在完整规则步之间的事件屏障建立一致快照，返回作业 ID |
| `request_load(load_request)` | 存档 ID、载荷版本、交接选项 | 异步读取与独立恢复，旧活动世界保留 |
| `cancel_job(job_id)` | 已知作业 ID | 返回取消或已提交结果；不能把成功载荷当失败删除 |
| `close_backend()` | 生命周期关闭 | 拒绝新操作，结束或取消作业，停止并回收线程 |

存档路径由应用在启动时注入，运行命令只接受后端签发或合法的存档 ID，
不接受世界名称拼成的任意路径。Godot 不负责目录扫描、SHA、压缩或载荷校验。
生产时刻、库存和运输成交不通过逐物品 Godot 回调处理。
后端自带完整生产／消费适配，Godot 的 HUD 读取统计快照。

运行时配置继承 [005](../prealpha-1/005-game-config.md#配置来源与生效)：
Godot 接收 `Resource.changed`，表现距离／高度进入新兴趣订阅，下一次刷新生效；
生产参数作为有序规则配置命令，在后续建造命令之前生效。
已有矿机保留放置时的参数快照，非法参数沿用既有关闭显示／停产规则，
不能把所有非法值统一拒绝后沿用旧有效值。运行时变化不自动写回 `.tres`，
存档恢复的规则参数不污染共享资源。重力和玩家运动参数仍按 005 的引擎配置边界处理。

## 标识、排序与可靠性

本节重放、退休、连续结果 ACK、独立控制与窗口预算部分已由
[受控等待](#受控等待第-17-项)替代；epoch、tick、修订与表现代号继续有效。

所有状态变化使用下列标识，不能只依靠场景节点实例 ID：

| 字段 | 意义 |
| --- | --- |
| `api_version` | 桥接协议版本；不兼容版本拒绝启动，不自动猜测 |
| `world_epoch` | 一次活动世界实例的代号；新建／成功加载递增，旧结果不可应用到新世界 |
| `command_seq` | 本次后端会话中严格递增的命令序号，用于排序、去重及确认 |
| `result_seq` | 可靠结果发布序号；消费确认按此序号推进，与命令终结顺序分离 |
| `frame_seq` | Godot 物理帧序号，绑定玩家姿态、时间输入和保存屏障 |
| `tick` | 已完成的固定规则步数 |
| `world_revision` | 权威世界编辑修订；查询／预览可声明所依据的修订 |
| `view_generation` | 当前显示订阅代号；过期画面结果弃用 |
| `query_id`／`job_id` | 独立查询与存读档作业身份；结果必须对应请求 |

普通编辑按接收的命令序号在时间事件边界串行执行。
批量线路放置是一个事务，成功才增加修订；
查询返回其观察的 tick／修订，不能伪装成尚未处理的编辑之后的结果。
需要基于预览提交的命令携带预览修订；已过期时重新校验全部路径，
合法则提交，非法则拒绝，不能仅凭旧的绿色预览放置。
相机快速移动的旧查询结果通过请求 ID 和视图代号识别，不能闪回旧预览。

`submit_batch` 明确返回 `Accepted`、`Busy` 或输入错误。
一批输入先整体校验，再原子入队；`Busy` 时整批未接收，不能只接收时间却丢掉命令。
入队后不同编辑命令各自返回终态，只有显式标成一个建造事务的操作才整体提交／拒绝。
队列满时不阻塞 Godot，也不悄悄丢弃建造、删除、暂停或保存操作。
宿主保存尚未接受的命令并有限重试；到达宿主待提交上限后禁用新的修改并显示状态。
重复提交同序号／同载荷只执行一次；相同序号不同载荷拒绝。
可靠结果确认使用连续 `result_seq` 消费水位，在消费确认前保留结果；
命令去重记录在其终态已消费后标为可退休，连续命令退休水位之外仍保留有界记录。
重放早于命令退休水位的命令返回 `AlreadyFinalized`，
绝不能重新执行。序号分配与重试状态由单个适配实例管理。

可靠结果包含 `Committed`／`Rejected`、错误码、tick、修订和必要的少量定位信息。
保存、加载、删除和覆盖确认均有可靠终态；进度可以覆盖，终态不能覆盖。
初版按字节和条数同时限制输入、可靠结果、静态表现和动态表现队列。
满额时停止接受产生更多可靠输出的新作业，保留取消／消费／关闭控制入口；
具体容量在 M06 测量锁定，不能用无限队列规避背压。
`poll_updates` 的单次转换量也有字节上限，超限分页领取。

接受批次／作业前预留其可靠输出额度，包括终态和必要的提交决定；
进度采用覆盖状态，不消耗无限可靠记录。输出记录有最大字节数，
额度不足则整批 `Busy`，世界线程不因发布已接受操作的终态阻塞。
控制请求有独立额度及去重，消费确认不产生需要再次确认的结果；
控制额度满时新的取消返回 `Busy`，消费和关闭通知仍可送达。
长作业未完成不阻挡后来结果的 `result_seq` 发布，
但命令未退休窗口也有上限，防止一个长作业留下无限去重尾部。

#### M06a 纯 Rust 通道参数（2026-11-26，当前规则，独立复审与完整复验通过）

本节多命令／结果窗口、连续身份与退休参数已被[受控等待](#受控等待第-17-项)替代。
单次建造、非阻塞锁、错误分类和关闭回收边界继续有效。

首切片每个实例固定一个 epoch，时间／作业和 GDExtension 适配由 M06b／c 接续。
默认最多 256 条尚未退休命令、64 KiB 命令载荷和 256 条／24 KiB 可靠结果。
单个显式建造命令最多 64 格；输入计费为每命令 32 字节加每建造格 16 字节，
可靠结果固定预留／计费 96 字节（含身份、终态、tick／修订和单格查询）。
这些是此切片的协议预算，不是整个世界内存、Rust 容器实际分配或 M07 几何上限；
未退休命令载荷只保存一份，待执行队列存序号，执行中的载荷副本也受单命令上限约束。
宿主提交／领取用短临界区的 `try_lock`，竞争返回 `Busy`，不等待世界操作。
消费确认不占输入／输出额度；领取整条结果，不返回残缺记录，
单页最多 256 条／24 KiB，调用方还可提供更小预算。
同批序号严格递增，新序号从最近接受序号连续分配；重试不占新序号。
早于退休水位的混合批次整体返回 `AlreadyFinalized`，不偷偷接收其中的新命令。
批次内非法参数、身份冲突、序号缺口和额度不足均不改变水位或接受部分操作。
尚未退休的记录占据输入预算直到连续退休，防止慢作业后的去重载荷无限累积。
关闭显式废弃本会话未消费结果，不产生另一个需要消费的关闭结果；
宿主观察独立退出状态，在退出前不能把同一运行时复用成新世界。
M06a 的 `Faulted` 回执中修订 `0` 表示故障后未知，不能据此回退世界修订；
宿主应冻结会话并只领取／确认结果，不能继续应用查询或接受编辑。

错误至少区分非法参数、越界、占用冲突、过期世界、队列繁忙、不支持的规则／版本、
坏档、磁盘失败、作业取消和后端故障。错误返回不得携带完整世界或任意用户文件内容。
预期的建造失败是正常结果；后端 panic／异常是故障状态，不能混为“这个位置不能建”。

### 建造与玩家物理协作

一般占用检查在 Rust 完成，但放带抬升玩家还需要 Godot 物理确认。
为继承现有 `FactoryGame` 的净空和抬升规则，影响玩家／自由镜头占用的建造使用短事务屏障：

1. Godot 暂缓有关玩家／镜头运动，提交当前 `pose_frame`、占用 AABB、安全余量和建造意图。
2. Rust 校验权威方块、同批上层带、镜头占用与扫掠净空，
   返回 `BuildPrepared(token, revision, pose_frame, proposed_lift)`；不先改世界。
3. Godot 确认该姿态未变化且扫掠范围现有碰撞修订就绪，
   执行引擎 `test_move` 等必要物理检查，提交带 token 的确认或取消。
4. 世界线程按序号确认 token／修订／姿态；过期则重新预检或拒绝，
   合法才原子提交方块与工厂，返回所需碰撞修订和最终抬升目标。
5. Godot 安装影响占用／扫掠范围的碰撞，完成玩家抬升后释放运动屏障。
   准备阶段取消恢复旧状态；已提交后取消不能撤销一半建造。

单格／结构的玩家和镜头防重叠也使用对应姿态与占用信息，
不能只用世界修订推断玩家没移动。影响正在移动实体的编辑在确认前采用同一屏障，
无关区域编辑不冻结玩家。长路径、同批几何与净空逐格工作全部在 Rust，
Godot 只提供少量物理对象状态和引擎查询结果。

## 时钟与暂停

本节积压恢复和逐帧玩家／保存配对部分已被[受控等待](#受控等待第-17-项)替代。
固定 tick、原始 delta、部分 tick 余量及故障冻结规则继续有效。

Godot 每个物理帧提交一次 `FrameInput`，包含 `frame_seq`、模拟 delta 和小型玩家姿态。
Rust 用固定 1/60 s tick 运行两种规则集，不用墙钟在暂停或菜单中偷偷推进工厂。
时间输入带序号且去重，队列繁忙时未接受的时间不能丢失或重复。
宿主保存有界时间事件流：帧前命令／查询、该帧 delta、帧后姿态分别定位。
时间推进先完成此前事件，再处理下一事件；编辑在发生时的累计模拟时间创建机器，
后续固定 tick 才按规则结算，不能统一把放置时刻舍入到整数 tick。
没有命令／查询／配置／保存／暂停屏障的相邻时间段才可合并；
合并保留原 delta 顺序或等价补偿状态，不把浮点求和差异带进生产相位。
含事件的帧保留其时间偏移与对应姿态，不能只保留最新姿态。
单帧定义为先应用帧前事件、再推进该帧 delta、再观察帧后状态；
帧间输入按其前一已提交时间位置进入事件流。
`legacy_discrete_v1` 保留累计时间／浮点补偿、未满 tick 的余量、dirty 拓扑、
`flushed` 和成交资格等现有语义：编辑恰在边界时的补充结算不能重复，
边界内编辑不提前成交。M06 用原事件流与 Busy 合并后的事件流等价重放核对。

每次调度最多处理有界数量 tick，再服务控制请求和结果领取。
报告 `pending_simulation_time`、完成 tick、最长 tick 和模拟落后；
积压达到上限时暂停接受新的游戏时间并通知宿主暂缓物理推进／操作，
恢复后继续处理已经接受的时间。不能无限追帧、截断已接受时钟或把积压写成正常帧。
允许合并尚未接收的表现订阅；不合并有玩法意义的编辑。

暂停按序号屏障生效：完成此前已接受的规则时间后停止 tick，返回暂停确认。
暂停画面仍允许轮询、存档、目录查询与关闭，不允许生产继续。
载入过程中旧世界暂停；取消／失败后按进入前的暂停状态恢复。
成功载入带回保存的固定 tick、累计模拟时间、未满一个 tick 的余量及生产调度状态。
渲染插值只使用只读位置数据，不改变库存、身份或保存的权威进度。
原有工具、库存打开和焦点规则仍由 Godot 协调输入边界。

### M06b 时间事件切片（2026-11-26）

本节命令去重、224 字节姿态事件、2 秒积压和 `SaveBarrier`／`FrameMismatch`
部分已被[受控等待](#受控等待第-17-项)替代；单次推进与 tick 边界继续有效。

状态：当前纯 Rust 规则，已实现并通过针对性回归、独立审查及完整 Rust／Godot 复验；
磁盘作业与试玩后台接入仍待 M06c。

采用有界单时间事件，复用原工厂的一次 `advance(delta)`，不跨线程搬动活工厂，
也不把一个 delta 拆成多次推进。普通 Godot 物理帧为固定 1/60 s；
此切片允许单事件 delta 为 0～4/60 s，超限在接收前明确拒绝，不能截断。
包括之前未满 tick 的余量与浮点边界容差，单事件最多推进 5 个固定 tick，
另保留已有边界补结算；每个事件后回到调度入口。
这是 tick 数的有界性，不表示单次大型拓扑修改或一个 tick 有固定墙钟耗时。

时间事件使用普通 `command_seq` 去重，并携带严格递增的 `frame_seq` 和完整
`persistence::Player` 帧末姿态。新帧序号允许跨过没有提交时间的菜单帧，
同帧同命令的重试仍只执行一次；新命令不能复用已经接受的帧序号。
宿主按帧前事件、时间事件及帧后保存请求排序，保持每个原始 delta；
Busy 待重试时保留原事件序列，不先浮点求和再提交。
时间事件和同批编辑整体校验／预留，非法姿态、过期帧或时间超限不得只接受编辑。
时间事件按 224 字节计费，暂停／恢复与配对屏障各按 32 字节；
可靠终态仍使用 M06a 的 96 字节预留。`Player.frame` 必须等于 `frame_seq`，
两者不能独立描述不同玩家帧。

默认最多积压 2 秒尚未完成的模拟时间，包含正在执行的事件；
时间预算与 M06a 输入／结果预算分别检查。
达到任一上限时返回 Busy，宿主暂缓物理推进并保存有界待提交事件。
处理完成才释放时间预算，故障进入冻结状态，不能把未完成时钟当已模拟。
状态报告完成 tick、累计时间／补偿、最近完成帧、暂停、积压和推进耗时；
单事件耗时可以作为 tick 耗时的保守上界，但必须明确标识，不能冒充逐 tick 实测。

暂停／恢复作为有序命令，在此前时间完成后返回可靠确认。
接受流中已排序的暂停之后，正 delta 时间事件整体拒绝，
直到对应恢复命令进入同一有序流；暂停时可用 delta 0 更新姿态。
工厂不通过墙钟或轮询自动推进。后续保存使用世界线程处理完成的帧末姿态，
请求帧必须与当前保存屏障配对；配对失败要求新帧，不能混合旧姿态与新工厂。
本切片先用纯 Rust 重放验证时钟、暂停和姿态配对，
磁盘作业及 Godot 宿主缓存／运动冻结由 M06c 接入并验收。
当前 `SaveBarrier` 只返回配对结果，不写盘或生成存档；
它在世界线程验证最近完成帧并为后续快照入口提供同一完整 `Player`。
无姿态或请求过去帧返回 `FrameMismatch`，时钟不额外推进。
已接受的时间事件发生规则错误时终止会话并发布故障终态，
不能跳过该时间继续执行后续命令；状态保留最近成功完成的时钟／姿态帧，
不能把它当成故障后的完整世界快照。

## 局部视图与碰撞协议

`Interest` 分别表达相机视图、显示距离／高度、玩家附近碰撞和正在查看的设备。
Rust 保存可重建的局部候选缓存，权威世界不依赖该缓存。
兴趣更新有 `view_generation`，各表现页还携带 epoch、tick、区块／批次键和修订。
距离、端点、负坐标、父节点变换与原规则一致；不能偷减范围证明变快。

静态输出分为 `ChunkReady` 和 `ChunkRemoved`，携带网格数组、材质槽／方向属性、
碰撞数组、AABB 与相关修订。显示网格和碰撞可以不同优先级领取；
碰撞依赖修订要覆盖邻面变化，不能把旧碰撞挂在新方块上。
静态结果按键保留最新修订直到宿主确认安装／移除，
过期结果由代号和修订拒绝；发现缺页、断档或 epoch 不符时重新订阅当前局部快照。
完整静态初始页有开始／结束标记，宿主不能把半页当作完整区域。

网格页的拟定布局如下，具体字节上限在 M07 冻结：

| 数据 | 过桥类型与校验 |
| --- | --- |
| 顶点、法线 | `PackedVector3Array`，区块局部米制坐标；法线数量等于顶点数 |
| UV／标记属性 | `PackedVector2Array` 与显式通道的 PackedArray；数量匹配，不传每顶点 Dictionary |
| 索引与表面描述 | `PackedInt32Array`，三角形索引合法；有界材质槽对应 Godot 已有资源 |
| 碰撞 | 独立顶点／三角形数组及碰撞修订，不在 Rust 创建 `Shape3D` |
| 安装描述 | 区块世界原点、AABB、epoch／代号／修订、分页面号和完整性标记 |

所有几何数值须有限，索引在分配／安装前校验；资源引用由 Godot 按材质槽解析。
数组由 Rust 桥接成批构造，Godot 不循环逐顶点转换；引擎创建资源仍在主线程。
网格与碰撞的局部原点一致，既有父节点变换由 Godot 安装器处理，
不能将世界坐标数组又乘一次区块位置。

动态输出按“可独立替换的批次”提供完整成员集合和缓冲：
`batch_key`、成员身份、有效实例数、容量、12 浮点／实例的 3D MultiMesh 变换、
必要的颜色／自定义数据及 AABB。
不假设一个物品永久属于同一批次；成员离开、进入或跨批必须在最新完整批次中反映。
尚未开始领取的动态快照可 latest-only 覆盖；已经领取的快照以
`display_snapshot_id`、tick、总页数和批次清单固定，页不能逐 tick 被替换。
初版最多保留一轮在途快照和一轮最新待领快照，单轮字节与领取期限有上限。
宿主收到全部页后确认该轮，按同一快照协调安装有成员迁移的批次，
再根据完整清单退休缺失批次；位置与成员不能混用不同 tick 造成重复物品。
超大局部视图允许多帧准备缓冲，但相关跨批集合在同一安装步骤换入，
不把残缺数组交给 MultiMesh。独立成员未变化的批次可后续优化更新，需另行证明一致性。
领取超时或超限则显式中止该轮，宿主丢弃未安装页并请求新局部快照，
不能持续覆盖最后一页使一轮永远无法完成；先保留旧完整画面。

矿石位置由 Rust 根据同一 tick 和来源方向计算；
正常帧不把整条运输队列或全厂几何往返 Godot。
Godot 保存局部身份映射用于高亮、拾取和测试，容量退休后释放。
活跃物品全部运动时传输量仍随当前可见物品数增长，须报告实际字节数。

以上动态协议的双快照／latest-only 预留及确认形式，在已接入的小工厂中由
[后台试玩动态规则](#后台试玩输入与动态物流接入2026-11-27当前规则)替代：
只保留一轮请求或完整未释放快照，固定轮身份和页面，安装后显式释放。
旧正文保留为后续流送方案依据。
Godot 以每帧时间／字节预算创建引擎资源并安装批次。
玩家碰撞兴趣优先，未覆盖的区域不得让玩家穿入；自由镜头与玩家碰撞订阅分开。
二者都提交下一运动的扫掠范围及余量，安装器按该范围维护碰撞修订覆盖。
只有覆盖目标权威修订才可依据引擎碰撞移动；新建墙体等编辑使相关扫掠范围立即失效。
覆盖缺失时暂缓该段运动，或向 Rust 请求带姿态／修订的权威数据扫掠结果，
由 Godot 在获准路径内执行物理运动；不能凭旧场景碰撞穿过新数据。
自由镜头缩放、绕点旋转和平移均遵循该检查，数据扫掠不要求全世界已生成 Shape。
载入／重生的 `WorldReady` 表示后端数据可运行，不等于场景可操作；
Godot 安装附近网格／碰撞后回传 `PresentationReady` 才开放输入。
详情与库存只返回正在查看的对象或有界页面；关闭 UI 后不持续拉全厂设备详情。

### M07a：附近静态网格首片（实施中）

先实现纯 Rust CPU 网格，再接世界线程的兴趣缓存、分页与 Godot 安装器。
表现区块沿用现有视图的全局对齐 8³ 格，独立于世界差量的 32³ 页；
负坐标使用向下整除，区块原点以 0.5 米格长计算。
每次只读取一个区块及六向邻格，禁止以全世界观测替代局部数据。
顶点／法线／颜色／UV／CUSTOM0 和三角形索引为连续数组；
碰撞提供独立三角形顶点，安装时与网格使用同一局部原点。

`VoxelWorldView`，坡面邻接保持其当前不剔除规则。

### M07b：世界线程静态分页（实施中）

先提供显式区块键的局部订阅，最多 64 个不重复的 8³ 表现区块；
键必须与目标世界边界相交，调用前校验数量，不能复制无限输入。
订阅区分当前世界和一个已准备的加载候选，携带 epoch、递增代号和候选作业号。
候选取消或切换后不能再读取其页；新 epoch 必须重新订阅。
取消胜出或提交决定失败时，同时释放该候选的已生成数组与未完成构建；
已确认领取的数组也必须释放，当前世界订阅不因候选取消而退休。
取消不回退订阅代号水位，旧代号不得重新建立已经退休的轮。
相机范围与碰撞扫掠到这些键的转换及运动许可仍由后续 Godot 安装切片接入。

世界线程每个事件边界最多生成一个区块，不调用整厂 `observe()` 获取朝向。
一轮所有区块使用同一工厂修订；建拆或旋转的接收立即使旧轮失效，
规则操作完成后重新生成，邻区遮挡变化也受此保守全局修订覆盖。
初版允许全局修订使不相关区块重建，后续局部依赖优化须另验收。
一轮最多 8 MiB 数组和描述载荷，超限整轮拒绝；
每页最多 128 个完整面，页描述按 4096 字节保守计费，整页硬上限 64 KiB。
页内索引从零开始，碰撞与网格使用相同面集合和区块原点，
空区块也交付一页用于退休旧资源，完整清单用于退休订阅外的区块。
表现页的 `revision` 和 `world_revision` 均使用该轮工厂修订，
包括朝向变化；不传底层 World 按格计数的内部修订作为安装许可。

完整轮生成后才可领取，分页携带固定 snapshot_id、总页数、全区块清单、
区块页号、工厂修订与 tick；重复领取不推进游标或确认安装。
只有全部页被领取后才接受该轮的安装确认，重复确认幂等；
代号、轮号、修订或候选不符必须拒绝。新订阅以及已确认轮后的首个编辑
各开启最多 5 秒的生成／领取／确认窗口；未完成轮内编辑不延长窗口。
超时明确中止并释放载荷，宿主保留旧完整画面，使用新代号重订阅。
初版只有一轮静态载荷，不在后台积攒历史轮；更新订阅释放旧轮。
此切片验收字节边界、多页完整性、漏页确认拒绝、重试、空页、
代号与候选隔离、邻面编辑失效、两规则集朝向及无时钟推进。
它不代表动态矿石分页、引擎资源安装或运动扫掠许可已经完成。

桥接将区块清单压为每键三个 int32，几何直接返回 PackedArray；
CUSTOM0 为每顶点四个 float32，不逐顶点传 Dictionary。
领取前检查调用方字节预算，实际 Variant 编码长度也不得超出页计费。

调用方在后台确认轮仍有效后，于物理帧边界切换完整根节点。

后台使轮失效时丢弃半轮并从新轮第一页领取，超时中止则用递增代号重订阅。
关闭先丢离树资源，再重试非阻塞取消订阅直到成功或原 epoch 已退休，
已启用的旧完整画面由场景所有者决定何时释放。
关闭使用后台实际接受的代号，不能用 Busy 尚未接受的新代号代替；
合法候选取消或 epoch 退休停止旧请求，但仍允许显式请求新的当前世界订阅。
候选本地资源／页失败后，决定前成功取消可显式转回当前订阅，
释放失败候选及其本地错误，但保留已接受身份和代号水位；
后端故障、缺接口或错误配置不能由此恢复。
离树安装器销毁也释放候选根，页数先受引擎 surface 上限约束，
每次 surface 创建必须确认成功后才推进安装水位。

## 一致快照与作业状态

本节旧帧身份协商与独立取消确认部分已被[受控等待](#受控等待第-17-项)替代；
完整检查点内容、世界拥有者捕获和磁盘原子裁决继续有效。

保存必须截取同一规则时刻的世界、机器、拓扑、生产、库存、运输、物品身份、
来源方向、tick、时间余量／补偿／flushed、规则配置和玩家状态。
玩家小型检查点至少包含位置、速度、出生点、视角、工具和建造朝向，
逐项映射当前 `FactoryGame.save_state`，不能把“玩家状态”仅实现为位置。
不能先保存机器，继续跑几帧，再保存运输。
Godot 不调用 `save_state()` 导出完整世界，也不接收原生运输快照再交回 Rust 存盘。

Godot 在物理帧末采集玩家姿态，保存事件放在该帧 delta 之后，
请求携带对应 `frame_seq`，适配协调器保证采样在玩家物理更新之后。
世界线程处理到该保存事件，在完整规则步之间的事件屏障截取，
保留当前累计时间与未满 tick 的余量，不为了保存额外推进到下一个 tick。
返回采用的 tick／frame／revision。若后端已越过请求帧而无法配对，
协商新的屏障和姿态，不声称过去的物理位置与当前工厂完全同刻。
保存屏障只短暂停止模拟取得快照，I/O 阶段可继续模拟。
区块和实体表可用 `Arc`／写时复制保持一致快照，但发生复制须计量；
RustConveyor 的原生 `snapshot()` 仍由拥有实例的世界线程执行，耗时单列。
快照中的纯字节和不可变数据才能交给 I/O 线程。

| 作业 | 状态顺序 | 成功点 |
| --- | --- | --- |
| 保存 | `Queued → Capturing → Encoding → Writing → Verifying → Committing → Completed` | 活动指针／目录事务持久提交完成 |
| 加载 | `Queued → Reading → Decoding → Validating → Preparing → Prepared → CommitDecided → SwitchApplied → Completed` | 新 epoch 及附近表现交接完成，宿主切换已确认 |
| 取消／失败 | 任一可取消阶段转 `Cancelled`／`Failed` | 返回可靠终态，保留原活动档／世界 |
| 保存提交不确定 | 索引可见切换后同步失败转 `CommitUncertain` | 不宣称持久成功；保留新旧载荷，待恢复确认 |

同时最多一个保存快照和一个加载作业；加载进入交接阶段前等待或取消保存，
不让多个完整世界快照无上限并存。自动保存忙时合并到一个待办，
保留命名保存请求的明确结果，不能无声覆盖用户请求。
保存并退出等待 `Completed`，失败保留游戏并显示错误。
关闭期间用进度／状态诊断耗时，不在主线程无限等待。

加载使用 staged world：I/O 解码纯数据，世界线程在暂停状态建立独立候选工厂，
验证后生成附近表现数据。旧世界、旧目录指针和旧表现保留直到交接成功。
新世界的资源可预建，但不能先拆掉玩家脚下旧碰撞。
候选停止模拟，表现页带候选 token，宿主只在候选资源区准备，不能当活动 epoch 安装。
Godot 完成必要资源预校验后发送 `PresentationReady`（加载的 `Prepared` 确认）；
世界线程是提交／取消的唯一排序者，
串行决定 `CommitDecided(token, next_epoch, player_state)` 或 `Cancelled`。
决定可靠保留、可重取且幂等，提交决定以后取消只返回 `cancel_too_late`。
Godot 收到决定后在一次物理帧内换入附近表现、玩家状态与 UI，
发送幂等 `SwitchApplied`；未发送前继续冻结运动，不让新 UI 配旧世界。
世界线程收到切换确认才启用候选模拟、报告 `Completed` 并释放旧世界；
确认丢失时重送，不销毁已决定提交的候选。
决定前失败／取消可以丢候选并恢复旧世界；决定后宿主安装故障冻结会话，
保留决定和新旧资源用于重试，不能一方回滚另一方继续新世界。
后续无关远处流送失败按显示错误处理。
内存预算须覆盖旧世界、候选世界和资源重叠的阶段。

保存在进入 `Committing`、执行可见索引切换前关闭取消窗口；
加载在 `CommitDecided` 前可以取消，此后只能完成／重试同一决定。
已完成则返回成功及 `cancel_too_late`，提交中返回当前状态，
不能回报取消后删除已成功或可能已经可见的档案。
覆盖、删除、自动淘汰按目录序列串行化，正在加载／保存的条目不能被另一命令移除。

## 格式 5 的容器契约

目标正常存档为独立于 Godot Variant 的**世界格式 5**。
初版采用显式小端编码，不直接 dump Rust struct，不把内存地址或 Godot 对象写入文件。
整数宽度、浮点精度、字段顺序由编码器／解码器共同测试锁定。
运输原生快照有独立版本，不能由外层格式 5 推断其兼容性。

拟定一个载荷容器；命名／自动档仍由目录管理多个载荷。
容器头和 section table 记录：

| 内容 | 契约 |
| --- | --- |
| 识别头 | 固定 magic、容器版本、头／表长度、载荷总长度，保留字段写零 |
| 世界描述 | 世界 ID、规则集与规则版本、边界、地下层数、必要生成配置 |
| 检查点描述 | tick、模拟时间与余量、修订、玩家帧和姿态 |
| 区段描述 | kind、schema version、压缩枚举、文件偏移、压缩／原始长度、记录数、原始 SHA-256 |
| 整体完整性 | 覆盖头／表及所有压缩区段的校验；校验字段自身按约定清零后计算 |

区段至少包括世界差量与结构实例、设备与库存、拓扑／待接缝、生产与时间、
运输／身份／来源方向、玩家与会话参数。
连续规则使用实际原生快照字节，离散规则保存真实队列与进度；
不能以“每格两颗”等生成公式替代玩家已经演化的状态。
材质、GPU 资源、派生网格、局部候选缓存及显示批次不进入权威存档。
可以存入可重建的拓扑加速信息，但必须全量核对其与权威设备一致。

每区段支持 `none` 与锁定参数的 `deflate`；是否压缩由实测策略选择，
不能把压缩模式变化当规则变化。按区段流式读取／编码，限制单区段和总解压大小；
必须在分配前检查长度、计数、偏移重叠、整数溢出及世界范围。
未知必需区段或版本拒绝；已声明可选的区段可以跳过，
不能把损坏的必需字段当默认值继续加载。
完整机器／物品身份、坐标、枚举、库存、生产相位、拓扑、运输状态与规则兼容性
在候选世界内进行语义验证。校验和正确也不代表玩法状态合法。

M08 冻结 magic、每区段字节表、上限、校验覆盖顺序和黄金文件；
本阶段不凭文档虚构一个已稳定发布的二进制 ABI。
上限至少覆盖继承世界范围和百万真实载荷，
以测量后的字节预算写入代码与格式条款，而非解除旧上限后无限分配。

## 磁盘提交、目录与恢复

Rust 维护世界 ID、命名档、当前继续点、自动档轮换及递增目录序列。
世界名称和存档名称只是 UTF-8 显示字段，不能成为任意路径；
继承当前身份、重名确认、双击载入、删除确认与轮换语义。
Godot UI 先取得条目／版本，再提交带预期目录序列的覆盖／删除请求，
目录已变化则刷新并重新确认目标，避免覆盖错误载荷。
目录查询分页返回元数据，不加载每条完整工厂。

持久提交遵循：

1. 在目标目录同文件系统写唯一临时载荷；失败不改活动指针。
2. 完成长度与校验，flush 并同步文件。
3. 从实际磁盘重读并流式验证容器、区段长度／校验及必要格式字段；
   不再完整构造第二个运行工厂，保存前一致快照已保证规则状态。
4. 原子重命名为不可变载荷，同步目录；写新的目录事务／非活动索引并同步。
5. 先进入不可取消的 `Committing`，再原子切换活动指针／索引并同步其目录，
   才报告保存完成；索引 rename 已可见而目录同步失败则转 `CommitUncertain`。
6. 成功后才淘汰超过轮换范围的旧载荷；失败绝不先淘汰可继续档。

具体跨平台同步实现与失败点在 M09 验收。
`CommitUncertain` 保留新旧载荷和索引，不执行取消清理／自动淘汰，
暂停受影响目录的全部索引／目录序列／继续点修改，
包括新增保存、自动保存、覆盖、删除、轮换、导入登记和加载后的最近条目更新；
只读查询／载荷读取及提交恢复不受限。不能另建新槽位绕过这个目录屏障。
有界重读与重新同步可确认成功，
否则返回明确不确定状态并在恢复流程处理，不报告普通“失败且完全未变”。
启动恢复可以选择已验证的新提交或旧提交，二者都必须有完整载荷，
不得把已可见索引指向的文件当临时文件删除。
不能仅因 `rename` 返回成功就宣称断电持久性；首轮支持范围为已验证的 macOS arm64。
保存支持取消临时输出，启动恢复时清理可确定未提交的临时文件，
在完整、已校验的目录事务中选择最近的有效提交。
活动索引坏了可回退到上一个有效提交；孤立载荷不自动变成最新继续点。
两个 bank／冗余索引只是原子性方案之一，实施可以保持现有双 bank 组织，
但必须保留恢复能力并写明新目录与旧目录共存规则。
清理与删除只能访问受控存档根目录内、符合身份格式的文件。

## M06c-1 关闭与线程回收（2026-11-26，当前规则）

已实现并通过针对性回归、独立审查及完整 Rust／Godot 复验，
证据见 [本轮记录](../../reviews/2026-11-25-alpha-2-start.md#m06c-1存档-io-与世界线程回收2026-11-26)。
世界内保存接续见下节 M06c-2a；目录、候选恢复与 GDExtension 后台接入继续实施。

关闭存档服务是可重复的非阻塞操作：拒绝后续作业，不获取进度锁、不等待磁盘、
不在 Godot 主线程 join。尚未进入提交的作业请求取消；已进入提交的作业继续，
关闭后仍可领取其唯一真实终态，不把已提交输出覆盖为取消。
独立退出状态在工作线程实际退出、释放资源且由后台回收后成立；
仅发送取消或退出标志不算线程回收。世界运行时使用同样的退出口径，
后续拥有 I/O 子服务时，还须等子服务回收才可报告整个运行时退出。
关闭活动会话依旧按 M06a 规则废弃其未消费结果，存档服务自身保留提交终态
供尚存的调用方领取；丢弃整个宿主不执行已提交载荷的删除。

控制窗口满时新取消可返回 Busy，消费与关闭始终可送达。

复用现有 `SaveRequest`／`Session` 规则，非法元数据整批拒绝。
一个运行时只保留一个保存槽位；保存终态被消费前不接收第二个保存，
普通命令窗口仍按连续已消费的终态退休。
`SaveCompleted` 返回捕获帧、存档身份和目录序列；
`SaveFailed` 只返回固定错误码，文件路径与任意磁盘错误文本不进入可靠结果。
帧配对失败终结为 `FrameMismatch`，不会输出存档。
子 I/O panic／断连使用明确的 `WorkerFault`，映射为保存失败，
不冒充非法存档输入；捕获前后观察到关闭时不再派发新 I/O。

另有最多 32 条控制记录及 32 × 96 字节结果预算，可由 `Limits` 分别缩小；
额度包含未消费终态。相同控制序号／作业身份重试不占新额度，
冲突重试、序号缺口和已退休控制请求拒绝。
`CancelCompleted` 沿统一 `result_seq` 返回是否取消胜出，
其 `command_seq` 为 0，普通结果的 `control_seq` 为 0。
领取控制回执只退休控制记录，不把它当作保存终态。
取消在世界事件边界执行，原子令牌从保存接收时保留到捕获和 I/O 提交，
捕获前取消不会初始化存档目录。提交胜出或保存已有终态时返回取消太迟。
两种结果额度独立保留，轮询页仍同时受条数和字节预算限制。

关闭／故障回收时，世界线程先关闭并等待子 I/O 的回收通知；
等待发生在后台，整个运行时的退出通知仍只在世界线程被回收后成立。
关闭活动会话废弃输出；故障为尚未终结的命令／控制发布可靠故障结果。
已进入提交的磁盘事务仍完成，不删除其载荷；故障回执不宣称磁盘完全未变，
重新打开目录时按既有恢复规则核实提交。

#### M06c-2b-1 目录领取协议（2026-11-26，当前规则）

本节普通命令退休及结果消费协议已被[受控等待](#受控等待第-17-项)替代。
目录元数据分页和独立载荷确认继续有效，身份无需递增。

`ListDirectory` 沿普通命令流提交，以 `command_seq` 为查询作业身份；
接收前同时预留磁盘槽位、可靠终态和一个目录载荷槽位。
磁盘槽位由保存与目录查询共用，一个未消费磁盘终态阻止下一磁盘作业；
目录槽位独立保留，因此消费目录终态后可以保存，但旧目录未确认时不能再查询。
不启用持久化的运行时整批拒绝目录请求；同载荷重试不再读盘。

I/O 返回纯目录，世界线程在同一 mailbox 发布中安装载荷及
`DirectoryReady { job_id, directory_sequence, entry_count }`；
固定失败结果为 `DirectoryFailed { job_id, error }`。
目录载荷最多 1024 条、2 MiB，`Limits.directory_count`／`directory_bytes`
可分别缩小。条目按 96 字节固定元数据加 ID、载荷 ID、档名、世界名的 UTF-8 字节计费，
不按压缩索引大小计费。超载荷预算时发布固定 `Failed`，释放目录预留；
失败终态仍占磁盘槽位直到消费。
现有磁盘索引的格式上限与该内存／传输预算分别检查，不把大目录塞进可靠回执。

`poll_directory(epoch, job_id, offset, DirectoryLimits)` 只用非阻塞锁访问保留内存，
每页最多 64 条、64 KiB，可用参数缩小；按完整条目克隆并报告实际字节、
下一偏移和总条数。单条放不下返回 `InvalidArgument`，不丢弃载荷。
同身份／偏移／预算重取同页；偏移等于总数返回空页，未来偏移拒绝。
未完成请求返回 `NotReady`，错误身份或已释放载荷返回 `InvalidArgument`，
旧 epoch 返回 `StaleEpoch`；锁竞争返回 `Busy`，关闭后拒绝访问。

`ack_directory(epoch, job_id)` 显式释放已就绪目录，允许重复或延迟旧确认，
旧确认不能丢弃较新的目录；未就绪确认返回 `NotReady`。
目录确认不消费可靠终态、退休普通命令或提前释放磁盘槽位；
可靠终态确认也不丢弃目录，两个确认可按任意先后顺序执行。
保留目录是该查询时的快照，后续保存不会改变它。
目录复用保存的可靠取消控制和子 I/O 回收规则；
取消在终态发布前胜出时丢弃载荷并发布取消失败，已就绪目录的取消返回太迟。

[目录分页记录](../../reviews/2026-11-25-alpha-2-start.md#m06c-2b-1目录保留与分页2026-11-26)。

2. 从提交准备请求被接收开始，到切换确认完成，冻结新的普通命令；

5. 先以失败测试覆盖决定／取消两种顺序、控制额度不足、准备回执消费后决定、

共 40 字节，后跟 DEFLATE 数据；index／session 内部是 Godot `var_to_bytes` 数据。
方块差量有局部 uint16 索引与 uint8 方块，
格式 4 物流 `packed == 1` 的机器行长 136 字节，拓扑使用 PackedInt32Array。
字段和当前有效校验规则见 [011](../prealpha-1/011-pressure-save.md#编码与范围)及源码。

旧档迁移完全在 Rust 正常运行路径内完成：

1. 用现有 Godot 写端生成小型黄金文件，覆盖格式 1／2／3／4、字典／packed 机器、
   默认／连续运输、坡道、多格结构、中文名称、空档和待接缝。
   核对实际 DEFLATE 包装形式、Variant／typed 容器标记、浮点编码、精度、对齐和尾字节，
   包含非零时间余量／补偿及边界补充结算状态。
2. Rust 实现**只支持存档实际用到类型**的 Godot 4.7.2 Variant 白名单解码器：
   标量、字符串、所需向量、数组／字典、实际 PackedArray 类型等；
   禁止对象实例化、限制深度／长度，未支持类型明确拒绝，不实现通用 Godot 运行时。
3. Rust 解包、校验并规范化旧数据，按格式保留原始世界范围与所有身份／相位。
   老档后端字段映射到 [001 的规则集](001-rust-backend-refactor.md#规则继承与语言切换)，
   缺省字段按对应旧版本规则处理，不根据扩展安装状态改选。
4. 原连续档的原生快照由兼容版本 RustConveyor 校验／恢复；
   如果该原生格式不兼容，报告版本错误并保留源档，不能把它当空运输重建。
   来源方向及绑定资料全部核对，显示几何在 Rust 中重建。
5. 候选世界经过完整校验与继续演化比对后，可加载并另写格式 5 载荷。
   **读取／导入不覆盖旧文件**；迁移失败不影响旧档和活动世界。

Godot 解码器在测试中作为旧格式参考，与 Rust 的接受／拒绝和字段结果对照；
最终正常游戏不得用“先在 GDScript 解整个档，再交给 Rust”作为兼容实现。
黄金文件小而有代表性，不能将玩家百万档整包纳入仓库。
旧档目录与新目录由 Rust 统一列出，条目明确版本和迁移身份；
导入采用稳定源世界 ID／载荷摘要关联，重复导入不制造不可辨认的同名条目。
旧列表删除可作为受控独立操作，但默认导入永远保留旧源。

### 格式 5 初版编码约定

使用手工排列字段的小端编码，复用 SHA-256 和 DEFLATE 库，
不序列化 Rust 内存布局或 Godot Variant。总文件与总解压预算均为 512 MiB；
单区段受总预算约束，计数另受有限世界范围约束。此为编码边界，
不构成百万世界性能验收。

固定头 128 字节，依次为：magic 八字节 `PFSAVE5\0`、容器版本 `u32=5`、
头与区段表总长 `u32`、区段数 `u32`、保留标志 `u32=0`、文件总长 `u64`、
世界 ID 十六字节、规则集 `u32`（离散 0／连续 1）、规则版本 `u32=1`、
tick `u64`、模拟时间 `f64`、工厂修订 `u64`、玩家帧 `u64`、保留零字节八个、
整体 SHA-256 三十二字节（偏移 96～127）。
整体 SHA 覆盖全部文件，头中 SHA 字段先清零。

每个区段描述 96 字节，依次为 kind／schema／flags／compression（各 `u32`，flags=1 表示必需）、
offset／stored length／raw length／record count（各 `u64`）、原始 SHA 三十二字节、
保留字节十六个零。六个必需区段分别为世界、设备、运输、拓扑、时钟与账目、
玩家与会话，schema 初版为 1；record count=1 表示聚合区段，内部集合另带计数。
原生运输版本独立写入运输区段并由库校验。
压缩枚举为 none 0／raw deflate 1，DEFLATE 等级 3，仅在确实缩小时使用。
所有区段连续排列、不重叠；计数、长度、枚举、保留位、尾部和语义均须校验。
基础类型：Cell 为 x／y／z 三个 `i32`，向量为三个 `f64`，布尔为 `u8` 的 0／1；
bytes 为 `u64` 长度后接原始字节，string 为该 bytes 布局的 UTF-8。
方向编码与设备方向采用南／西／北／东 0～3；原生端口采用北／东／南／西 0～3，
空槽为 255，两种方向不得互换。以下字段按表内顺序连续写入，无隐含对齐。

| kind | schema 1 的原始区段字段 |
| --- | --- |
| 1 世界 | minimum Cell、maximum Cell、floor depth `i32`、flat bool、world revision `u64`、next structure ID `u64`；chunk count `u64`，每行 chunk Cell、差量 bytes（每记录本地索引 `u16`＋方块 `u8`）；structure count `u64`，每行 ID `u64`、anchor Cell、rotation `u8` |
| 2 设备 | machine count `u64`，按实际机器顺序写每行：Cell、block／direction／settled 各 `u8`；quantity／eligible／last output 各 `i64`；interval `f64`、amount `i64`、next deadline `f64`、input cursor `u64`、placed `f64`、cycles `i64`；ore count `u64`，每矿石 ID `u64`、incoming／outgoing 各 `u8`、progress `f64`；outgoing index 和三个 input index 各 `u64`，无连接为 `u64::MAX`；stop tick `i64`，未发生生产停产时为 -1 |
| 3 运输 | 离散为空；连续为 native version `u32`、原生 snapshot bytes。实际队列、树、预订、物品水位及原生设备状态由 RustConveyor 的版本化格式负责 |
| 4 拓扑 | 离散为空；连续为 port count `u64`，每行三维 Cell、三个 input side 和三个 output side 各 `u8`，保留原生槽顺序 |
| 5 时钟与账目 | 外层 factory revision `u64`、next request `u64`、规则层 bytes。离散规则层为 layout clock；连续规则层为 layout clock bytes＋连续账目。layout clock 依次是 settings interval `f64`、amount `i64`、time／compensation 各 `f64`、tick／flushed 各 `i64`、next item ID `u64`、dirty bool、layout 账目。每份账目是 initial／produced／removed 各 `i64`、created／retired 各 `u64` |
| 6 玩家与会话 | world ID 十六字节、world name string、autosave minutes `f64`、retention `u32`、player frame `u64`；position／velocity／spawn／body rotation／view rotation 五个向量；tool／build rotation 各 `u8`、free view bool、free position／free rotation 两个向量 |

固定空离散检查点输入及容器 SHA-256 冻结在
[`tests/persistence.rs`](../../../rust/factory_core/tests/persistence.rs)；
同时独立断言 magic、头长、区段数、世界身份、玩家帧和保留位。
矿机截止时间须与参数、放置时间和已完成周期一致；
周期与截止时间一起回退也须拒绝，不能以合法 SHA 接受重复生产或永久停产的伪相位。
浮点停产使用保存的历史 stop tick 核对实际结算周期及截止时间失去增长的条件，
不能用保存时更晚的 tick 证明旧周期停产；合法停产之后的存档仍可恢复。

### 目录提交与恢复

不可变载荷使用新身份文件，先写唯一临时文件、同步，再从磁盘重读校验完整容器。
目录使用两个带 SHA 的版本化索引，索引带递增序列、条目身份与载荷身份、名称、
世界身份、规则、时间和种类；索引原子 rename 为可见提交点，再同步目录才报告成功。
保留另一份有效索引，以及两份索引仍引用的所有载荷；新载荷不覆盖旧载荷。
恢复选最近完整有效索引，坏索引回退，孤立载荷不成为继续点。
继续点沿用最近有效保存语义，加载不隐式改写目录。
索引已可见但目录同步失败时返回提交不确定，并阻止进一步修改，恢复与重新同步确认后解除。
根目录内操作按文件锁串行化，覆盖／删除携带预期目录序列；文件名不接受显示名称或任意路径。
坏索引（包括超限索引）参与无效 bank 判定，不阻断另一 bank 的回退。
新实例或缓存索引指纹变化时，在锁内重新核对索引载荷并同步目录；
瞬时锁竞争只使当次请求失败，后续请求可重试。取消在调用方领取非提交终态前仍有效，
已成功取消的 Loaded 结果不得产生可提交候选。

### 同步试玩桥接

握手报告 `persistence=true`、`checkpoint_jobs`；`background=false` 仍表示世界没有迁入后台线程。
上句描述同步切片的原能力声明；当前小工厂已由
[后台试玩接入](#后台试玩输入与动态物流接入2026-11-27当前规则)改用世界线程。
保留的 `background=false` 表示完整迁移能力门槛尚未通过，不再判断独立试玩的线程归属；
同步对照实例仍在调用线程运行。
`configure_persistence(absolute_root)` 只注入目录，后台 I/O 服务最多一个作业。
`request_save_list()`、`request_save(session, {name, overwrite, kind, sequence})`、
`request_load(id)` 和 `request_delete_save(id, sequence)` 返回 job ID；
`poll_save_job()` 返回阶段或可靠终态，`cancel_save_job(id)` 返回是否接受取消。
加载先返回 `Prepared` 与候选观察／会话，Godot 准备完整离线显示和碰撞后调用
`commit_prepared_load(id)`；候选失败或取消不改活动世界。
保存只跨桥接传入小型玩家／会话值，Rust 内部捕获世界；
候选观察沿用当前整世界同步显示边界，本切片尚未提供分页／百万世界加载验收。
独立 CLI 的 `validate-save <file.pfs> [ticks]` 校验并恢复真实档案，
可在新进程继续指定 tick 数用于离线验收。
