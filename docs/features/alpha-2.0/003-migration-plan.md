# 003：分阶段迁移、验收与新对话交接

所属版本：**alpha-2.0**。状态：**待实施计划；M00～M15 均未开始**。
日期：2026-11-25。读者：新对话中的实施智能体、开发者和独立审查者。
目标与模块边界见 [001](001-rust-backend-refactor.md)，
通信、时钟、存档和旧档兼容见 [002](002-backend-protocol-and-persistence.md)。
本文件管理实施顺序与验收，不重复维护玩法或格式字段。

## 接手时先确认什么

按 [AGENTS](../../../AGENTS.md)阅读 README、对应版本规格与实际工作树。
README 当前阶段仍是 prealpha-2；alpha-2.0 文档存在不表示已实现或已切换阶段。
计划制定时 `prototypes/rust_world/` 是独立静态实验，不能当成完整后端起点。
RustConveyor 已承担可选连续运输，Godot 仍拥有世界、拓扑、生产、库存和存档。

先区分本次文档、此前静态原型及其他用户未提交修改，保留全部现有工作；
查明实际分支／源码／安装扩展来源，不假设当前二进制来自当前 RustConveyor 源码。
开始业务实现时使用功能分支，必要时隔离 worktree；不擅自提交、推送或迁移旧档。
运行命令及实时编辑器约束以 [开发说明](../../development.md)为准。
两个 vendored `addons/` 和 `.godot/` 生成文件不在重构修改范围。

实施者可以修正本计划的算法和小任务划分，但须保留用户目标、兼容边界与验收证据。
发现方案不成立时写明证据、调整所属条款，然后实施；不把每个合理实现选择都变成审批点。
显著玩法变化、删除无法替代的用户能力等范围变化需要明确说明，不能借“重构”悄悄执行。

## 切片策略与依赖

先证明完整小工厂的 Rust 规则和旧档可解释，再接 Godot；
先同步验证最小链路，再把独占世界搬到后台；
最后替换真实保存／加载、移除默认热路径上的旧权威状态。
每个检查点保持可运行，Godot 旧后端在过渡期作为对照和故障定位入口。
新后端测试路径缺扩展时必须报错，不能偷偷跑旧脚本而让测试假通过。

```text
M00 基线
  └─ M01 workspace／格式夹具
       ├─ M02 世界与结构 ── M03 建造和查询
       └─ M04 工厂与两套规则（同时依赖 M02）
             └─ M05 同步小工厂 Godot 链路（依赖 M03）
                  └─ M06 后台时钟／可靠通信
                       ├─ M07 局部网格、碰撞与物品显示
                       └─ M08 完整快照与格式 5
                            └─ M09 原子保存与目录
                                 └─ M10 staged 加载（依赖 M07）
                                      └─ M11 旧档导入
M03 + M04 + M06 + M07 ── M12 全部规则操作与 UI 接管
M07 + M11 + M12 ── M13 增量编辑与内存检查点
M13 ── M14 全规模验收 ── M15 默认切换／清理／交付
```

M07 与 M08、M11 的纯解码部分与 M12 的输入／查询适配可在协议和接口稳定后并行，
M12 的完整验收必须等待 M07 的碰撞和表现交付；
但共享世界结构、序列协议和迁移格式由同一接口契约约束。
不要让两个实现者同时修改核心协议；并行适用于已有输入／输出边界的独立切片。
S／M／L 表示相对规模，不是工期承诺；L 必须拆成单独可验证的小变更。
每项除下表验收外，都需针对性测试、独立审查和对应文档状态更新。

## 任务与可执行验收

### M00：重新建立当前基线（M，无依赖）

交付：当前默认与连续规则的行为夹具、完整存读档／挂载阶段测量、
来源记录，以及 [001 候选预算](001-rust-backend-refactor.md#验收与候选性能预算)的校准结论。
涉及 `scripts/pressure_*`、`run_native_pressure.sh`、报告检查器及已有基准入口。

1. 冻结输入夹具、两仓库源码指纹、安装库哈希、Godot／Rust 版本、相机／视图参数；
   采用当前保存去重实现，旧记录只作对照，静态原型不能替代完整工厂。
2. 分别量生成、快照、编码、压缩、写入／同步、磁盘校验、独立进程读档、规则恢复、
   Godot 挂载、首个可操作帧与稳定运行；嵌套时间不得相加重复计费。
3. 默认规则百万窗口也尝试有界测量；超时／内存限制保留原因与已有阶段样本，
   不无限补跑、不宣称已有完整默认百万基线。小型规则对照必须有效。

### M01：Rust workspace、桥接能力和黄金输入（M，依赖 M00）

交付：`rust/` 三 crate、锁定依赖与构建来源、最小能力握手、旧档黄金文件。
参考 RustConveyor 当前公共 API、Godot 桥接／安装入口，复用独立包而非复制源码。

1. `factory_core`／`factory_cli` 无 Godot 依赖；扩展能在 Godot 4.7.2 加载、关闭，
   协议版本或缺库必须返回明确错误；新类名与旧运输扩展不冲突。
2. 生成且验证格式 1～4 小型夹具，记录旧 Variant／DEFLATE 实际布局与规则来源；
   fixtures 不含玩家数据，旧写端只作为 oracle，不改其现行保存规则。
3. 锁定版本、许可证、编译模式和最小平台支持；可从干净环境安装到隔离项目，
   不提交库、固定端口、本机绝对路径或令牌。

### M02：有限世界、占用和结构（M，依赖 M01）

交付：`factory_core::world`／`entities`，替代的数据来源为
`voxel_world_data.gd` 及现有结构规则／测试。

1. 验证世界边界、地下层数、基岩、区块差量、32³ 索引、负坐标和地形推导；
   与现有小世界逐格结果核对，不因不同布局改变可建造范围。
2. 多格结构放置、旋转、底面吸附、挖任意格整座拆除与占用冲突保持原行为，
   原子失败无残留，逻辑身份失效不能命中新设备。
3. 验证百万级方块与大量设备的数据字节／构建数量，
   未编辑地形不物化完整逐格对象；快照读者不会看到半次编辑。

### M03：射线、线路与建造事务（L，依赖 M02）

交付：`queries` 和建造命令，来源为 `voxel_raycast.gd`、现有线路规划与建造测试。
先射线和单格，再坡道／直角线路，再跨结构占用的完整事务。

1. 射线端点、距离、格面、非法向量与负坐标正确；预览查询有修订／请求身份且有长度上限。
2. 继承四向、八种坡道、锁定路径、轴顺序、贴地与跨建筑规则，
   失败整条拒绝；长路径不能在 Godot 逐格重新验证。
3. 放置／拆除同时更新世界、结构、机器与待拓扑修改；
   未确认预览不是权威状态，旧修订提交重新校验。
   预检 token 携带玩家／镜头占用和姿态、拟抬升与净空结果，
   验证同批上层带、过期姿态和取消；Godot 物理确认与运动屏障在 M12 集成验收。

### M04：完整工厂与规则集（L，依赖 M01、M02）

交付：`topology`、`production`、`inventory`、`transport`。
来源为 `logistics_data.gd`、`logistics_topology.gd`、`logistics_machine.gd`、
生产调度、旧运输与 `rust_belt_transport.gd`。
拆为设备／库存、离散运输、连续适配、完整账目四个切片。

1. Rust CLI 的矿机→带→箱子可持续运行：检查生产相位、已成交库存、堵塞、
   轮询、物品身份、来源方向、坡道、合流和环路；没有 Godot 配额／消费回调。
2. `legacy_discrete_v1` 与旧默认小夹具逐 tick 比对可观察状态；
   `conveyor_continuous_v1` 核对原公共包语义、真实几何长度和等待接缝。
   保存所需的时间、调度和待结算状态都在 Rust。
3. 空网／碎片／长段、实际生产和消费均有工作量记录；
   同步阶段在当前执行线程内创建／使用 `Network`，M06 后由世界线程独占；
   不跨线程搬移活实例，不重写包的队列树。

### M05：Godot 同步小工厂链路（M，依赖 M03、M04）

交付：薄 `FactoryBackend` 与显式依赖注入；过渡开关选择新路径。
涉及 `factory_session.gd`、主场景协调和新增适配脚本，不先替换全部大场景。

1. 小世界通过命令建矿机→带→箱子，Godot 只显示 Rust 的设备／物品和统计，
   没有同时 tick 旧 `LogisticsData` 或保留第二套权威库存。
2. 非法输入、事务拒绝、查询响应、规则选择及关闭得到可诊断结果；
   桥接不泄漏 Rust 内部引用，不用每格／每物品跨语言调用。
3. 保持现有玩家、菜单和视角基本运行，实测过渡链路；
   同步阶段仅为证明接口，不能据此宣称后台或百万性能完成。
   该阶段实例归调用线程所有，M06 停止测试会话并在工作线程按相同夹具重新创建；
   不要求此时迁移运行现场，检查点恢复等待 M08。

### M06：后台执行、时钟与可靠协议（L，依赖 M05）

交付：`runtime`、有界队列、消费水位、时间屏障与生命周期。
以 [002 标识／时钟](002-backend-protocol-and-persistence.md#时钟与暂停)为验收，
先可靠命令，再时间／暂停，再 shutdown。

1. 满队列、重复请求、相同序号不同载荷、过期 epoch、结果页重试均不重复编辑／丢终态；
   接受前可靠输出额度预留、独立控制额度、result_seq 消费及命令退休窗口可测，
   长作业和停止 poll 时仍不会阻塞世界线程或无界增长。
2. 固定 tick、时间去重、合并、暂停／恢复、积压限制和保存姿态屏障一致；
   菜单可持续 poll，暂停不生产，catch-up 不无限占用工作线程。
   保留编辑发生时刻、余量／补偿／flushed，原时间事件流与 Busy 合并流等价重放；
   覆盖同边界多次编辑、边界内放矿机及暂停／保存之间的事件排序。
3. 独占世界与 I/O 线程启动／关闭符合归属，故障明确暂停；
   主线程无完整规则循环，关闭不留下工作线程或加载旧世界的消息。

### M07：Rust 表现数据与 Godot 流送（L，依赖 M06）

交付：`meshing`、局部候选／实例缓冲和 Godot 表现安装器。
涉及 `voxel_world_view.gd`、`logistics_view.gd`、矿石池与表面 shader 的现有验收。
先方块网格／邻面，再碰撞，再设备标记，最后动态矿石。

1. Rust CPU 数组与实际 `ArrayMesh`／碰撞一致，验证邻区编辑、结构、坡道、
   四向标记、遮挡面、负坐标及父节点变换；业务不在 Godot 逐格造顶点。
2. 动态批次成员、缓冲、AABB、容量／退休与身份保持正确，
   验证固定快照多页、漏页／超时恢复、进入／退出／跨批协调安装，
   生产快于领取时仍能完成一轮且无重复／丢失，宿主按批 `set_buffer`。
3. 相机与玩家碰撞范围独立，载入／重生／移动不穿未就绪地面；
   验证新建墙体、延迟碰撞安装、自由镜头平移／缩放／绕点旋转，
   扫掠范围修订未覆盖时正确限制运动或采用 Rust 数据扫掠。
   固定与移动图形窗口、日志和截图验收，随后停止游戏。

### M08：一致快照与格式 5（L，依赖 M06）

交付：`snapshot` 与 engine-free 编码器／解码器，更新 002 的逐字节格式与上限。
先内存一致检查点，再区段容器，再坏档／精度验收。

1. 生产／库存／拓扑／原生或离散运输／身份／时间／玩家屏障同刻，
   保存后原世界继续运行；恢复后继续演化一致，不用生成公式替代矿石。
   玩家位置、速度、出生点、视角、工具、建造朝向和时间补偿／flushed 逐项恢复验收。
2. 格式可由 `factory_cli` 独立读取，长度／枚举／重叠／截断／溢出／版本／SHA
   全部检验，语义坏档在候选世界拒绝。兼容版本和精度有小型黄金文件。
3. Godot 不接收全量快照；记录快照暂停、实际复制、编码和内存峰值，
   native 快照时间不能隐藏在 I/O 中。

### M09：目录、异步保存与恢复（L，依赖 M08）

交付：`storage` 与 Rust 目录页、命名／覆盖／自动保存／删除。
参考 `save_game_files.gd`、`save_game_store.gd` 的当前用户语义。

1. 保存必须实际磁盘重读校验后持久提交；每个写／同步／rename／索引切换点
   注入失败或中断，重新启动可恢复最近有效档，失败不先淘汰旧自动档。
   索引已可见、目录同步失败的窗口进入 CommitUncertain，
   取消不能删除其载荷，恢复后新旧提交都不能有悬空引用。
   不确定状态阻止该目录全部索引／继续点修改，
   验证新增保存、自动保存、导入登记与加载后的最近条目更新也不能绕过屏障。
2. 名称、ID、目录序列、覆盖／删除确认及分页正确；
   根目录约束、并发操作、取消与提交竞态可测，保存并退出等终态。
3. 保存快照／待办数量有界，正常路径不调用 Godot 压缩、解析或导出世界；
   独立进程保存／重启比对真实内容物与继续演化。

### M10：staged 加载与会话交接（L，依赖 M07、M09）

交付：候选世界 token、附近表现屏障与 Godot 主场景原子切换。
涉及会话生命周期、暂停、主菜单、重生和加载进度。

1. 读取、验证、建实例到附近表现就绪均有阶段；提交决定前失败／取消保留旧世界和脚下碰撞，
   旧暂停状态可恢复，不先清空场景等待后端。
2. 成功一次交接 epoch、玩家姿态、世界／物品表现与 UI；
   世界线程串行决定提交／取消，Prepared／CommitDecided／SwitchApplied 幂等重取，
   旧消息无效，首个输入帧有碰撞；决定后取消不回滚，完成确认后才释放旧世界。
3. 独立进程完整加载与取消／故障路径核对，
   测量旧／候选世界资源重叠峰值、首次可操作和全部请求场景就绪。

### M11：旧格式 1～4 的 Rust 导入（L，依赖 M10）

交付：`legacy` 白名单 Variant 解析、规范化、规则保留及旧／新目录共存。
纯解析可提前在 M01 夹具上开发；最终加载接入以 M10 完成为前提。

1. Godot oracle 与 Rust 的合法／非法夹具结果一致，覆盖字典／packed、旧边界、
   中文、结构、坡道、两规则集与连续原生版本；禁止对象解码与无限递归／解压。
2. 旧档加载后继续演化保持对应规则，全部身份、来源、时间与待结算状态合法；
   不支持的版本明确拒绝，不当成空网络或静默换规则。
3. 导入另存格式 5，源档字节不变，重复导入有稳定关联；
   游戏不依赖 GDScript 全档解码或把全档穿过桥接。

### M12：全部规则操作与 UI 接管（L，依赖 M03、M04、M06、M07）

交付：所有玩家规则操作、预览、设备／库存查询和配置到 Rust 的边界。
涉及 `scripts/player/`、`scripts/ui/`、主场景协调及配置 Resource 注入。

1. 单格／结构／线路建造、拆除、旋转、查询均以 Rust 结果为准；
   工具、输入焦点、库存、自由镜头、菜单仍按现有用户行为运行。
2. 参数由 Godot 编辑资源显式转成启动配置，Rust 验证并持有规则参数；
   `Resource.changed` 的运行时更新分别进入兴趣订阅／有序规则配置命令：
   距离／高度下一次刷新生效，生产参数只影响后来放置的矿机，
   已有矿机保留参数快照，非法值、实例隔离和不自动写回资源按 005 验收。
   玩家物理由 Godot 执行，姿态／重生候选／碰撞准备协作不留隐含全局状态。
3. 关闭 UI 释放订阅，详情只有局部页面，未确认建造与过期预览不伪装已提交；
   类型检查、输入／物理集成和真实窗口操作全部验收。
   建造期间移动／切换镜头、同批上层带、抬升净空、延迟碰撞及提交／取消竞态
   按 002 的姿态事务测试，完成碰撞安装／抬升前不恢复相关运动。

### M13：增量编辑与单份状态内存检查点（L，依赖 M07、M11、M12）

交付：去除普通编辑的全厂物化，内存与工作量审计；
已有 RustConveyor split／join／remove 能力优先复用。

1. 局部编辑只修改受影响区块、设备、路径与接缝；
   若需要访问整条受影响分量，明确记录访问规模，不声称严格 O(1)。
2. 连续生产／消费、批量删除、长段中间拆带／接带、重复保存加载和 UI 开关后，
   身份／库存守恒且缓存退休，内存不随次数无界增长。
3. Godot 常态没有全厂设备／矿石／拓扑副本，Rust 派生索引／快照／队列也有字节审计；
   万级和复杂工厂不因多层缓存出现可重复的时间／RSS 回退。

### M14：全规模、兼容与产品验收（L，依赖 M13）

交付：三轮有效矩阵、全功能验证、独立审查与有范围的历史证据。
按下节口径执行，优化只针对已观测热点，不能再次无限搜索组合。

1. 两规则集的小／中／百万及复杂工厂、独立保存／加载、长期编辑／生产和 restart
   验证；旧档成功／拒绝、故障恢复与数量／身份／时间账目完整。
2. headless 核心／宿主与真实图形固定／移动窗口分列，
   来源、工作量、实际绘制、阶段 CPU／帧间隔／RSS及原始样本齐全。
3. 候选预算和回退门槛逐项给结论；缺样本、不可用平台或实时编辑器明确限制，
   未达标项不写成已验收，也不以静态实验或历史测试填补。

### M15：默认切换、旧路径清理与交付（M，依赖 M14）

交付：默认完整 Rust 后端、可复现安装／CI、受影响规格的替代链接与 README 阶段声明。
具体切换门槛见 [最终切换](#最终切换与交付)。

1. 正常游戏不再创建完整 GDScript 世界／工厂／存档规则对象，
   原型与旧测试 oracle 只作为明确的开发材料；缺少完整后端库明确报错。
2. 删除已证实无用的重复热路径，保留仍被玩家物理、输入或兼容测试使用的代码；
   列出保留理由，禁止为凑“全 Rust”把 Godot 引擎职责搬走。
   旧纯规则测试的行为验收转入 Rust，场景／输入／物理验收保留在 Godot；
   不能随旧实现删除其唯一验收，oracle 的保留不代表旧规则继续进入正常运行。
3. 全检查、独立审查和图形验收通过后才更新阶段与旧条款替代标识，
   安装与测试无需本机路径／预装库，未验证平台不声明支持。
   若切换／清理改变 M14 已测执行路径、构建配置或初始化对象，
   重测受影响性能项并记录最终源码／库来源，不能沿用切换前成绩。

## 测量与停止条件

基准对象是完整工厂：方块、矿机、传送带、矿石、箱子、库存、时间与真实存档。
夹具须记录实际设备／物品数、拓扑、运行 tick、成交／产消量和可见返回数；
“百万”指百万量级传送带的有限世界，不能指加载一百万次或百万个静态空方块。
继承压力生成规则，复杂夹具增加碎片、合流、环路和持续来源／汇，不把一种长蛇形当全项目。

测量遵循：

- 同机器、release 库、冻结输入和相机；至少万级、十万级、百万及复杂工厂，
  两规则集分列，同条件三轮有效样本。当前工具原有更多尺度可保留。
- 普通运行预热 120 tick、测量 300 tick；另设长期生产／消费与重复编辑／存读档窗口。
  冷／热缓存分别标注，独立进程读档不能用内存快照代替。
- 分列核心、桥接、Godot 安装／上传、引擎帧间隔、首次可操作及全部挂载；
  计时窗口外的生成、审计、截图和报告写入也记录成本，不混入模拟 tick。
- 记录每 tick 实际工作和队列／区段访问数，避免通过少算生产、少显示物品证明加速。
  三轮报告中位数、p95／最大值及分轮差异，保存／加载总时长单列。
- RSS 为完整真实进程稳定／峰值，Rust CLI 与游戏不同口径；
  `/usr/bin/time -l` 可采峰值，阶段采样用经校准的 OS API。
  macOS 某些 `ps` 返回零时标为不可用，必要时用 `proc_pidinfo`，不把零当低内存。

M00 为各尺度设置超时／内存停止线。后续超线一次保留未完成阶段，
定位后最多进行有明确假设的复测；两个连续无收益候选就结束该优化方向。
基线缺失则标注绝对预算与比较限制，不能编造倍率。
没有可靠收益或出现小规模／复杂工厂回退的方案不进入最终组合。
正确性失败先修规则，再谈性能；未达性能预算需要明确报告并收敛范围，
不无限运行矩阵直到出现漂亮样本。

## 验证命令与证据

现有 Godot 完整验证继续使用：

```bash
bash scripts/verify.sh
```

以下 Rust／安装命令是**拟新增入口，M01／M15 实现后才可执行**：

```bash
cargo test --manifest-path rust/Cargo.toml --workspace
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets -- -D warnings
bash rust/install.sh /path/to/isolated-godot-project release
```

`factory_cli` 至少提供生成、重放、check-save、import-legacy、benchmark 子命令，
其精确参数在实现时写入 [开发说明](../../development.md)，不要让本文件与操作说明竞争。
RustConveyor 包验证在其仓库按实际 workspace 命令执行；
只有需要公共 API 变更才修改包仓库，并分开审查。
现有 native 压测工具测的是旧职责边界，需在 M00／M14 显式适配新后端后才能用于 alpha 验收。

每个游戏切片：先相关失败测试确认 RED，最小实现 GREEN，再相关回归；
独立 subagent 先读验收／测试后审查实现，处理 Critical／Important 后复验。
完整游戏改动运行 `verify.sh`；Rust 格式、静态检查与核心／桥接测试适用时全部执行。
直接改脚本／场景触发编辑器扫描；改 `.tscn` 后显式保存并立即完整验证。
视觉批次先确认 Godot AI 当前项目，读取目标场景，运行日志和截图，结束停止游戏。
实时连接不可用时用无头及独立图形进程说明范围，不虚构编辑器或独立审查。

简短证据写入 `docs/reviews/`，注明日期、变更范围、测试／测量入口、
发现及处理、来源与限制；完整日志、报告和压力档留在工具输出目录，不手工抄成现状。
纯文档检查本地路径／锚点、继承／替代一致性、diff 和独立审查，不运行游戏矩阵充数。
