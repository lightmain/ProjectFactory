## 切片策略与依赖

先证明完整小工厂的 Rust 规则和旧档可解释，再接 Godot；
先同步验证最小链路，再把独占世界搬到后台；
最后替换真实保存／加载、移除默认热路径上的旧权威状态。
每个检查点保持可运行，Godot 旧后端在过渡期作为对照和故障定位入口。
新后端测试路径缺扩展时必须报错，不能偷偷跑旧脚本而让测试假通过。

```text
M00 基线
  └─ M01 workspace／格式夹具
       ├─ M02 世界与结构 ── M03 建造和查询
       └─ M04 工厂与两套规则（同时依赖 M02）
             └─ M05 同步小工厂 Godot 链路（依赖 M03）
                  └─ M06 后台时钟／可靠通信
                       ├─ M07 局部网格、碰撞与物品显示
                       └─ M08 完整快照与格式 5
                            └─ M09 原子保存与目录
                                 └─ M10 staged 加载（依赖 M07）
                                      └─ M11 旧档导入
M03 + M04 + M06 + M07 ── M12 全部规则操作与 UI 接管
M07 + M11 + M12 ── M13 增量编辑与内存检查点
M13 ── M14 全规模验收 ── M15 默认切换／清理／交付
```

M07 与 M08、M11 的纯解码部分与 M12 的输入／查询适配可在协议和接口稳定后并行，
M12 的完整验收必须等待 M07 的碰撞和表现交付；
但共享世界结构、序列协议和迁移格式由同一接口契约约束。
不要让两个实现者同时修改核心协议；并行适用于已有输入／输出边界的独立切片。
S／M／L 表示相对规模，不是工期承诺；L 必须拆成单独可验证的小变更。
每项除下表验收外，都需针对性测试、独立审查和对应文档状态更新。

后续验收执行 [001 的用户范围调整](001-rust-backend-refactor.md#需求判断与边界)：
正常游玩与完整链路优先；人工极端数值样本不阻断交付；

实施切片（射线、纯线路几何及端口／前缀已 RED／GREEN，独立 Godot 对照通过；
线路几何与端口／前缀独立复审通过；射线多轮数值边界问题已修复，

- **M03a**：有界格子射线、薄平带与坡道实体命中、格面／端点及负坐标。
  与当前 Godot 射线结果独立对照；非法输入在遍历前拒绝，
  遥远起点先裁剪到有限世界，避免按无界距离逐格扫描。
  普通坐标使用补偿浮点；溢出或极小乘积保留有限输入的精确值，
  在归一化分量下溢时延后除法，保持格面侧别与有限距离交点。
  同时到达格面的轴按 X／Y／Z 顺序处理；双精度中相差不超过 `1e-12` 米
  的遍历距离按平局处理。旧 Godot 的单精度累计可在三轴切角处反转这个顺序，
  新实现保持上述明确顺序；此数值边界差异用两个切角验收单独固定，
  多轴 oracle 样本避开该不稳定切角，普通射线仍逐项核对格面与距离。
- **M03b**：保留双轴顺序的路径足迹与最低合法高度求解，
  然后接四向端口、坡道、锁定前缀和跨结构净空；长度上限先于分配。
  纯几何入口接受调用方长度额度，硬上限为继承的最大世界体积 `128³` 格；
  非法额度、超长足迹与不匹配高度数组在分配前拒绝。
  该上限覆盖世界内任意不自交路线，跨语言预览仍需 M06 的字节额度／分页，
  不能把核心可求解长度直接当作单次桥接预算。
  端口／前缀切片使用只读世界和显式机器朝向查询；空格没有机器朝向，
  坡道朝向固定为南／西／北／东，下坡入口高一格、上坡出口高一格。
  C 后的末下坡从前方出口格续接，刷新原终点保持原路径；
  直线空终点可贡献最后一次下降，转角不能贡献坡道容量。
  预览、锁定、切换轴序和取消均不修改世界，长度额度覆盖完整前缀与后缀，
  虚拟终点的内部高度数组也受硬上限约束。预览后世界、起点出口或终点入口
  改变时重新验证并拒绝失效路径；真正提交在 M03c／M04 原子更新工厂。
  C 锁定同样重验最新世界和机器朝向；失效时保留原前缀并记录错误，
  再次有效预览后可继续锁定，避免把迟到障碍固化进不可改的前缀。
  验收覆盖四向下坡、重复锁定／切换轴序、固定机器口、跨带／结构、
  上下坡净空、自交、迟到障碍、世界边界和额度拒绝，并逐段独立核对 Godot 输出。
- **M03c**：预览请求／世界修订／姿态身份、取消与整批建造事务。

## 测量与停止条件

基准对象是完整工厂：方块、矿机、传送带、矿石、箱子、库存、时间与真实存档。
夹具须记录实际设备／物品数、拓扑、运行 tick、成交／产消量和可见返回数；
“百万”指百万量级传送带的有限世界，不能指加载一百万次或百万个静态空方块。
继承压力生成规则，复杂夹具增加碎片、合流、环路和持续来源／汇，不把一种长蛇形当全项目。

测量遵循：

- 同机器、release 库、冻结输入和相机；至少万级、十万级、百万及复杂工厂，
  两规则集分列，同条件三轮有效样本。当前工具原有更多尺度可保留。
- 普通运行预热 120 tick、测量 300 tick；另设长期生产／消费与重复编辑／存读档窗口。
  冷／热缓存分别标注，独立进程读档不能用内存快照代替。
- 分列核心、桥接、Godot 安装／上传、引擎帧间隔、首次可操作及全部挂载；
  计时窗口外的生成、审计、截图和报告写入也记录成本，不混入模拟 tick。
- 记录每 tick 实际工作和队列／区段访问数，避免通过少算生产、少显示物品证明加速。
  三轮报告中位数、p95／最大值及分轮差异，保存／加载总时长单列。
- RSS 为完整真实进程稳定／峰值，Rust CLI 与游戏不同口径；
  `/usr/bin/time -l` 可采峰值，阶段采样用经校准的 OS API。
  macOS 某些 `ps` 返回零时标为不可用，必要时用 `proc_pidinfo`，不把零当低内存。

M00 为各尺度设置超时／内存停止线。后续超线一次保留未完成阶段，
定位后最多进行有明确假设的复测；两个连续无收益候选就结束该优化方向。
基线缺失则标注绝对预算与比较限制，不能编造倍率。
没有可靠收益或出现小规模／复杂工厂回退的方案不进入最终组合。
正确性失败先修规则，再谈性能；未达性能预算需要明确报告并收敛范围，
不无限运行矩阵直到出现漂亮样本。
