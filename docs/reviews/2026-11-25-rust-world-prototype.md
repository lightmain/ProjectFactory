## 实现

新增隔离的 `prototypes/rust_world/`，仅 Rust 与 Python 标准库。
最终世界由显式 `u16` 区块数组持有，支持直接读取、编辑、增量统计、
流式存档与直接恢复。观察游标按范围求区块，输出完整进入／更新区块、
离开编号和统计；游标绑定独立世界身份。

命令生成一次夹具，再由独立进程加载、等待 RSS 握手、执行固定范围与编辑查询。
审计采用单独平铺参考和消息解码器，核对每条消息应用后的完整可见区块；
编辑审计先于移动阶段，不以最终非空数或重新进入后的数据替代逐步正确性。
操作计时包含输出编码，消息记录与审计在计时外，整个进程峰值包含审计内存。

## 正式性能验收

正式报告在 `/tmp/factory-world-probe-20261125.CSHrrq/formal-rss/`：
`summary.json`、`runs.jsonl`、三份输入档与逐进程完整 stdout/stderr。
环境为 Apple M4 Pro、macOS 26.5.1 arm64、Rust 1.98.1；
按 Cargo 默认 release 参数构建，构建日志与二进制摘要关联本次操作。
驱动自身不构建二进制，报告明确将外部二进制的构建来源标为未自动认证。
同一二进制、源码与输入摘要在批次前后相同，三次生成诊断与九次独立 probe
均成功；总体状态 `a_passed`，预算失败列表为空。每轮两次全量审计与逐包审计通过。

前一批 `formal/` 在小样本首轮因 `ps` 返回零而停止，
状态 `measurement_incomplete`，不能作为成功样本。
保留该批的输入与原始日志；没有隐藏失败或填零补齐。
后备方法据 Darwin `sys/proc_info.h` 使用 `proc_pidinfo(PROC_PIDTASKINFO)`，
仅在返回完整结构且 `pti_resident_size > 0` 时有效。
完整重跑的九轮加载后 RSS 均通过该方法采集，报告保留方法和原始 `ps` 输出；
进程峰值仍来自 `/usr/bin/time -l` 的最大驻留集字节值。

最高进程峰值约 25.33 MiB，包含独立参考、消息记录和审计，并非只计算世界数组。
每种重复操作每轮保留 1,000 个样本及 p50/p95/最大值；
百万不变查询每轮 p95 为 42 ns，这类极短读数受时钟分辨率影响，
不能用其替代实际数据输出的耗时。

每轮首次查询访问 4 区块、读取 16,384 格、输出 32,860 字节；
三尺度相同。不变查询的 1,000 次合计访问 4,000 区块、
读取 0 格、输出 76,000 字节统计头。编辑查询访问 4,000 区块、
重发 1,000 区块、读取 4,096,000 格、输出 8,272,000 字节。
百万移动查询访问 5,876 区块，进入／离开各 124 块，
读取 507,904 格、输出 1,092,800 字节。边缘范围会相交 6 区块，
因此没有把移动查询都记成 4 区块，也没有扫描全部 256 区块。
这些实际工作量支持所选局部查询路径；三尺度计时本身不构成复杂度证明。

## 结论的适用范围

本实验只验证所选静态世界存储、恢复、局部访问与数据输出成本。
文件缓存未控制，加载不是冷盘测量，也不包含 Godot 的网格、碰撞、
FFI、首个可玩画面或运输模拟。不能据此把旧游戏约 63 秒的加载归因于语言效率，
也不能由 A 的结果宣称百万传送带可以实时运输。
