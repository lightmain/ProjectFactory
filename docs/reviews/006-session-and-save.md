## 独立审查及处理

独立子智能体先读规格和测试，再审查世界数据、规则快照、文件读写、
会话、输入及菜单。初次审查未发现确定的 Critical，提出四项 Important：

- 矿机周期号可与下一生产时刻矛盾：增加相位一致性校验。
- 已结算拓扑可缺失连接或混入待生效方向：验证完整邻接及方向一致性，
  待生效状态仍保留旧图。
- 矿石间距校验容差宽于求解器：统一为物流规则的时间容差。
- 快照产量上限小于配置支持范围：移除额外产量、数量及身份上限，
  采用 GDScript 整数范围，保留文件长度限制。

四项均补充失败用例，确认失败后修复，聚焦复验通过。
Optional 建议补充残留跳跃和语义非法但校验正确的文件：
已加入暂停期间按住跳跃、释放后再跳，以及未知版本不替换活动世界的测试。
复审确认相位、完整拓扑与整数范围三项关闭，但发现满载闭环可积累小于单带容差的
间距误差，导致首次采样断言。已补四带满载环失败用例，并增加整张图的零时间
位置可行性校验；校验不修改矿石状态。最终独立聚焦复审确认该剩余 Important
已关闭，未发现新增 Critical、Important 或 Optional；7 项快照测试复验通过。

## 2026-11-05：启动失败追查与验收更正

上述“隔离 Godot 环境”只隔离了引擎与报告位置；当时 `verify.sh` 仍在原项目
导入，未隔离编辑器缓存。开发中曾出现新类无法识别，重新导入后通过，
但未验证后续实时编辑器扫描会不会使问题复发，先前验收不足。

用户报告启动失败后，现场复现 `logistics_data.gd` 的
`Identifier "SnapshotValues" not declared in the current scope`。
新脚本存在于编辑器文件列表，但编辑器全局类表缺失五个新会话/快照类：
`FactorySession`、`SaveGameStore`、`SessionMenu`、`SessionSnapshot`、`SnapshotValues`。
原项目无头导入将磁盘类表从 286 补至 291，能暂时启动；只触发旧脚本的
文件时间变化并扫描，编辑器便把内存中的 286 项旧表写回，丢失新类。
扫描返回完成并不能证明缺失类型已注册。

修复验证流程的资源隔离：引擎只导入临时工作副本，复制未提交资源，
排除编辑器缓存、Git、本机配置与生成输出；类型检查根据当前启动配置
替换检查入口，移除旧 `main.tscn` 的写死匹配。
两项脚本回归先确认原缓存被改写、入口未替换的正确失败原因，再修复通过；
随后补充报告保留断言，发现 GdUnit 将绝对报告路径解释为项目资源路径，
改为临时副本旁的相对目录，副本清理后报告仍保留。

通过支持的编辑器退出/重开流程刷新现场类注册，未手改 `.godot/`。
重新连接 ProjectFactory，扫描确认 291 项注册，启动主菜单并请求 New World，
游戏和玩家正常挂载，检查主菜单及第一人称世界截图，编辑器与游戏日志无新增错误。
原生 macOS 键鼠验收限制仍适用；这次现场通过 Godot AI 菜单信号请求新世界。

独立子智能体先审回归与验收，再审此次验证脚本和开发说明；
最终复审无 Critical 或 Important，确认相对报告路径及保留断言关闭遗漏。
Optional 建议增加引擎非零退出、退出零但打印错误时的清理与日志保留用例；
此类用例尚未增加；现有 `run_checked` 错误输出检查仍在执行。

最终完整验证包含两项 Python 回归、业务类型检查、194 项 GdUnit4 测试及
启动场景 120 帧，全部通过；XML/HTML 报告实际留在临时副本旁，副本已删除。
验证前后原项目全局类缓存的 SHA-256 一致。完整验证后再次启动实时项目，
新世界、玩家与隐藏菜单状态正常，新增编辑器错误为零，游戏日志无错误。
另检查暂停与恢复成功；所有现场运行结束后已停止游戏。
受影响文档的本地链接及 `git diff --check` 通过。

## 2026-11-05：补充真实启动集成检查

用户进一步要求用集成测试防止启动回归。此前两项 Python 检查使用模拟引擎，
既有会话测试在已加载测试类的进程中实例化会话，不能覆盖独立游戏进程的入口加载。
新增 [启动探针](../../tests/integration/project_startup_probe.gd) 与
[执行器](../../scripts/check_startup.py)，接入完整验证前后两个独立真实引擎进程。

通过可见按钮信号进入新世界、确认第一人称玩家，再检查暂停与继续。

成功必须有标记，脚本错误、异常退出、超时和缺标记均失败；配置在退出时恢复。
原项目类表及文件系统缓存同时比较内容与修改时间。

编排回归先在旧流程缺少首次启动步骤时正确失败，再修复通过。
另外在临时副本进行两个真实引擎负控：
原项目式无头导入实际创建/改写缓存后，保护检查拒绝该变化；
将 `SnapshotValues` 注册名改为其他名字后，真实导入与启动报原类无法识别，
执行器拒绝启动结果。负控仅修改临时资源，未手工编辑 `.godot/`。

独立初审提出一项 Important：原缓存开始前就缺类时，只有不变性检查仍可能假绿。
已增加只读注册门禁，检查所有业务类的当前名称与路径并拒绝重复注册。
真实临时项目导入后再添加类但不重新导入，旧门禁确实接受该缺类状态；
修复后同一负控拒绝缺失类。新增合成注册表回归覆盖旧类名、错路径与正常注册。
同时处理 Optional：拒绝执行器指向原项目别名及未知阶段；
暂停改经玩家输入边界，恢复后检查处理状态、玩家控制与物理帧；
补充缺成功标记、退出零但有脚本错误、异常退出时的拒绝与配置恢复/日志保留回归。

独立聚焦复审确认 Important 已关闭，无新的 Critical 或 Important；
Optional 遗留为重复注册与参数拒绝的自动用例。未知阶段、同根别名的拒绝
另经执行器调用验证，配置未变化；同根判定使用文件系统身份以覆盖路径别名。
最终完整验证通过：四项 Python 回归、194 项 GdUnit4 测试、两次真实独立启动、
业务类型与主场景 120 帧检查；原缓存不变、原注册表完整。
完整验证后现场编辑器启动主菜单和新世界，新增错误为零，验证后停止游戏。
受影响文档的本地引用与 diff 检查通过。

这些检查覆盖磁盘注册缓存和独立进程启动，不直接读取编辑器内存中的类表；
