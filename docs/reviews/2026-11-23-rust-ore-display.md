## 实现与针对性验证

Godot 桥接缓存宿主提供的纯几何，返回矿石身份、最终三维位置与所属查询行。
显示缓存不进入运输快照；Godot 的 Rust 显示路径不创建临时
`LogisticsOreQueue`／`LogisticsOre`，不再逐颗计算三维位置。
规则、编辑、存档和默认 GDScript 后端继续使用原采样接口。
编辑、恢复和等待连边成功使显示缓存失效；普通 tick 保留几何。
首次绑定累计耗时独立记录，不从采样加速中隐去。

Rust 将同段精确相邻请求整理成批，复用内部精确边界定位。
新增 `Network.sample_adjacent_ranges` 共享相邻区间的边界定位，
各行仍只读取自身上限允许的矿石；不导出整个合并区间再按舍入位置拆行。
显示报告的 `queries` 是合并批次数，不代表一次常数成本查询。
排序约为 `O(R log R)`，边界定位和读取仍约为
`O((R + M) log I)`，其中 R 是请求行数、M 是实际返回矿石数、I 是段内矿石数。

Rust 三维与邻接采样测试先因最小桩返回零位置／错误而产生两个预期失败，
实现后通过；另补补偿边界测试：内部位置略小于、等于、略大于 0.5，
三者均返回舍入位置 0.5，但保持正确格子归属，恢复后也一致。
原生显示三项测试与公开运输契约 44 项测试通过；格式和 clippy 检查通过。
日志位于 RustConveyor 的 `.tmp/display-verification/`：
`rust-red.log`、`rust-green-expanded.log`、`package-api.log`、
`review-rust-green.log`、`review-clippy.log`。

Godot 新接口首次测试因缺少成批显示方法产生预期失败。
最终独立进程检查四向平带、八种坡道、端点与转弯来源，比较旧采样后
实际三维位置与新输出，使用精确 Vector3 等值；核对身份、行顺序、
重复请求、未知格子、返回上限、已知与未知入口、空请求、
非法几何拒绝的原子性，以及恢复、旋转和等待连边。
真实主场景渲染池核对高度等值可见、阈值下隐藏和三维变换。
此处主场景断言在无头进程运行，不能替代真实像素／窗口验证。
针对性日志 `godot-red.log`、`godot-final-targeted.log`、
`review-fixes-red.log`、`godot-reviewed-final.log`；
最终日志有成功标记且零 Godot 错误。
