## 2026-11-24：原生导出、入向和压缩的进入条件

使用 R02 的百万／复杂工厂隔离项目，从既有原始磁盘档恢复实际运输实例。
诊断日志和原始 JSON 位于当次临时输出目录
`native-million-diagnostic-v2.log`、`native-complex-diagnostic-v2.log`、
`native-million-diagnostic.json` 和 `native-complex-diagnostic.json`；
两项均打印成功标记且无解析／运行错误。早期相对脚本路径错误的日志仍保留，
引擎退出码为零不能将那两次失败认定为成功。

百万实例的原生检查点为 48,778,032 字节，同一进程内三次桥接导出分别为
172,648／170,117／173,320 微秒；独立原生实例恢复为 3,265,643 微秒，
恢复后的原生字节完全一致。这些是实际桥接 API 的诊断，既不是完整玩家保存，
也不是三轮独立进程性能比较。先前三个独立 release 导出诊断为
0.163625／0.166034／0.166897 秒，但使用另建队列，不能代替实际工厂的配对验收。
导出相对约 65 秒的普通保存只占约 0.27%；即使该阶段降到零也不能达到
5% 端到端门槛。批量恢复的 3.27 秒仍包含整个原生解析／校验／构建，
不能当作队列插入热点；不据此改变队列树形或浮点合并语义。

诊断在存档起始 tick 上再推进 420 和 216,000 tick，末次恰好多运行一逻辑小时。
百万入向记录为 8／35／14,175 条，末次现有 Variant 编码为 340,216 字节，
三次字典复制为 861／849／693 微秒；复杂工厂为 15／50／50 条，
末次编码 1,216 字节，复制为 5／3／2 微秒。编码字节不是字典堆占用，
引擎静态内存也不包含全部 Rust 堆；这些结果不支持按两百万矿石推算入向表
或承诺紧凑化能降低 10% 进程内存。该小时推进只用于数据量诊断，不是图形帧率基线。

R02 百万普通保存中，压缩、校验和、读回解压的合计包含耗时为
3.094307／3.057465／2.937688 秒，对应完整保存
64.942546／65.272897／62.595050 秒，每轮均低于 5%。
保持其他工作不变时，即使三阶段全部消失也达不到本轮端到端门槛；
因此压缩候选不进入实现。不放宽两次完整规则校验、磁盘重读或原子 bank 提交。

## 2026-11-24：图形基线的环境复核

原三轮矩阵保留全部输出，但多例没有绘制任何帧，另有窗口焦点混合或失焦，
不能作为同条件的三轮比较。当天 `pmset -g log` 记录 01:02:53 关闭显示、
01:02:58 合盖休眠，直到 15:47:56 才恢复显示并因开盖／输入唤醒。
这些记录证实了环境休眠；不将每次失焦或未绘制的具体原因进一步推定为引擎缺陷。

后续图形进程用临时 `caffeinate -diu` 包裹，断言只持续到该编排进程结束，
未修改系统休眠设置。10k 与复杂工厂各完成生成、独立固定加载及独立移动加载，
六例都通过报告检查，测量窗口逐帧焦点均为 true。固定加载还完成三次不同世界的
保存／加载／静置循环。这是环境烟测，单次结果不能替代三轮性能验收。

补齐基线时仅复用来源、档案、负载与焦点一致的完整运行，保留原始运行路径；
原失败或混合焦点记录仍保留。第一次补测因已添加的回归脚本与冻结基线源码不同，
被来源校验拒绝，未启动引擎；恢复基线脚本后重新编排，不放宽来源校验。
两项原因不同的失败批次均不计入优化收益。
