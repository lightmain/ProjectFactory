# 我做了什么：把 Rust 后台接入可玩的工厂场景

记录日期：2026-11-27。范围：受控等待方案之后，移动、建拆、查询和动态物流的接入批次。
读者：项目开发者，以及希望了解这次实际开发过程的读者。
本文沿用[上一篇开发复盘](2026-11-26-alpha-2-ai-development-process.md)的组织方式，
记录起点、实施、返工和验证。玩法与协议的当前规则仍以
[后台试玩规格](../features/alpha-2.0/002-backend-protocol-and-persistence.md#后台试玩输入与动态物流接入2026-11-27当前规则)为准。

**这次我把主菜单的“新后端试玩”接到了 Rust 世界线程。玩家可以在小工厂里移动，
切换自由镜头，查询方块和设施，放置、拆除及提交传送带线路，并看到持续运动的矿石。
Godot 负责输入、局部画面和物理碰撞，Rust 保存工厂状态并执行规则。**

本轮交付到后台小工厂接续；完整后台存读档的产品验收、大世界流送和后续迁移仍需继续。

## 1. 接手时已有组件，缺的是实际场景接续

上一篇复盘记录了一个问题：世界、工厂、存档和后台组件逐步实现，
用户等待的完整后台试玩却一直没有形成。此后，用户授权先简化协议，
再提出本轮明确要求：“开始接入移动、建拆、查询和动态物流显示”。

开始本轮时，[受控等待方案](2026-11-27-controlled-wait.md)已经完成。
它让普通世界操作串行执行：Godot 提交一个请求，Rust 接收后执行，
Godot 再领取一次结果。操作未结束时，玩家相关物理推进等待，
菜单、进度和结果领取继续运行，等待期间的墙钟时间不补进工厂模拟。

后台查询、静态网格分页、碰撞安装器、会话宿主和存档候选交接也已有实现。
这些组件各自通过验证，并不意味着玩家已经能从实际场景使用它们。
本轮以这些组件为基础，补上场景输入和表现之间的连接。

这里的世界线程是游戏进程内的 Rust 后台线程。Godot 向它提交小型请求，
稍后读取查询和操作结果；它并不是一个需要部署的网络服务。

## 2. 我先补了局部动态数据，让工厂运行能被看见

静态网格只能显示方块和设施，不能说明矿石正在运输。
我为既有的离散规则和连续运输规则补了局部设备与矿石采样，并新增
[动态快照模块](../../rust/factory_core/src/runtime/display.rs)。
世界线程按 Godot 请求显示的附近区块采样设备数量、端口和矿石位置，
每一轮数据都对应同一个模拟 tick。tick 是工厂模拟的推进计数，
用来判断一幅画面中的数据是否来自同一时刻。

这轮数据通过原生桥接变成 Godot 的 PackedArray，也就是连续存放的批量数组。
我没有先导出全厂再让 Godot 筛选；采样从后端的局部范围开始，
并对请求范围和每轮、每页载荷设置边界。

一轮数据可能拆成多页。我让已生成的轮身份和页面保持固定，
Godot 收齐并校验清单、身份、数组长度后才安装整轮。
矿石跨区块时，位置和成员一起切换；离开兴趣范围的成员随整轮替换退休。
页面失败时保留上一幅完整画面，避免把半轮矿石显示出来。

Godot 侧新增的[动态视图](../../scripts/backend/factory_dynamic_view.gd)
用 MultiMesh 批量更新矿石，同时替换设备信息。MultiMesh 是 Godot
用一个批次绘制许多相同网格的资源，矿石数量变化不需要逐颗建立场景节点。

## 3. 我把查询和建拆接到同一份权威世界

玩家瞄准时，场景提交射线查询；线路草稿变化时，场景请求建造预览。
这些请求带有本次查询和视图的身份。结果返回后，
场景检查当前镜头、工具和交互状态是否仍匹配，再决定是否显示。
因此，移动、换工具或取消之后返回的旧查询不会重新点亮旧预览。

绿色预览只用于提示。真正提交时，Rust 仍须用当前世界重新检查，
线路也重新规划。因为玩家看到预览与后端收到提交之间可能发生变化，
预览通过不能直接保证建造成功。

我新增了[安全建造模块](../../rust/factory_core/src/runtime/safety.rs)，
把建造分成准备和确认。场景先保存玩家、必要的自由镜头占用范围以及当前姿态，
并冻结相关运动。Rust 规划新增方块，检查重叠和需要的抬升空间，
返回这次准备的身份及目标高度。

Godot 随后检查当前位置是否保持不变、当前碰撞是否覆盖检查范围，
并用引擎物理确认抬升路径。确认回到 Rust 后，Rust 再检查准备身份、
完整姿态和世界修订，条件都成立才修改世界。
世界修订是编辑后的状态版本，用来防止把针对旧几何的确认应用到新世界。

本片允许线路新增的传送带在安全条件下抬升玩家；
普通单格建造重叠玩家时拒绝。提交成功后，Godot 等新碰撞安装完成，
再执行抬升并释放运动等待。线路草稿的取消与已接受准备操作的生命周期分开处理，
避免把隐藏预览误当成撤销已接受的操作。

## 4. 我把玩家、自由镜头和菜单接进了场景

主要连接放在[后台试玩适配器](../../scripts/backend/factory_runtime_playground.gd)。
适配器在场景中注入现有宿主、静态交接组件和新动态视图，
并把玩家输入、查询、建拆结果及 HUD 更新串起来。
“新后端试玩”默认使用这条后台路径；原同步路径保留为显式规则对照。

玩家每个物理帧移动前，适配器根据拟执行的运动计算扫掠范围，
检查该范围的碰撞是否属于当前世界实例和修订。
缺覆盖、操作未结束或新碰撞尚未安装时先等待；
覆盖齐全后，由 Godot 执行真实运动和碰撞。
这里检查的是即将移动经过的空间，而不只是玩家所在的一个点。

自由镜头也接入相同的覆盖保护。滚轮和中键增量留到物理帧执行，
缩放和绕点旋转使用独立的视野中心射线。
绕点运动分段检查路径；进入自由视角时，从玩家眼睛扫掠到初始镜头位置，
避免先把镜头放到顶棚另一侧。

我复用了工具栏、物品栏和暂停菜单。普通等待保留必要的按键释放和中键手势，
暂停、失焦等状态按既有规则取消交互。到期自动保存安排在已执行玩家帧之后，
并继续使用宿主的暂停采样链路。
场景或静态分页发生错误时，主动操作停止，生命周期领取仍继续，
错误菜单提供关闭会话并返回主菜单的路径。

## 5. 实际输入和独立审查暴露了哪些返工

接通组件之后，我用场景测试走实际 InputEvent，也就是 Godot 收到的输入事件。
随后，独立审查先读验收和测试，再检查实现。
这两个环节发现了一些仅凭模块测试不容易看出的连接问题。

| 问题 | 表现或原因 | 本轮处理 |
| --- | --- | --- |
| 右键接错建造入口 | 后端具备能力，实际右键仍不能按预期建造 | 修正入口，并验证右键放置、左键拆除 |
| 线路命令键类型不一致 | GDScript 的 StringName 键没有按字符串命令键被桥接识别 | 统一提交键，验证 R 切轴、重复 C 锁定和最终提交 |
| 世界边界外仍要求碰撞覆盖 | 玩家向外接近边界后，向内移动也可能一直等待 | 只要求扫掠与有限世界相交的部分有覆盖 |
| 取消后重新请求同一显示代号 | 旧生成任务可能在新请求之后发布，覆盖新轮 | 给每次接受的生成请求分配独立轮身份，发布前重验 |
| 规则重启遗漏状态 | 新宿主可能使用旧工具初值，或宿主、玩家、菜单暂停状态不一致 | 初始化工具和朝向，修正回调顺序，统一暂停意图 |
| 故障只冻结输入 | 会话可能停在无法离开的错误状态 | 保持领取和关闭链路，验证错误菜单能返回 |

安全建造还补了同批上层几何和迟到顶棚的检查；
原生动态桥接补了真实两页清单、预算及两套规则的坡道位置验证。
这些修复按相关范围先确认失败原因，再实现和复验。
最后一次暂停规则重启修复完成后，我重新运行了完整 Godot 检查。

仍保留两项非阻断审查建议：加强暂停重启测试在恢复前的状态断言，
以及统一原生测试初始关闭等待的期限。它们在验收记录中单独标明。

## 6. 我验证了什么，也处理了哪些环境问题

Rust 完整验证通过，涵盖 workspace 测试、格式、Clippy、
安装与编译身份、真实原生桥接，以及世界、查询、路线、网格和物流对照。
Godot 最终完整检查执行了 543 个测试，零失败、零跳过，
并通过类型检查、原生运输与显示回归、跨进程启动和主场景运行。
这些数字只描述本次记录对应的验证，不作为项目长期测试总数维护。

图形检查先在装有当前原生库的隔离项目中运行真实窗口。
两张物流截图显示矿石位置变化，模拟 tick 持续推进，暂停菜单显示正常。
安装新库之后，我又从当前 Godot 编辑器启动后台试玩，
确认后台模式已就绪、错误为空，并检查 Tab 自由镜头的实时画面。
Esc 暂停后，连续二十个物理帧的模拟 tick 保持不变。
两次图形验证结束后都停止了游戏。

这期间出现了环境返工。沙箱限制 Godot 用户目录中的恢复锁和着色器缓存写入，
首次窗口截图因此缺少地面和 UI。我只在隔离项目关闭磁盘着色器缓存，
重新运行后画面和日志正常；测试夹具也写入隔离项目。
这些处理没有修改正式游戏的存档路径或渲染设置。

原生库还需要区分磁盘文件和已加载的代码。我核对新库与 Rust 源码的构建身份，
完整保留旧安装目录，再安装已验证的新目录，没有覆盖正在映射的库文件。
新启动的游戏进程已经使用新安装，编辑器自身仍需重启更新其原生类。

独立审查确认 Rust、场景修复和文档没有剩余阻断项。
详细证据、限制及日志名称见[本轮验收记录](2026-11-27-background-playground.md)。

## 7. 这次交付到了哪里

这次形成了可以从项目入口体验的后台小工厂：
Rust 世界线程执行工厂规则和查询，Godot 用局部静态碰撞与动态数组显示结果，
玩家输入已经经过场景链路进入后台。

“新游戏”默认入口仍使用原后端。后台小工厂接续没有自动完成 alpha-2.0 整体迁移，
也没有改变 README 声明的开发阶段。
存读档菜单复用已有宿主和交接组件，完整后台存读档产品验收仍待补；
百万规模流送、多方块结构和库存编辑仍属于后续范围。
本轮的脚本输入、自动测试和截图检查也不能替代玩家亲自操作的手工体验验收。

后续工作的范围和验收应继续从
[迁移计划](../features/alpha-2.0/003-migration-plan.md)与当前规格接续，
而不是根据一个小工厂画面就判断完整迁移已经完成。
